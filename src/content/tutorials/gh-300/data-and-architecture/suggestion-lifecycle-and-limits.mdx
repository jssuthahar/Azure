## Start with a question

<Story question="Copilot finishes your line almost before you've stopped typing. How many checks did that suggestion pass, and which mistakes could still be inside it?">

Think of ordering food on an app. You tap, the restaurant gets your order, the kitchen cooks, someone packs and seals it, and a rider drops it at your door. Plenty of checks happen. You still open the box before you eat.

A Copilot suggestion has the same kind of journey. It's quick because every step is small, but there are several of them, and the model at the centre has real limits. Knowing the lifecycle helps you answer exam questions, and it helps you spot when a suggestion is likely to be wrong.

</Story>

## The technical explanation

### The lifecycle, step by step

| Step | What happens | Where |
| --- | --- | --- |
| 1. Trigger | You pause while typing (or trigger a suggestion explicitly) | Your editor |
| 2. Gather context | Code before and after the cursor, file name and language, related open tabs | IDE extension |
| 3. Exclusions | Files covered by a content exclusion are skipped | IDE extension |
| 4. Build the prompt | Context is ranked and trimmed to fit the context window | IDE extension |
| 5. Send | Encrypted over HTTPS | Network |
| 6. Proxy | Authentication and pre-filters (offensive content, prompt injection) | GitHub |
| 7. Generate | The LLM predicts the most likely tokens, sometimes several candidates | Model |
| 8. Post-process | Quality, insecure patterns, offensive content, public code match | GitHub |
| 9. Display | Grey ghost text at your cursor | Your editor |
| 10. Decide | Accept, accept part, cycle, or dismiss; engagement data is recorded | You |

### Your keys at step 10

| Action | Windows and Linux | macOS |
| --- | --- | --- |
| Accept the whole suggestion | Tab | Tab |
| Dismiss | Esc | Esc |
| Next / previous alternative | Alt+] / Alt+[ | Option+] / Option+[ |
| Accept the next word | Ctrl+→ | Cmd+→ |
| Open the completions panel | Ctrl+Enter | Ctrl+Enter |

**Next edit suggestions (NES)** extend the idea: after you change something, Copilot predicts the next edit you're likely to make, even a few lines away, and you jump to it and accept with Tab. The **VS Code & GitHub** tab shows cycling three alternatives and accepting word by word.

### Limits of LLMs and Copilot

The model in step 7 is powerful and still a guesser. Know these limits by name:

- **Knowledge cut-off.** Training data stops at a date, so newer library versions and APIs may be missing or wrong.
- **Hallucinations.** It can invent functions, options or whole packages that don't exist. Installing a made-up package name is a real supply-chain risk.
- **Insecure or outdated code.** It learned from public code, including bad patterns.
- **Bias.** Assumptions in training data can show up in names, examples and logic.
- **Non-deterministic output.** The same prompt can give different results.
- **Limited context window.** It only sees what fits in the prompt, not your whole system.
- **Rare languages and frameworks.** Less training data means weaker suggestions.
- **No real understanding or execution.** It doesn't run, compile or test what it suggests.

```javascript
// Copilot suggested this in src/discount.js. Looks fine. Is it?
const pct = CODES[code] ?? 0;
return Math.round(total - (total * pct) / 100);   // rounding rule: does the business want this?
```

The code is plausible, and only you know whether rounding belongs there. That's the whole point: review it, run `npm test`, and keep it only if it matches the requirement.

<Callout type="exam">
Lifecycle questions often give you the steps out of order. Remember the shape: **context → prompt → proxy (pre-filter) → model → post-process → you**. Limit questions describe a symptom: "suggests a method from an old version" is the **knowledge cut-off**; "a package that doesn't exist" is a **hallucination**; "different answer each time" is **non-deterministic output**; "ignores code in a file it never saw" is the **context window**.
</Callout>

<DeepDive title="Why non-determinism isn't a bug">

A language model gives a probability for each possible next token. If it always picked the single most likely one, output would be repetitive and often worse. So it samples, which means two runs can differ. Your context also changes constantly as you type and switch tabs. That's why the completions panel and Alt+] exist: you're expected to look at options and choose. It's also why you can't treat "Copilot wrote it the same way last time" as evidence of correctness. Tests are the evidence.

</DeepDive>
