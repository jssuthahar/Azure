## Start with a question

<Story question="Copilot suggests a function name that doesn't exist in your project. Was the model wrong, or did it never see the right file?">

Picture a tailor stitching a shirt for you over the phone. If you only say "make it nice", you get a standard shirt. If you send your measurements, a photo of a shirt you love and the fabric, you get something that fits.

Copilot is that tailor. It only knows what's in the **prompt**, and for an inline suggestion the IDE builds that prompt for you from whatever is near your cursor and open in your editor. When the right file isn't in that bundle, the model guesses, and guesses can look confident.

</Story>

## The technical explanation

### Context for inline suggestions

When you pause while typing, the Copilot extension gathers:

- **Code before the cursor** (the prefix) and **code after it** (the suffix), so the suggestion fits in the middle.
- The **file name, path and language**. `tests/discount.test.js` tells the model you're writing a test in JavaScript.
- **Related snippets from open tabs** (neighbouring tabs). Having `src/discount.js` open while you write its test helps a lot.
Repository custom instructions are used by chat, agents and code review, not by inline completions, so don't count on them to steer ghost text.

Then it **ranks and trims**. A model reads a limited number of tokens per request (the **context window**), and completions need to come back quickly, so only the most relevant pieces go in. Files covered by a **content exclusion** are skipped.

### Context for chat

Chat prompts carry more, because you're asking a question rather than continuing a line.

| Piece | Where it comes from |
| --- | --- |
| Your question | What you typed, plus any slash command such as `/explain` or `/tests` |
| Active file or selection | Included automatically in the editor's chat |
| Chat variables | `#file`, `#selection`, `#codebase`, `#changes`, `#terminalSelection`, `#terminalLastCommand`, or files and images you drag in |
| Participants | `@workspace` (your project), `@terminal`, `@vscode`, `@github` |
| Custom instructions | `.github/copilot-instructions.md` and matching `.github/instructions/*.instructions.md` files |
| Chat history | Earlier turns in the same conversation |

All of that has to fit the context window too. Long conversations push older turns out or crowd the useful context, which is why starting a new chat for a new topic helps.

```text
You:  Why does applyDiscount return NaN for unknown codes? #file:src/discount.js
      📎 Used 2 references: discount.js, cart.js
```

### Check what was really used

Under a chat answer, expand **Used n references** to see exactly which files and snippets went in. If the file you care about is missing, attach it and ask again. If it never appears even when attached, it may be excluded. The **VS Code & GitHub** tab walks through this with open tabs, a `#file` chip and the references list.

In the Copilot CLI, `@path` adds a file to your prompt and `/context` shows how full the context window is. You can try `/context` in the Practice Lab sandbox.

<Callout type="exam">
Questions here test **what Copilot looks at**. For inline suggestions, the answer is code around the cursor, the file's name and language, and **open tabs**. For chat, add the **selection or active file**, **# variables**, **@ participants**, **instructions** and **history**. "Copilot keeps suggesting code from an unrelated file" means **close the unrelated tab**. "Make sure chat uses a specific file" means **#file** or select it.
</Callout>

<DeepDive title="Why the suffix matters">

Older autocomplete only looked backwards. Copilot also sends the code **after** your cursor, which lets the model fill a gap instead of just continuing. If you're writing the middle of `applyDiscount` and the `return` line already exists below, the suggestion will define the variable that `return` needs. That's also why a half-finished file with a clear function signature and a comment above it gets better suggestions than an empty one: there's more signal on both sides of the cursor.

</DeepDive>
