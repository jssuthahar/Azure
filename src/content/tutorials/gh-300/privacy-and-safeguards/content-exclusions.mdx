## Start with a question

<Story question="The payment key lives in config/secrets.js, and that file is open in a tab while you code. Is Copilot reading it?">

It can. When you're typing in `src/cart.js`, Copilot builds its prompt from the code around your cursor and from snippets in your other open tabs. If `config/secrets.js` is one of those tabs, bits of it may be sent along.

Nobody did anything wrong here. That's how Copilot finds useful context. But your security team would rather that file never went anywhere, and asking 40 developers to "close that tab" isn't a control.

A **content exclusion** is the control. An admin lists the path once, and Copilot leaves that file alone for everyone in the repository.

</Story>

## The technical explanation

Content exclusions are part of **Copilot Business** and **Copilot Enterprise**. Individual plans (Free, Pro, Pro+) don't have them.

### What an excluded file means in the IDE

In supported IDEs, when a file matches an exclusion:

- Copilot gives **no inline suggestions** inside it.
- Copilot **doesn't use it as context** for suggestions in other files.
- The **Copilot status icon** says the file is excluded, so developers can tell "blocked on purpose" from "broken".

The file isn't hidden, encrypted or changed. You can still open and edit it. Exclusions also don't apply to every Copilot feature, so check GitHub's docs for the features your team relies on before you promise anything.

### Three places to set them

| Level | Who | Format | Reach |
| --- | --- | --- | --- |
| **Repository** | Repository admin | List of paths, one per line | That repository |
| **Organization** | Organization owner | YAML: repository name (or `"*"`) → paths | Named repos, or all of them |
| **Enterprise** | Enterprise owner | YAML, like the organization | Repositories across the enterprise |

Repository level, under **Settings › Copilot › Content exclusion**:

```yaml
- "/config/secrets.js"   # one file, from the repository root
- "/secrets/**"          # everything under /secrets
- "*.pem"                # any .pem file anywhere
```

Organization level, under **Organization settings › Copilot › Content exclusion**:

```yaml
contoso-shop:
  - "/src/legacy/report.js"
"*":
  - "**/.env"
```

Paths use fnmatch-style patterns. A leading `/` anchors the path at the repository root. Without it, the pattern can match in any folder, which is sometimes what you want and sometimes a surprise.

### Timing and the audit log

An exclusion change can take **up to 30 minutes** to reach IDEs that are already open. If a developer still sees suggestions right after you save, ask them to **reload the window** before you start debugging. Every change to exclusions is recorded in the organization's **audit log** as a `copilot.` event, so you can see who changed what.

### Editor settings are a different thing

Each developer can switch inline completions on or off per language in VS Code:

```json
"github.copilot.enable": {
  "*": true,
  "plaintext": false,
  "markdown": false,
  "yaml": false
}
```

That's handy when ghost text gets in the way of writing docs. But it's **personal**. Anyone can flip it back, and it does nothing for the next developer. If a file is sensitive, the answer is a content exclusion set by an admin, not an editor preference.

<Callout type="exam">
Read who's asking. "An administrator must prevent Copilot from using files in a folder" points to **content exclusion** at repository or organization level. "Apply to all repositories" means organization YAML with **`"*"`**. "A developer wants no suggestions in Markdown" is the **`github.copilot.enable`** setting. "The exclusion was just added but suggestions still appear" means **wait up to 30 minutes or reload the window**. And remember: exclusions need **Business or Enterprise**.
</Callout>

<DeepDive title="Exclusions are a second line, not the first">

An exclusion stops Copilot reading a file. It doesn't stop the secret being in Git history, in a fork, or on a laptop. The first line is keeping secrets out of the repository: environment variables, a secrets manager, and **secret scanning with push protection** so a key can't be pushed by mistake. Use exclusions for files that must live in the repo but shouldn't feed an AI tool, such as licensed third-party code or customer data samples.

</DeepDive>
