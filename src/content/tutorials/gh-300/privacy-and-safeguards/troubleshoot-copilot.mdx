## Start with a question

<Story question="Monday morning, you open contoso-shop, start typing, and no grey text appears. Where do you start?">

Not by reinstalling VS Code. That's the slow way.

Copilot can go quiet for about seven ordinary reasons, and most of them tell you which one it is if you look in the right place. The status bar icon, then the logs. Five minutes, usually.

Some of the reasons aren't bugs at all. An admin may have excluded the file you're in. You may have switched off suggestions for YAML last week and forgotten. Knowing the list means you can tell "broken" from "working as configured".

</Story>

## Explain it like I'm 10

<Eli10>

Your torch won't turn on. You don't throw it away. You check, in order:

Is it switched on? Are there batteries? Are they the right way round? Is the bulb OK?

Copilot is the same. Are you **signed in**? Do you have a **seat** (the batteries)? Is this **one file** blocked on purpose? Is the **internet** getting through? You go down the list until you find it.

</Eli10>

## The technical explanation

### Work from the editor outwards

| Symptom | Likely cause | Check or fix |
| --- | --- | --- |
| No suggestions anywhere, icon shows signed out | Not signed in | **GitHub Copilot: Sign in** from the Command Palette |
| Signed in, still nothing | No **seat**, or the seat was removed | Check your Copilot settings on github.com, or ask the org admin |
| Nothing in **one file** | File is **excluded** | Status icon says excluded. Expected behaviour, ask the admin if it's wrong |
| Nothing in one **language** | Disabled in `github.copilot.enable` | Set that language to `true` |
| A suggestion seems to vanish | **Public code filter** is Block and it matched | Expected. The org chose Block |
| Spinner, then errors | **Proxy or firewall** blocks Copilot's endpoints | Read the logs, set `http.proxy`, ask IT to allow the endpoints |
| Odd errors after an update | **Extension out of date** or mismatched with VS Code | Update the GitHub Copilot Chat extension and VS Code |
| Chat or CLI missing, completions fine | **Organization policy** turned the feature off | Ask the admin which policies are set |

### Read the logs

In VS Code, open **View › Output** and pick **GitHub Copilot** from the dropdown, or run **GitHub Copilot: Open Logs** from the Command Palette. That's where the real reason shows up:

```text
[GitHub Copilot] Fetching completions…
[GitHub Copilot] Error: request blocked by proxy (407)
```

A `407` means proxy authentication. Errors about certificates often mean a proxy that inspects TLS traffic, and the corporate root certificate needs to be trusted. Connection timeouts mean a firewall isn't letting Copilot's endpoints through. GitHub's firewall troubleshooting page lists the hosts your network team needs to allow.

### Content exclusion problems

Exclusions cause two kinds of tickets.

**"I excluded it, but Copilot still suggests there."** Changes can take **up to 30 minutes** to reach an IDE that's already open. Reload the window (**Developer: Reload Window**). If it still happens, check the pattern: `/secrets/**` anchors at the repository root, `secrets/**` can match anywhere. Also check the IDE and extension are supported and current, and remember exclusions don't apply to every Copilot feature.

**"Copilot doesn't work in this file and I need it."** Look at the status icon. If it says the file is excluded, Copilot is doing what the admin asked. Talk to whoever owns the rule (repository admin or org owner). The audit log shows who changed it, as a `copilot.` event.

<Callout type="exam">
Match the scope of the symptom to the cause. **Every file** silent: sign-in, seat, network, extension. **One file**: content exclusion. **One language**: `github.copilot.enable`. **Exclusion not working yet**: up to **30 minutes**, reload the window. **Need error details**: **Output › GitHub Copilot** logs. If a feature like chat is missing for everyone in the org, think **policy**, not a broken install.
</Callout>

<DeepDive title="The Copilot CLI has its own checks">

In the terminal, Copilot CLI problems follow the same idea. `copilot version` and `copilot update` deal with old builds. `/login` fixes authentication, or check the token in `COPILOT_GITHUB_TOKEN`, `GH_TOKEN` or `GITHUB_TOKEN` (a fine-grained token with the Copilot Requests permission; classic tokens aren't supported). If the CLI won't start at all for an org seat, the organization may have turned the CLI off by policy.

</DeepDive>
