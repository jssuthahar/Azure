## Start with a question

<Story question="Copilot just suggested 30 lines that look a lot like a popular open-source library. Can you use them?">

Maybe. It depends on the licence of the code it matches, and whether you'll follow it.

Most of what Copilot suggests is new, stitched together from patterns. But now and then a longer suggestion matches code that already exists in a public repository. If that repository is MIT-licensed, you're probably fine with attribution. If it's GPL, your legal team will want a word.

The problem is you can't tell by looking. So Copilot gives your organization a choice: **hide** those matches entirely, or **show** them with a note saying where the code came from and under which licence.

</Story>

## Explain it like I'm 10

<Eli10>

Your teacher has two rules she could pick for essays.

Rule one: if a sentence is copied from a book, cross it out. You never even see it. That's **Block**.

Rule two: you can keep it, but you have to write the book's name next to it so everyone knows where it came from. That's **Allow** with a **code reference**.

The teacher (the admin) picks the rule for the whole class.

</Eli10>

## The technical explanation

### How a match is found

Before a suggestion reaches your editor, Copilot's post-processing compares it with code in public GitHub repositories. A **match** means a stretch of about **150 characters** or more that's the same. Short, common code like `for (let i = 0; i < n; i++)` doesn't trigger it.

### Block or Allow

| | **Block** | **Allow** |
| --- | --- | --- |
| Matching suggestion shown? | No | Yes |
| Code reference? | — | Yes: repository URL and licence |
| Where | Suggestion simply doesn't appear | Inline: **Output › GitHub Copilot Log (Code References)**. Chat: listed in the answer |
| Good for | Teams that want no licence decisions at the keyboard | Teams that want visibility and know how to attribute |

A code reference for an inline suggestion looks something like this in the Output panel:

```text
[GitHub Copilot] Code reference
  Similar code found with 1 license type: MIT
  github.com/example/cart-utils/blob/main/total.js
```

### Who sets it

| Plan | Who controls the setting | Where |
| --- | --- | --- |
| Copilot Free, Pro, Pro+ | You | Your personal Copilot settings on github.com |
| Copilot Business | Organization owner | **Organization settings › Copilot › Policies** |
| Copilot Enterprise | Enterprise owner (enforce) or each organization | Enterprise policies, or the org's Copilot policies when the enterprise leaves "No policy" |

If a developer gets a seat from an organization, the organization's choice applies. They can't override it in personal settings.

<Callout type="exam">
"Ensure Copilot doesn't suggest code that matches public repositories" is the policy set to **Block**. "Developers need to see the licence of matching code" is **Allow**, which shows **code references**. "The same setting for every organization" means the **enterprise enforces** the policy. Remember the number: about **150 characters**. And a code reference is information, not permission: the developer still follows the licence.
</Callout>

<DeepDive title="Why Block isn't a legal guarantee">

Block hides suggestions the filter detects as matches. It doesn't promise that nothing Copilot writes resembles existing code, and it doesn't check code you paste in yourself. It lowers the risk; it doesn't remove responsibility. That's why many teams pair it with licence scanning on dependencies and a clear rule on attribution. For the contract side, Business and Enterprise terms include IP indemnity, with conditions that the terms spell out.

</DeepDive>
