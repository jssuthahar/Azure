## Start with a question

<Story question="If you hire a contractor to redo your kitchen, do you want them to just give advice, or plan the job, fetch tools, ask before cutting into a wall, and keep going until it's done?">

For a full kitchen, you want the second one. But you also want them to check with you before anything loud, and you don't want them rifling through every room of the house to figure out where the fuse box is.

That's **agent mode**. Copilot plans the job, edits files and **asks before running commands**. **MCP servers** are the extra tools in its van: a GitHub tool for issues, a browser, a docs search. And a **sub-agent** is the apprentice sent to find the fuse box, who comes back with one sentence ("it's under the stairs") instead of a tour of the house.

</Story>

## Explain it like I'm 10

<Eli10>

Agent mode is Copilot doing a whole job, not just answering.

It makes a plan, changes the files and asks "can I run the tests?". You say yes or no.

If a test fails, it tries again.

MCP is like plugging new tools into it, such as one that reads your GitHub issues.

A sub-agent is a little helper it sends off to look something up. The helper comes back with a short note, so the main agent's head doesn't get too full.

</Eli10>

## The technical explanation

### Agent mode vs Copilot Edits

Both live in the Chat view's mode picker in VS Code.

| | Edit mode (Copilot Edits) | Agent mode |
| --- | --- | --- |
| Which files | The ones you add to the working set | Finds them itself |
| Runs commands | No | Yes, after you approve |
| Reads errors and tests | No | Yes, and iterates |
| Uses tools / MCP | No | Yes |
| You review | Each diff: Keep or Undo | Each diff, each command, each tool call |

Ask agent mode for an outcome, not steps: "Add a FREE code that gives 100% off, make sure totals never go negative, and add tests." It searches for `discount`, edits `src/discount.js`, creates `tests/discount.test.js`, then asks:

```text
⌨️ Run in terminal: npm test
   [Allow]  [Allow for this session]  [Skip]
```

If a test fails it reads the assertion, fixes the code and runs the tests again. When it's done you get a summary and the diffs to **Keep** or **Undo**. "Allow for this session" saves clicks but means it won't ask again for that command, so use it in repos you know.

### MCP servers add tools

The **Model Context Protocol** is an open standard for connecting AI apps to tools and data. An MCP server exposes **tools** (functions the agent can call) and sometimes resources. In VS Code you list servers in **`.vscode/mcp.json`**, which you can commit so the whole team gets the same setup:

```json
{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/"
    }
  }
}
```

That's the **GitHub MCP server**: tools for issues, pull requests, Actions and more. Ask "Which open issues are labelled bug?" and the agent calls `list_issues`, after asking you. Other servers can run locally (`"type": "stdio"` with a command) for a browser, a database or your own API. In **Copilot CLI**, `/mcp` lists and adds servers and they're saved in `~/.copilot/mcp-config.json`; the GitHub MCP server is built in.

Two controls matter. You can switch individual tools on or off in the **tools picker**, and an organization with Copilot Business or Enterprise has an **MCP servers in Copilot** policy that allows or blocks MCP for its members. If the policy blocks it, no `mcp.json` file will bring it back.

### Sessions and sub-agents: managing context

Every file the agent reads, every command output and every turn of chat goes into its **context window**. Long tasks fill it, and a crowded window means slower, vaguer answers.

- **Agent sessions** keep separate pieces of work apart. Start a new session for a new task instead of piling everything into one, and you can come back to an earlier session later. In the CLI that's `/session`, `/resume` and `--continue`.
- A **sub-agent** runs a side task in **its own context**: "find every place we log user emails" or "research how the report module is used". It reads what it needs and returns a **summary**, and only that summary enters the main conversation.
- **Delegating** a whole task to Copilot coding agent (`/delegate` in the CLI, or assigning an issue on github.com) moves the work off your machine entirely; it comes back as a draft pull request.

<Callout type="exam">
Read the verbs. "Run the tests and fix failures automatically" is **Agent mode**; "change these files, no commands" is **Copilot Edits**. "Connect Copilot to an external system or tool" is an **MCP server**, configured in **`.vscode/mcp.json`** (key `"servers"`) or with **/mcp** in the CLI. "MCP tools don't appear for anyone in the company" suggests the organization's **MCP policy**. "Keep the main conversation's context small while researching something else" is a **sub-agent**; "keep two tasks separate" is **agent sessions**.
</Callout>

<DeepDive title="Custom agents, tools lists and trust">

A **custom agent** (`.github/agents/<name>.agent.md` in a repo, or `~/.copilot/agents/` for your own CLI agents) is a named persona with its own instructions and a `tools` list. A "test-writer" agent that can only read and edit files, with no shell access, is a neat way to limit what an agent can do. MCP servers run with whatever access you give them, so treat third-party servers like any dependency: check who publishes them, prefer OAuth over tokens pasted into config, and keep secrets out of a committed `mcp.json` (VS Code supports input variables for that). Tool approvals stay on by default for a reason.

</DeepDive>

## When to use it and when not to

<UseWhen
  use={[
    'Agent mode for tasks that need searching, multi-file edits, running tests and a few rounds of fixing.',
    'Copilot Edits when you know the files and want no commands run.',
    'MCP servers when the agent needs data or actions outside your repo, such as issues or docs.',
    'Sub-agents or new sessions to keep research and side tasks out of the main context.',
  ]}
  avoid={[
    'Approving every command for the session in an unfamiliar repository.',
    'Adding MCP servers from unknown publishers, or committing tokens in mcp.json.',
    'Merging agent changes without reading the diffs and running the tests yourself.',
