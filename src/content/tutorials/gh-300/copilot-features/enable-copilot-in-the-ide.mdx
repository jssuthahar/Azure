## Start with a question

<Story question="You installed Copilot, signed in, opened src/cart.js and started typing. Nothing happens. What did you miss?">

Usually one of three things. The GitHub account you signed in with doesn't have Copilot access. Copilot is turned off for that language. Or something between you and GitHub, like a company proxy, is blocking it.

Setting up Copilot is quick: **install the extension, sign in, check the status bar**. Knowing what each step does is what lets you fix it when it doesn't work, and that's what the exam asks about.

</Story>

## The technical explanation

### Step 1: install the extension

In VS Code, open **Extensions** (Ctrl+Shift+X), search for **GitHub Copilot** and install it. In current VS Code one extension, **GitHub Copilot Chat**, brings chat, inline suggestions and agent mode together.

Other editors have their own Copilot extension or plugin:

| IDE | How you get Copilot |
| --- | --- |
| **Visual Studio Code** | GitHub Copilot Chat extension from the Extensions view |
| **Visual Studio** | Built in to recent versions; sign in with GitHub |
| **JetBrains IDEs** (IntelliJ IDEA, PyCharm, Rider and others) | GitHub Copilot plugin from the JetBrains Marketplace |
| **Xcode** | GitHub Copilot for Xcode extension |
| **Eclipse** | GitHub Copilot plugin from the Eclipse Marketplace |
| **Vim / Neovim** | The `copilot.vim` plugin |

### Step 2: sign in with an account that has access

VS Code asks you to **sign in to GitHub**. The account needs one of these: **Copilot Free**, a paid individual plan (**Pro** or **Pro+**), or a **seat** assigned by an organization on **Copilot Business** or **Enterprise**. Signing in with an account that has none of these won't light Copilot up. If your seat comes from work, sign in with the account that's a member of that organization.

### Step 3: check the status bar

The **Copilot icon** in the status bar tells you it's ready. Click it to see your plan, snooze suggestions for a while, or turn completions off for the current language. If something's wrong, the icon shows it.

### Turn suggestions on or off per language

The `github.copilot.enable` setting takes an object of languages:

```json
{
  "github.copilot.enable": {
    "*": true,
    "plaintext": false,
    "markdown": true
  }
}
```

`"*"` covers every language; the other keys override it. **Next edit suggestions** (NES), which predict your next edit, have their own setting.

### The keys you'll use from day one

| Action | VS Code (Windows/Linux) |
| --- | --- |
| Accept a suggestion | **Tab** |
| Dismiss it | **Esc** |
| Next / previous suggestion | **Alt+]** / **Alt+[** (Option on macOS) |
| Accept the next word | **Ctrl+→** |
| Open the completions panel | **Ctrl+Enter** |
| Inline chat in the editor | **Ctrl+I** |
| Open the Chat view | **Ctrl+Alt+I** |

### When nothing appears

Work through it in order: does the account have a **seat** or plan, is the status bar icon showing an error, is the **language disabled**, is the file covered by a **content exclusion**, is a **proxy or firewall** blocking Copilot, is the extension **out of date**. The logs are in **Output › GitHub Copilot**, or run **GitHub Copilot: Open Logs** from the Command Palette.

<Callout type="exam">
"Installed and signed in but no suggestions" questions usually want you to check the **licence (seat)** before anything else. "Disable Copilot for one file type" is the **github.copilot.enable** setting, not uninstalling the extension. And remember that the **plan belongs to the GitHub account**, not to the IDE, so the same seat works in VS Code, Visual Studio and JetBrains.
</Callout>

<DeepDive title="Why an organization policy can hide a feature you expect">

Even with a seat, an organization can turn features off by policy, for example Copilot Chat in the IDE, the CLI or certain models. If a teammate has a feature you don't, compare which organization granted each of your seats and check its Copilot policies. An enterprise-enforced policy wins over the organization's own choice.

</DeepDive>
