## Start with a question

<Story question="If you're already in the kitchen with your hands dirty, do you want to walk to another room to ask for help?">

No. You want the helper right there at the counter. Plenty of developers spend half their day in a terminal: running tests, using git, logged in to a server. Switching to an editor's chat window to ask "what does this script do?" breaks the flow.

**GitHub Copilot CLI** puts the helper at the counter. Type `copilot` in your repo and you can ask about the code, have it write a file or run a command, and it asks before it touches anything.

</Story>

## The technical explanation

### What it is and why it helps

Copilot CLI is the `copilot` command. It's an **agent**: it can read files in the folder, search them, edit them, run shell commands and call MCP tools, and it checks with you before using a tool it hasn't been allowed yet. That makes it useful when:

- you work over SSH or mostly in the terminal,
- you want to ask about a repo you just cloned,
- you want to script a prompt (`copilot -p "…"`) in a shell script or CI job,
- you want to hand a task to Copilot coding agent with `/delegate`.

It needs a Copilot plan (Free, Pro, Pro+, or a Business or Enterprise seat), and an organization can turn the CLI off by policy. It replaces the older `gh copilot` extension.

### Install it

| Method | Command |
| --- | --- |
| npm (any OS, Node.js 22+) | `npm install -g @github/copilot` |
| Homebrew (macOS, Linux) | `brew install --cask copilot-cli` |
| WinGet (Windows) | `winget install GitHub.Copilot` |
| Install script (macOS, Linux) | `curl -fsSL https://gh.io/copilot-install \| bash` |

Check it with `copilot version` and keep it current with `copilot update`.

### First run: trust, then sign in

```text
$ cd contoso-shop
$ copilot
Confirm folder trust: ~/contoso-shop
  1. Yes
  2. Yes, and remember this folder for future sessions
  3. No (Esc)
```

It asks because it can read every file here and, with your approval, change them and run commands. Only trust folders whose contents you trust.

Then sign in:

- **`/login`** inside the session uses the **device flow**: copy a one-time code and approve it on github.com.
- For automation, set a **fine-grained personal access token** with the **Copilot Requests** permission in `COPILOT_GITHUB_TOKEN`, `GH_TOKEN` or `GITHUB_TOKEN`. Classic tokens aren't supported.

### Inside a session

Type a request in plain English. Three bits of syntax are worth knowing:

```text
copilot ❯ explain @src/cart.js            # @path adds a file to the context
copilot ❯ !git status                     # ! runs a shell command directly
copilot ❯ /model                          # / is a slash command
```

| Slash command | What it does |
| --- | --- |
| `/login`, `/logout` | Sign in or out |
| `/model` | Pick a model (your plan and organization decide the list) |
| `/mcp` | List, add or show MCP servers |
| `/agent` | Pick a custom agent |
| `/delegate` | Hand the task to Copilot coding agent on GitHub, which opens a draft PR |
| `/usage` | See what the session used, including premium requests |
| `/context`, `/compact` | See what fills the context window, and summarise history to free space |
| `/session`, `/resume` | Session details, and switch back to an earlier session |
| `/init`, `/plan`, `/review` | Create instructions for the repo, plan before coding, review changes |
| `/clear`, `/help`, `/exit` | Start over, list commands, leave (the session is saved) |

Settings, MCP servers (`mcp-config.json`) and personal custom agents (`agents/`) live in `~/.copilot/`.

<Callout type="exam">
Expect "which command installs it" and "how do you sign in" questions. Install is **npm install -g @github/copilot** (Node.js **22+**), or Homebrew, WinGet or the script. Sign-in is **/login** (device flow) or a **fine-grained PAT** with **Copilot Requests** in **COPILOT_GITHUB_TOKEN**, **GH_TOKEN** or **GITHUB_TOKEN**; classic PATs don't work. **@path** adds a file, **!** runs a shell command, **/model** switches models and **/delegate** hands work to the coding agent. If the CLI is blocked for everyone in a company, think **organization policy**.
</Callout>

<DeepDive title="What trust and approvals actually protect">

Trusting a folder means Copilot CLI may read files there. It still asks before each new kind of action, such as writing a file or running `shell(npm)`. You can answer yes once, or yes for the rest of the session. When you launch it you can pre-approve or block tools with `--allow-tool` and `--deny-tool`, and a deny always wins, which matters most in non-interactive runs (covered in the next lesson). A cloned repo can contain instructions files and scripts written by someone else, so be careful trusting folders you haven't read, and never pre-approve all tools there.

</DeepDive>
