## Start with a question

<Story question="If you call a plumber and just say 'it's broken', how long before they fix the right pipe?">

A long time. Now imagine you say "the kitchen tap drips, here's a photo, it started after last week's repair". The plumber knows what kind of job it is, where to look and what changed.

Copilot Chat is the same. A **slash command** tells it the kind of job (`/fix`, `/tests`). A **participant** like `@workspace` sends the question to someone who knows the whole house. **#** context like `#file` is the photo. And like any plumber, it only knows what you showed it.

</Story>

## Explain it like I'm 10

<Eli10>

Copilot Chat is a clever friend you text about your code.

A word starting with / says what you want: explain, fix, write tests.

A word starting with @ picks who to ask: the whole project, the terminal, GitHub.

A word starting with # hands over a page to look at.

Your friend can only remember so much at once, so start a new chat when you change the subject.

## The technical explanation

### Slash commands

Type **/** in the chat box to see them. Select code first, so Copilot knows what "this" means.

| Command | What it does |
| --- | --- |
| `/explain` | Explains the selected code or the active file |
| `/fix` | Proposes a fix for problems in the selection |
| `/tests` | Writes unit tests for the selection |
| `/doc` | Adds documentation comments |
| `/new` | Scaffolds a new project or file |
| `/clear` | Starts a fresh conversation |
| `/help` | Lists what's available |

Select `applyDiscount` in `src/discount.js`, type `/tests`, and Copilot writes tests for SAVE10, an unknown code, no code and an empty cart. You then **Insert into new file** or **Copy**.

### Participants (@) and context (#)

**Participants** are experts with their own context:

- `@workspace` answers questions about your whole project ("where is the discount applied?").
- `@vscode` answers questions about the editor and its settings.
- `@terminal` helps with shell commands and the integrated terminal.
- `@github` brings in GitHub data such as issues and pull requests.

**Context variables** start with `#` and add exactly what you choose: `#file:src/cart.js`, `#selection`, `#codebase` (search the workspace), `#terminalSelection`, `#terminalLastCommand` and `#changes` (your uncommitted changes). You can also drag files or a screenshot into the chat.

```text
@workspace why could cartTotal return NaN? #file:src/discount.js
```

Under each answer, **Used n references** lists what Copilot actually read. If the file you care about isn't there, add it.

### Model picker and feedback

The **model picker** lets you choose a model or **Auto**, which picks one for you. Which models you see depends on your plan and on your organization's **Models** policy. Premium models use your monthly premium-request allowance, and extra use can be paid for or blocked by a budget.

Use **👍 / 👎** on an answer to send feedback. It helps GitHub improve the service and it's a habit worth having: a thumbs down on a confident but wrong answer is useful data.

### Prompt files: reuse a good prompt

If you keep typing the same careful prompt, save it as a **prompt file** in `.github/prompts/`:

```markdown
---
description: Write edge-case tests for one module
mode: agent
---
Write unit tests for ${input:file} with the Node test runner.
Cover an unknown code, no code, an empty cart and totals that would go negative.
```

Save it as `.github/prompts/edge-tests.prompt.md` and run it with `/edge-tests` in chat. Everyone on the team gets the same instructions, and you improve the prompt through a pull request. Front matter can also set `tools` and `model`. Prompt files run only when you call them; repository instructions (`.github/copilot-instructions.md`) are added to every request automatically.

### The limits you need to know

- **Context window.** Each request has a size limit. Your message, the context you added, custom instructions and the **chat history** all count. Long files get trimmed.
- **History helps and hurts.** Follow-ups like "now add tests" work because earlier turns are included. Old, unrelated turns confuse the answer. Use `/clear` or a new chat when the topic changes.
- **Only what it can see.** Chat doesn't magically know your whole repo. It uses the active file, your selection and what you add.
- **Answers can be wrong.** Made-up APIs, outdated library versions and insecure code all happen. Review and test.
- **Not deterministic.** The same question can give a different answer next time.

<Callout type="exam">
Map the need to the syntax. "Write tests for the selection" is **/tests**; "fix this error" is **/fix**; "start over" is **/clear**. "Question about the whole project" is **@workspace** or **#codebase**; "about the editor" is **@vscode**; "about the last command's output" is **#terminalLastCommand**. "Reuse the same prompt for consistent answers" is a **prompt file** (`.prompt.md`, run with `/name`). "Answers drift off topic in a long chat" points to **chat history** filling the **context window**.
</Callout>

<DeepDive title="Participants, tools and agent mode">

In Ask mode, participants decide whose context is used. In **Agent** mode the model chooses **tools** itself (search the codebase, read a file, run a terminal command, call an MCP tool), so you'll mostly use `#` references to point it in the right direction. A prompt file's `tools` list limits which tools it may use when it runs as an agent, which is a simple way to make a reusable prompt that can read and edit but never run shell commands. Organization policies still apply: if an admin turns off a feature or a model, no prompt file can turn it back on.

</DeepDive>
