## Start with a question

<Story question="Do you want to bake a cake, or do you want to build an oven, wire the kitchen and then bake a cake?">

Most developers just want to bake the cake: write code and ship features. Yet with plain servers they also have to install operating systems, patch them every month, configure web servers and plan how to scale.

**Platform as a Service hands you a ready kitchen.** You bring the recipe (your code) and the ingredients (your data).

</Story>

## Explain it like I'm 10

<Eli10>

Think about a **school science lab**. When you arrive, the benches, gas taps, microscopes and safety equipment are already set up and checked by the lab technician. You do not build anything. You just **do your experiment**.

PaaS is a ready-made science lab for computer programs. Microsoft is the lab technician who keeps everything working. **You only bring your experiment** (your app).

</Eli10>

## The technical explanation

With **Platform as a Service**, the provider manages everything IaaS covers (datacenter, hardware, network, virtualisation) **plus** the operating system, runtime and middleware. It usually adds operational features such as **automatic patching, scaling, high availability and backups**. You deploy your application and manage your data, identities and access configuration.

### PaaS on Azure

| Azure service | What it gives developers |
| --- | --- |
| Azure App Service | Host web apps, REST APIs and mobile back ends in .NET, Java, Node.js, Python or PHP, with autoscale and deployment slots |
| Azure SQL Database | Fully managed SQL Server database engine with automated backups, patching and high availability |
| Azure Cosmos DB | Globally distributed NoSQL database with low-latency reads and writes |
| Azure Functions | Run small pieces of code in response to events (also serverless) |
| Azure Container Apps | Run containers without managing Kubernetes clusters |

<Callout type="exam">
Some services fit more than one label. Azure Functions is both **PaaS** and **serverless**. On the exam, read what the question emphasises: "no infrastructure management, pay per execution" points to serverless; "developers focus on code, provider manages the platform" points to PaaS.
</Callout>

<DeepDive title="Designing for PaaS: what changes in your architecture">

- **Stateless instances**: the platform adds and removes instances, so keep session state in Azure Managed Redis or a database, and files in Blob Storage, not on local disk.
- **Configuration and secrets**: use app settings plus Azure Key Vault references, and authenticate with **managed identities** instead of connection-string passwords.
- **Networking**: PaaS endpoints are public by default. Lock them down with access restrictions, VNet integration for outbound traffic and **private endpoints** for inbound.
- **Release safety**: App Service deployment slots let you warm up and swap releases with no downtime and instant rollback.
- **Limits**: every PaaS service has quotas (connections, request size, timeouts). Read them early. They shape the design.

</DeepDive>

## When to use it and when not to
