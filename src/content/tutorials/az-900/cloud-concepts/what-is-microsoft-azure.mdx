## Start with a question

<Story question="If you wanted to open a pizza shop, would you build your own power station, water plant and road first?">

Of course not. You rent a shop, plug into the city's electricity, connect to the water supply, and spend your energy on making great pizza.

For a long time, companies that wanted to run software had to do the equivalent of building their own power station. They bought servers, rented a server room, ran cables and hired people to keep it alive. **Microsoft Azure is the "city utilities" option for software**: the infrastructure is already built, and you plug into it.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine a gigantic toy shop that never runs out of stock. It has building blocks (computers), storage boxes (places to keep your files), walkie-talkies (networks) and even robot helpers (AI). You do not buy the toys. You **borrow exactly what you need** for your project, give it back when you are done, and pay only for the time you used it.

Microsoft owns that toy shop. It is called **Azure**, and it has branches all over the world.

</Eli10>

## The technical explanation

**Microsoft Azure is Microsoft's public cloud computing platform.** Microsoft first announced it in 2008 as "Windows Azure", made it commercially available in 2010, and renamed it Microsoft Azure in 2014 to reflect that it runs far more than Windows.

Today Azure offers **more than 200 services**. You do not need to know them all for AZ-900. You need to recognise the main families:

| Family | Example services | What they do |
| --- | --- | --- |
| Compute | Virtual Machines, App Service, Azure Functions, AKS | Run your code and applications |
| Storage | Blob Storage, Azure Files, Managed Disks | Keep files, images, backups and disks |
| Networking | Virtual Network, VPN Gateway, ExpressRoute, Azure DNS | Connect resources securely to each other and to you |
| Databases | Azure SQL Database, Azure Cosmos DB | Managed relational and NoSQL databases |
| Identity and security | Microsoft Entra ID, Microsoft Defender for Cloud | Sign-in, access control, threat protection |
| Management and governance | Azure Policy, Azure Monitor, Cost Management | Control, monitor and pay for what you run |
| AI and analytics | Azure AI services, Azure Machine Learning, Microsoft Fabric | Add intelligence and analyse data |

### Where Azure runs

Azure's infrastructure is spread across **regions**: geographic areas such as "UK South" or "Southeast Asia" that contain one or more datacenters. Many regions are split into **availability zones**, separate datacenter groups with independent power, cooling and networking. You will meet these properly in Module 2. For now, remember that you choose *where* your resources run.

<Callout type="note">
Azure is not the same thing as Microsoft 365. Microsoft 365 (Outlook, Teams, Word) is **software as a service** that Microsoft runs on its cloud. Azure is the **platform** you build and run your own solutions on. Both use Microsoft Entra ID for sign-in, which is why they feel connected.
</Callout>

<DeepDive title="Control plane vs data plane: a distinction that pays off in production">

Every Azure service has two planes:

- **Control plane**: management operations such as create a storage account, resize a VM or assign a role. These all go through Azure Resource Manager at `management.azure.com`, and RBAC and Azure Policy are enforced here.
- **Data plane**: using the resource, such as reading a blob, querying a database or calling your web app. Requests go straight to the service endpoint.

Why it matters: an RBAC role like *Contributor* lets you manage a storage account but does not, by itself, let you read blob data with Entra ID auth (you need a data role such as *Storage Blob Data Reader*). Outages can also affect one plane and not the other. Knowing which plane a failure is in is a strong signal of seniority in an interview.

</DeepDive>
