## Start with a question

<Story question="Why does everyone in a city share one bus network instead of each family running its own bus?">

A bus network is expensive to build and run, but when thousands of people share it, each ride costs very little. You do not own the bus, but you can get on whenever you need to.

**The public cloud works the same way.** Microsoft builds enormous datacenters. Millions of customers share them, and each pays only for the "rides" they take.

</Story>

## Explain it like I'm 10

<Eli10>

Think of a **public swimming pool**. Anyone can go. You do not have to build a pool, fill it, clean it or hire lifeguards, because the pool company does all that. You pay for entry and swim.

Lots of people use the same pool, but you each have your own locker with your own lock. In the public cloud, everyone shares the same giant computers, but **your stuff is locked in your own locker** and nobody else can open it.

</Eli10>

## The technical explanation

A **public cloud** is a deployment model in which a cloud provider owns, operates and maintains the infrastructure and makes services available to the general public over the internet. Microsoft Azure is a public cloud.

The defining characteristic is **multi-tenancy**: the same physical servers, storage systems and network devices serve many customers (tenants). Isolation is enforced in software and hardware. Hypervisors separate virtual machines, virtual networks separate traffic, encryption protects data, and identity controls decide who can access what.

| Advantage | Why it matters |
| --- | --- |
| No capital expenditure | Nothing to buy; start immediately |
| Massive scale | Capacity is available when you need it |
| Pay-as-you-go | Costs follow usage |
| No hardware maintenance | The provider handles hardware, power, cooling and physical security |
| Global reach | Deploy close to users in many regions |

| Trade-off | What it means |
| --- | --- |
| Less physical control | You cannot choose the exact server or walk into the datacenter |
| Specific compliance needs | Some requirements may be harder to meet (check region and certification options) |
| Dependency | You rely on the provider and your connectivity |

<DeepDive title="Isolation options inside the public cloud">

If a workload needs more isolation without leaving Azure:

- **Azure Dedicated Host**: a physical server dedicated to your organisation, with your VMs only.
- **Isolated VM sizes**: sizes that take a whole physical host.
- **Confidential computing**: VMs and containers that use hardware-based trusted execution environments (for example AMD SEV-SNP or Intel TDX), so data stays encrypted even while in use, protected from the host operator.
- **Private endpoints**: reach PaaS services over a private IP in your virtual network instead of a public endpoint.

These options let regulated industries use the public cloud without moving to a private cloud.

</DeepDive>
