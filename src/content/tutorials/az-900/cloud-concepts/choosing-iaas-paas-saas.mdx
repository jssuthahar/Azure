interview:
  - level: beginner
    q: Explain IaaS, PaaS and SaaS in one sentence each.
    a: >-
      IaaS means renting virtual servers that you manage yourself. PaaS means renting a ready platform where you just deploy your code. SaaS means using finished software over the internet that the provider runs completely.
    followUps:
      - q: Can you give me an Azure or Microsoft example for each?
        a: >-
          IaaS is Azure Virtual Machines. PaaS is Azure App Service or Azure SQL Database. SaaS is Microsoft 365.
  - level: intermediate
    q: Can one solution use all three service types?
    a: >-
      Yes, and most do. A company might use Microsoft 365 for email (SaaS), host its customer API on App Service with Azure SQL Database (PaaS), and run a legacy reporting server on a VM (IaaS). You choose per component, not per company.
    followUps: []
  - level: experienced
    q: How do you decide the default compute choice for a new service in an enterprise?
    a: >-
      I use a "most managed first" rule. Can a SaaS product do it? If not, can it run as serverless or PaaS (Functions, App Service, Container Apps)? If it needs more control or portability, containers on AKS. Only fall back to VMs when there is a concrete reason, such as OS dependencies, licensing or specialised hardware. Each step down gives more control but adds operational cost, so the burden of proof is on going lower.
    followUps: []
  - level: scenario
    q: A company has three needs. Migrate a legacy app quickly, build a new customer portal, and give staff email. Which service type for each?
    a: >-
      Legacy app, IaaS (lift and shift to VMs). Customer portal, PaaS (App Service plus a managed database). Staff email, SaaS (Microsoft 365).
    followUps: []

## Start with a question

<Story question="You are hungry. Do you cook from scratch, use a meal kit, or order delivery?">

All three get you fed. They differ in **how much you control** (exact ingredients, seasoning) and **how much work you do** (shopping, cooking, washing up).

Cloud service types are the same choice for software. There is no "best" option, only the right one for each situation.

</Story>

## Explain it like I'm 10

<Eli10>

**Pizza time!** Here are four ways to have pizza:

- 🏠 **Make it at home from nothing** (on-premises): buy flour, own an oven, cook, clean. You do it all.
- 🛒 **Take-and-bake pizza** (IaaS): the shop gives you the base and oven time. You choose toppings and bake it.
- 🍕 **Pizza delivered** (PaaS): the pizzeria makes and bakes it to your order. You lay the table and serve it.
- 🍽️ **Dining at a pizza restaurant** (SaaS): you just sit down and eat. Everything else is done for you.

</Eli10>

## The technical explanation

The three service types sit on a scale of **control versus convenience**:

<ResponsibilityGrid />

| | IaaS | PaaS | SaaS |
| --- | --- | --- | --- |
| You get | VMs, storage, networks | A managed platform for your code and data | A finished application |
| You manage | OS, runtime, apps, data, access | Apps, data, access | Data, users, devices, settings |
| Control | Highest | Medium | Lowest |
| Management effort | Highest | Medium | Lowest |
| Azure / Microsoft examples | Virtual Machines, VM Scale Sets | App Service, Azure SQL Database, Functions | Microsoft 365, Dynamics 365 |
| Typical users | IT administrators, infrastructure teams | Developers | End users and business teams |

## When to use each, and when not to

<UseWhen
  use={[
    '**IaaS** when you need OS control, specific software, or a fast lift-and-shift.',
    '**PaaS** for new custom applications, APIs and managed databases.',
    '**SaaS** for standard business capabilities you do not need to build.',
  ]}
  avoid={[
    '**IaaS** for simple web apps. You inherit patching and scaling you do not need.',
    '**PaaS** for software that needs OS-level installs or unsupported runtimes.',
    '**SaaS** when the process is your unique competitive advantage and needs deep customisation.',
  ]}
/>
