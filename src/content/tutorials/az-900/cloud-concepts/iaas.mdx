  - level: beginner
    q: What is IaaS? Give an Azure example.
    a: >-
      IaaS means renting basic computing infrastructure, such as virtual machines, disks and networks, from a cloud provider. The provider manages the physical hardware; I manage the operating system, software and data. Azure Virtual Machines is the main example.
    followUps:
      - q: What exactly do you manage on an Azure VM?
        a: >-
          The OS and its patches, installed software and runtimes, the application, data, network configuration such as NSG rules, identities and access, and backup choices. Microsoft manages the physical server, storage hardware, network and datacenter.
  - level: intermediate
    q: Why would you choose IaaS over PaaS?
    a: >-
      When I need full control of the OS (custom drivers, specific versions, agents), when migrating an existing app quickly without changes (lift and shift), when the software isn't supported on a PaaS offering, or for workloads like custom databases or legacy line-of-business apps. The trade-off is that I take on patching, scaling and high-availability design.

Automate patching with Azure Update Manager, protect with Azure Backup, and standardise with policy. Then plan a modernisation path, moving web tiers to App Service or containers and databases to Azure SQL, so the platform team stops managing OSes it doesn't need to.

## Start with a question

<Story question="You want to run an old program that only works on one specific version of Windows. Where do you put it in the cloud?">

Most modern cloud platforms say "give us your code and we run it". But this program needs a particular operating system, an installer that clicks through twenty screens, and a vendor's monitoring agent.

You need a computer you control completely, without buying one. That is **Infrastructure as a Service**.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine renting an **empty flat**. The landlord gives you the building, walls, electricity and water pipes, and fixes the roof if it leaks. Everything inside is up to you: furniture, decoration, cleaning, locks on your bedroom door.

IaaS is renting an empty computer. Microsoft gives you the machine, the power and the network. **You install everything on it and keep it tidy.**

</Eli10>

## The technical explanation

**Infrastructure as a Service** is the most flexible cloud service type. The provider supplies and manages the **physical datacenter, physical network, physical hosts and the virtualisation layer**. You get virtual machines, disks and virtual networks, and you're responsible for **everything you put on them**: the operating system, patches, middleware, runtimes, applications, data, and their configuration and security.

### IaaS on Azure

| Azure service | What you get |
| --- | --- |
| Azure Virtual Machines | Windows or Linux VMs in many sizes (general purpose, memory-optimised, GPU and more) |
| Virtual Machine Scale Sets | Groups of identical VMs that scale automatically |
| Managed Disks | Block storage disks for VMs |
| Azure Virtual Network | Your private network in Azure, with subnets and security rules |

### Common IaaS use cases

- **Lift-and-shift migration**: move existing servers to Azure quickly, then modernise later.
- **Test and development**: build and tear down environments in minutes.
- **Custom or legacy software** that needs a specific OS, drivers or agents.
- **High-performance computing (HPC)**: large numbers of powerful VMs for simulations and rendering.
- **Website hosting** where you need full control of the web server.

<Callout type="tip">
A stopped VM in Azure can still cost money. If you only "shut down" inside Windows, the VM stays **allocated** and compute charges continue. Stop it from the portal, CLI or PowerShell so it is **deallocated**. Disks are still billed either way.
</Callout>

<DeepDive title="IaaS done well: what senior engineers add">

- **Availability**: a single VM's SLA depends on its disk type (highest with Premium SSD or Ultra Disk). Use availability zones or availability sets plus a load balancer for production.
- **Automation**: build images with Azure VM Image Builder, configure with cloud-init or Desired State Configuration, deploy with Bicep or Terraform. Never hand-build production VMs.
- **Patching**: Azure Update Manager can schedule and report patches across Azure and Arc-enabled servers.
- **Security**: no public IPs on management ports; use Azure Bastion or just-in-time VM access; enable Defender for Servers.
- **Cost**: right-size, autoscale with Scale Sets, use reservations or savings plans for baseline, and Spot VMs for interruptible batch work.

</DeepDive>
