## Start with a question

<Story question="Your company has 300 servers. One of them fails at 3 am. Who notices, and who fixes it?">

In a traditional server room, maybe nobody notices until users complain in the morning. Then someone drives in, finds the server, and starts repairing it.

In the cloud, monitoring can **notice automatically**, a scale set can **replace the failed instance automatically**, and an alert reaches the on-call engineer's phone. If anyone needs to act, they can do it **from a browser anywhere**. That is **manageability**.

</Story>

## Explain it like I'm 10

<Eli10>

Think of a **video game** where you build a city. You do not walk around fixing every building by hand. You have a **control panel**: tap a button to build ten houses, see warning icons when a building catches fire, and send firefighters automatically.

Azure gives companies a control panel like that for their computers. They can manage everything from one screen, or even let it **fix itself**.

</Eli10>

### One control plane, many tools

Whichever tool you use, every management request goes through **Azure Resource Manager (ARM)**. That is why a VM created in the portal looks exactly the same as one created with the CLI or a Bicep file.

For example, creating a resource group with the Azure CLI:

```bash
az group create --name rg-exam-portal --location westeurope
```

…or declaring infrastructure as code with Bicep:

```bicep
resource storage 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: 'stexamportal001'
  location: 'westeurope'
  sku: { name: 'Standard_ZRS' }
  kind: 'StorageV2'
}
```

You do not need to write code for AZ-900. Just recognise that these tools exist and what each is for. They are covered fully in Module 3.

<DeepDive title="From click-ops to platform engineering">

Teams usually move through stages:

1. **Click-ops** in the portal, which is fine for learning, risky for production.
2. **Scripts** (CLI/PowerShell) for repeatable tasks.
3. **Infrastructure as code** in source control with CI/CD pipelines, so environments are reproducible and changes are reviewed.
4. **Platform engineering**: golden templates, policy-as-code, self-service environments (for example Azure Deployment Environments) and automated operations with Azure Monitor alerts triggering runbooks or Functions.

Measure manageability by how long it takes to stand up a new, compliant environment, and by how much of incident response is automated.

</DeepDive>
