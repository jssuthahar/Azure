## Start with a question

<Story question="Would you pay for a full year of gym membership if you only plan to go for three weeks?">

Traditional IT is like buying the annual membership. You pay for servers sized for your busiest day, all year, even when they sit idle.

The cloud is like a **pay-per-visit gym pass**: each visit is recorded and you pay for what you used. That is the **consumption-based model**.

</Story>

## Explain it like I'm 10

<Eli10>

Think of a **water meter** at home. Every time you turn on the tap, the meter counts the litres. At the end of the month you pay for exactly the water you used. Long showers cost more; a holiday month costs almost nothing.

Azure has meters too. They count **how long your computers run** and **how much stuff you store**, and you pay for exactly that.

</Eli10>

## The technical explanation

In the **consumption-based model**, cloud resources are **metered** and billed according to actual usage. Microsoft's AZ-900 material lists three benefits:

1. **No up-front costs**: nothing to buy before you start.
2. **No need to purchase and manage costly infrastructure** that you might not fully use.
3. **Pay for additional resources only when you need them**, and stop paying when you no longer need them.

### How Azure meters common services

| Service | Typical meter |
| --- | --- |
| Virtual Machines | Per second of running time, by VM size (and OS licence if included) |
| Managed Disks | Per disk size tier per month (billed even if the VM is stopped) |
| Blob Storage | GB stored per month + read/write operations + data retrieval for some tiers |
| Azure Functions (consumption plans) | Executions + memory used over time (GB-seconds) |
| Bandwidth | GB of data transferred out (egress); inbound data is generally free |
| Azure SQL Database | Provisioned compute (vCores) per hour, or serverless compute used per second |

<Callout type="warning">
**A VM that is "Stopped" is not the same as "Stopped (deallocated)".** If you shut down the operating system from inside the VM, Azure still reserves the hardware and keeps charging compute. Stop it from the Azure portal, CLI or PowerShell so it is deallocated. Disks keep billing until you delete them.
</Callout>

<DeepDive title="FinOps: making consumption pricing work for you">

The consumption model gives engineers the power to spend money with an API call. Mature organisations treat that as a shared responsibility called **FinOps**:

- **Visibility**: tag every resource (owner, cost centre, environment) and report by tag in Cost Management.
- **Accountability**: budgets per team with alert thresholds (for example 50%, 80%, 100%), plus anomaly alerts.
- **Optimisation**: right-size with Azure Advisor, auto-shutdown for non-production, delete orphaned disks and IPs, choose storage tiers deliberately, and buy reservations or savings plans for the steady baseline (see Cloud Pricing Models).
- **Architecture**: prefer services that scale to zero for spiky workloads; cache to cut egress; keep chatty services in the same region.

</DeepDive>
