interview:
  - level: beginner
    q: Explain the difference between a VM, a container and a function.
    a: >-
      A VM is a whole computer with its own operating system that I manage. A container is a lightweight package of just my app and its dependencies that shares the host's OS, so it starts quickly. A function is a small piece of code that runs only when an event happens, with no servers to manage at all.
    followUps: []
  - level: intermediate
    q: Why are containers more lightweight than VMs?
    a: >-
      VMs virtualise hardware, so each one boots a full guest OS. Containers virtualise the operating system: they share the host kernel and only package the app and its libraries. That makes them smaller, faster to start and denser on the same hardware.
    followUps: []
  - level: experienced
    q: How would you pick between AKS, Azure Container Apps and Azure Functions for a new microservices system?
    a: >-
      Functions for event-driven glue and short tasks. Container Apps for containerised microservices when I want serverless scaling, including to zero, without running Kubernetes myself. AKS when I need full Kubernetes control, custom networking, operators or very large scale and have the skills to run it. I would start with the most managed option that meets the requirements.

## Start with a question

<Story question="Do you need a whole house, a caravan, or just a tent?">

A house gives you everything but takes ages to build. A caravan is quick to move and has what you need. A tent is up in a minute for one night. Azure compute is the same choice: **VMs, containers or functions**.

</Story>

## Explain it like I'm 10

<Eli10>

- 🏠 A **virtual machine** is a whole house: you decorate every room and fix the plumbing.
- 🚐 A **container** is a caravan: it carries just what you need and goes anywhere quickly.
- ⛺ A **function** is a pop-up tent: it appears when needed, then packs itself away.

</Eli10>
