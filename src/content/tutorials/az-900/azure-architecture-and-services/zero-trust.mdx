  **Zero Trust** is a security model that assumes the worst and trusts nothing by default, not even requests from inside the corporate network. Its three guiding principles are **verify explicitly** (always authenticate and authorise using all available signals), **use least privilege access** (just-in-time and just-enough access) and **assume breach** (minimise blast radius and segment access).

## Start with a question

<Story question="Once someone is inside the office network, should they be trusted with everything?">

The old model said yes. **Zero Trust** says no: check every request, every time.

</Story>

## Explain it like I'm 10

<Eli10>

In a Zero Trust school, you show your ID at **every door**, not just the front gate. Even if you're already inside, the library still checks you, and you only get keys to the rooms you need today.

</Eli10>

## The technical explanation

| Principle | Meaning | Azure examples |
| --- | --- | --- |
| Verify explicitly | Use identity, device, location and risk on every request | Entra ID, MFA, Conditional Access |
| Least privilege | Just-in-time, just-enough access | Azure RBAC, Privileged Identity Management |
| Assume breach | Segment, encrypt, monitor, limit blast radius | NSGs, private endpoints, Defender for Cloud |
