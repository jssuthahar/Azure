interview:
  - level: beginner
    q: What is the simplest way to run a container in Azure?
    a: >-
      Azure Container Instances. I give it an image and it runs, with no VMs or cluster to manage, and I pay per second while it runs.
    followUps: []
  - level: intermediate
    q: When would you choose AKS over Container Instances?
    a: >-
      When I have many containers that need orchestration: automatic scaling, rolling updates, self-healing, service discovery and load balancing. ACI is for single containers or short tasks; AKS is for complex, long-running microservice systems.
    followUps: []
  - level: experienced
    q: Where does Azure Container Apps fit?
    a: >-
      Between the two. It runs microservices on Kubernetes under the hood, with KEDA autoscaling, Dapr and revisions, but without exposing the cluster. It suits teams that want microservices and scale to zero without becoming Kubernetes operators. AKS is for when you need the full Kubernetes API and ecosystem.

## Start with a question

<Story question="“It works on my machine!” Why does code break when it moves to a server?">

Because the server has different versions and settings. **Containers** fix this by packing the app with everything it needs.

</Story>

## Explain it like I'm 10

<Eli10>

A container is like a **lunchbox** with everything inside: sandwich, fork, napkin. You can take it anywhere and lunch works the same.

- **ACI**: eat one lunchbox now.
- **Container Apps**: a canteen that brings out more lunchboxes when more kids arrive.
- **AKS**: a huge school kitchen run by a head chef (Kubernetes) for thousands of lunches.

</Eli10>
