  Besides Blob Storage, Azure Storage offers **Azure Files** (fully managed file shares over SMB and NFS), **Queue Storage** (large numbers of messages between application components), **Table Storage** (NoSQL key/attribute data) and **Managed Disks** (block-level storage volumes for virtual machines).
updated: 2026-11-11
readingMinutes: 6
keyTerms:
  - term: Azure Files
    definition: Managed file shares accessible over SMB or NFS, like a network drive.
  - term: Queue Storage
    definition: Stores messages (up to 64 KB each) so app components can work asynchronously.
  - term: Table Storage
    definition: Schemaless NoSQL storage of structured key/attribute data.
  - term: Managed Disk
    definition: A block storage volume attached to an Azure VM.
interview:
  - level: beginner
    q: Match each storage service to a use case.
    a: >-
      Azure Files for shared folders that many computers map as a drive. Queues for passing work messages between parts of an app. Tables for simple NoSQL data such as user settings. Managed Disks for the hard drives of virtual machines.
    followUps: []
  - level: intermediate
    q: Why would an app use a queue?
    a: >-
      To decouple components. The front end drops a message on the queue and returns quickly, and back-end workers process messages at their own pace. If workers are slow or down, messages wait instead of being lost, which smooths out traffic spikes.
    followUps: []
  - level: experienced
    q: Azure Files or Blob Storage for a document-processing app?
    a: >-
      Azure Files if existing software expects a file system path or SMB share, or for lift-and-shift of file servers. Blob Storage for new cloud-native apps reading through HTTP APIs or SDKs, which is cheaper and more scalable, with tiers and events.
    followUps: []
