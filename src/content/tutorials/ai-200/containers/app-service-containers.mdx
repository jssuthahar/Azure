## Start with a question

<Story question="Your AI search key is in the image. What happens when you need to change it?">

You rebuild the image, push it, redeploy, and hope nobody pulled the old one and kept it. Worse, anyone who can pull the image can read the key.

On **App Service**, configuration lives outside the image. You add **app settings**, they show up in your container as environment variables, and the secret ones can point at **Azure Key Vault**. Change a setting and the app restarts with the new value. No rebuild.

</Story>

## Explain it like I'm 10

<Eli10>

Your lunchbox (the image) is packed. But each day the teacher pins a note to it: "Today's room is 4B". That note is an **app setting**. You don't repack the box to change the room.

Some notes are secret, like a locker code. Instead of writing the code on the note, the teacher writes "ask the office for locker 12". The office is **Key Vault**, and only you are allowed to ask.

</Eli10>

## The technical explanation

### Create the web app from an ACR image

```bash
az appservice plan create --resource-group rg-ai --name plan-rag --is-linux --sku P0v3

az webapp create --resource-group rg-ai --plan plan-rag --name ragapi-web \
  --container-image-name myreg.azurecr.io/ragapi:1.4.0 \
  --assign-identity '[system]'
```

Let the app pull with its **managed identity** instead of a registry password:

```bash
PRINCIPAL=$(az webapp identity show -g rg-ai -n ragapi-web --query principalId -o tsv)
ACR_ID=$(az acr show -n myreg --query id -o tsv)
az role assignment create --assignee $PRINCIPAL --role AcrPull --scope $ACR_ID
az webapp config set -g rg-ai -n ragapi-web --generic-configurations '{"acrUseManagedIdentityCreds": true}'
```

To move to a new version later, run `az webapp config container set -g rg-ai -n ragapi-web --container-image-name myreg.azurecr.io/ragapi:1.5.0`.

### Settings become environment variables

```bash
az webapp config appsettings set -g rg-ai -n ragapi-web --settings \
  WEBSITES_PORT=8000 \
  MODEL_DEPLOYMENT=gpt-4.1-mini \
  SEARCH_ENDPOINT=https://srch-rag.search.windows.net
```

```python
import os
deployment = os.environ["MODEL_DEPLOYMENT"]      # set as an app setting
search_key = os.environ["SEARCH_KEY"]            # a Key Vault reference, resolved for you
```

App Service tries to detect the port, but if your container listens on 8000, set **WEBSITES_PORT=8000**. Saving settings restarts the app. **Connection strings** also become environment variables, with a prefix such as `SQLAZURECONNSTR_` or `CUSTOMCONNSTR_`.

### Secrets: Key Vault references

1. Turn on the app's managed identity (done above with `--assign-identity`).
2. Give it read access to secrets: the **Key Vault Secrets User** role (or a Get access policy).
3. Set the app setting value to a reference:

```bash
az webapp config appsettings set -g rg-ai -n ragapi-web --settings \
  SEARCH_KEY="@Microsoft.KeyVault(SecretUri=https://kv-rag.vault.azure.net/secrets/search-key/)"
# the other accepted form:
#   @Microsoft.KeyVault(VaultName=kv-rag;SecretName=search-key)
```

Leave the version off the URI and App Service uses the latest version, refreshing it within 24 hours (or immediately when the app's config changes). Put a version on it and the value stays pinned.

<Callout type="exam">
If a question wants configuration **without rebuilding the image**, the answer is **app settings**. If it wants the secret **stored in Key Vault** but read by the app **as an environment variable**, it's a **Key Vault reference** and a **managed identity** with access to the vault. A container that "doesn't respond to HTTP pings" on a custom port needs **WEBSITES_PORT**. Pulling from ACR without credentials is the **managed identity** with **AcrPull**. In slots, tick **deployment slot setting** for values that must not swap.
</Callout>

<DeepDive title="Troubleshooting a reference that won't resolve">

In the portal, the Environment variables page shows a status next to each Key Vault reference. A red status usually means the identity has no access, the vault's firewall blocks App Service (allow trusted services, or use VNet integration and a private endpoint), or the secret name is wrong. If the app uses a user-assigned identity, set `keyVaultReferenceIdentity` on the site so App Service knows which identity to use. For container logs, turn on logging with `az webapp log config --docker-container-logging filesystem` and stream them with `az webapp log tail`.

</DeepDive>
