## The technical explanation

**Azure Database for PostgreSQL flexible server** is managed PostgreSQL. Microsoft patches it, backs it up and can run a standby for high availability. You still write normal SQL and use normal PostgreSQL drivers. For Python that's **psycopg** version 3:

```bash
pip install "psycopg[binary]" psycopg_pool azure-identity
```

### What a connection needs

| Setting | Example | Notes |
| --- | --- | --- |
| `host` | `contoso-pg.postgres.database.azure.com` | From the server's Overview page |
| `port` | `5432` | `6432` if you go through the built-in PgBouncer |
| `dbname` | `support` | A database on the server |
| `user` | `rag-api` (an Entra identity) or `pgadmin` | The role name in PostgreSQL |
| `password` | an Entra token, or a database password | Token preferred |
| `sslmode` | `require` | Refuses to connect without TLS |

### Passwordless sign-in with Microsoft Entra ID

Two things have to be set up on the server first. The server's authentication must allow Microsoft Entra (the portal option is "Microsoft Entra authentication only" or "PostgreSQL and Microsoft Entra authentication"). And an **Entra admin** must create a database role for your user, group or managed identity.

Then your code asks for a token and uses it as the password:

```python
import os
import psycopg
from azure.identity import DefaultAzureCredential

credential = DefaultAzureCredential()

def get_token() -> str:
    # Token for Azure Database for PostgreSQL
    return credential.get_token("https://ossrdbms-aad.database.windows.net/.default").token

conn = psycopg.connect(
    host=os.environ["PGHOST"],          # contoso-pg.postgres.database.azure.com
    dbname=os.environ["PGDATABASE"],    # support
    user=os.environ["PGUSER"],          # rag-api (the managed identity's role name)
    password=get_token(),
    port=5432,
    sslmode="require",
)
```

`DefaultAzureCredential` uses your `az login` session on your laptop and the app's **managed identity** in App Service, Container Apps or Functions. Same code, no secret.

The token is checked only when a connection opens. An open connection keeps working after the token expires, but any new connection needs a fresh token. That matters once you add a pool, which you'll see below and in the performance lesson.

### Running queries safely

```python
tenant = "contoso"
search = "refund"

with conn:                                   # commits on success, rolls back on error
    with conn.cursor() as cur:
        cur.execute(
            "SELECT id, title FROM docs WHERE tenant_id = %s AND title ILIKE %s LIMIT 10",
            (tenant, f"%{search}%"),         # values travel separately from the SQL
        )
        for row in cur.fetchall():
            print(row)

        cur.execute(
            "INSERT INTO docs (tenant_id, title, body) VALUES (%(t)s, %(title)s, %(body)s) RETURNING id",
            {"t": tenant, "title": "Refund policy", "body": "Refunds within 30 days..."},
        )
        new_id = cur.fetchone()[0]
```

The `%s` and `%(name)s` placeholders are the whole point. psycopg sends the SQL text and the values separately, so a value like `'; DROP TABLE docs; --` is just a strange title, not a command. This is called a **parameterised query**, and it's the answer to SQL injection.

For many rows at once, `cur.executemany(sql, rows)` reuses the same statement, and `cur.copy()` with `COPY ... FROM STDIN` is the fastest way to bulk-load, which you'll want when loading thousands of embeddings.

### Reusing connections

Opening a PostgreSQL connection costs a TLS handshake, sign-in and a new server process. A web API that opens one per request spends more time connecting than querying. Use a pool, and give it a connection class that gets a fresh token every time it opens a connection:

```python
from psycopg_pool import ConnectionPool

class EntraConnection(psycopg.Connection):
    @classmethod
    def connect(cls, conninfo="", **kwargs):
        kwargs["password"] = get_token()     # fresh token for every new connection
        return super().connect(conninfo, **kwargs)

pool = ConnectionPool(
    conninfo=f"host={os.environ['PGHOST']} dbname=support user=rag-api sslmode=require",
    connection_class=EntraConnection,
    min_size=2, max_size=10,
)

with pool.connection() as conn:
    print(conn.execute("SELECT version()").fetchone())
```

<Callout type="exam">
Watch for three things. **Passwordless** or "no secrets in code" means a **Microsoft Entra token** from **DefaultAzureCredential** used as the PostgreSQL password, with the scope **`https://ossrdbms-aad.database.windows.net/.default`**. "Prevent SQL injection" means **parameterised queries**. And "the app fails after about an hour" points to a token fetched once and reused for new connections.
</Callout>

<DeepDive title="Network access decides whether you can connect at all">

Flexible server has two networking models, chosen at creation. **Public access** gives the server a public endpoint protected by firewall rules (and you can add private endpoints). **Private access (VNet integration)** puts the server inside a delegated subnet with no public endpoint, and your app must reach that VNet. If the connection times out, it's almost always networking. If it's refused with "password authentication failed", it's the token, the user name or a missing role. Knowing which error means what saves a lot of time.

</DeepDive>
