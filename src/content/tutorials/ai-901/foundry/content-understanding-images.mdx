## The technical explanation

Content Understanding handles images with the same building block as documents: an **analyzer**. You either use a prebuilt one or create your own.

### Prebuilt: describe the image

**`prebuilt-imageSearch`** returns a natural-language description of an image. That's handy for search and retrieval-augmented generation (RAG): index the descriptions and people can find photos by typing what they're looking for.

### Custom: your own fields

For business-specific answers you create a **custom analyzer**:

1. Set **`baseAnalyzerId`** to **`prebuilt-image`**.
2. Add a **field schema**: each field has a name, type, description and method.
3. Test it on sample images in the Foundry portal and check the confidence scores.

Images support two field methods:

| Method | What it does | Car-photo example |
| --- | --- | --- |
| **Classify** | Picks one value from a list you define | `DamageType`: Scratch, Dent, Broken glass, None |
| **Generate** | Writes a value from what it sees | `DamageSummary`: "Dent and scratch on the rear left door." |
| Extract | Copies a value printed in a document | Not available for images |

```json
{
  "baseAnalyzerId": "prebuilt-image",
  "fieldSchema": {
    "fields": {
      "DamageType":    { "type": "string", "method": "classify", "enum": ["Scratch", "Dent", "Broken glass", "None"] },
      "Severity":      { "type": "string", "method": "classify", "enum": ["Minor", "Moderate", "Severe"] },
      "DamageSummary": { "type": "string", "method": "generate", "description": "One sentence describing visible damage and where it is" }
    }
  }
}
```

This JSON is simplified to show the shape. In the portal you add the same fields through a form, then upload a test photo.

### Where it fits next to other vision options

| Need | Pick |
| --- | --- |
| Generic caption, tags, objects or OCR | Azure Vision image analysis |
| An open question about one photo | A multimodal model in the chat playground or your app |
| The same business fields from thousands of images, with confidence scores | Content Understanding custom analyzer |
| Descriptions for image search | `prebuilt-imageSearch` |

<Callout type="exam">
Two traps to watch. First, a question may offer **extract** as the method for an image field: it's wrong, extract is **documents only**. Second, if the scenario needs **custom categories** from photos (damage type, product condition, shelf status) with consistent output, the answer is a **Content Understanding custom analyzer** on **prebuilt-image**, not plain image tagging.
</Callout>

<DeepDive title="Writing field descriptions that work">

The model fills fields from your descriptions, so the wording matters. Be specific about what counts: "Severe means the panel is torn or glass is broken; Moderate means a visible dent larger than a palm." For classify fields, keep the list short and the options clearly different, and include a "None" or "Unclear" option so the model isn't forced into a wrong choice. Then test on real, messy photos (bad lighting, odd angles) before you set your confidence threshold.

</DeepDive>
