### The deploy step

When you select **Deploy** on a model, Foundry asks for:

- **Deployment name**: anything you like, such as `gpt-4.1-mini` or `support-bot`. Your code will pass this exact name as `model`.
- **Deployment type**: where requests are processed and how you pay.
- **Rate limit** (tokens per minute) from your quota, plus the guardrail (content filter) to apply.

| Deployment type | What it means | Pick it when |
| --- | --- | --- |
| **Global Standard** | Pay per token; requests can be processed in any region | You're starting out, or want the newest models |
| **Data Zone Standard** | Processing stays inside the US, EU or APAC data zone | Data must stay in a zone |
| **Standard** | Processing in the resource's own geography | Strict regional processing |
| **Provisioned** (global, data zone or regional) | Reserved capacity in provisioned throughput units | Steady, high volume with predictable latency |
| **Global Batch** | Upload a file of requests, results within 24 hours, about half the price | Large jobs that aren't urgent |

Data stored at rest stays in your resource's geography for every type.

### The chat playground

The playground has a **system message** box, a chat window and a parameters panel:

| Parameter | What it does |
| --- | --- |
| **Temperature** (0 to 2) | Lower is focused and repeatable, higher is more varied and creative |
| **Top P** | Another way to control variety. Change this or temperature, not both |
| **Max output tokens** | Caps the length of each reply |
| **Stop sequences** | Text that makes the model stop generating |
| **Frequency and presence penalty** | Discourage repeating the same words or topics |
| **Past messages included** | How much chat history is sent with each new question |

Reasoning models show a **reasoning effort** setting instead of temperature.

When you're happy, select **View code**. It shows sample code (Python and other languages) with your endpoint, deployment name, system message and parameters already filled in, so the app behaves the same as the playground.

<TryIt labs="ai-deploy-chat" text="Deploy a model with Global Standard, chat with it in the playground and change the temperature and max tokens." />

<Callout type="exam">
Remember the order: **deploy first, then chat**. The **deployment name** is what code calls. **Global Standard** is the default type. For parameter questions: repeatable or factual answers → lower temperature; cut-off replies → raise max output tokens; the same phrases repeating → frequency penalty.
</Callout>

<DeepDive title="Quota, rate limits and instant access">

Each subscription has a quota of tokens per minute per model and region. When you deploy, you assign part of that quota to the deployment, and requests over the limit get HTTP 429 errors. Some models in preview offer instant access, where you can call them by name without creating a deployment, but for the exam assume the deploy-then-call flow. Open models can also run on managed compute, where you pay per hour for the VMs instead of per token.

</DeepDive>
