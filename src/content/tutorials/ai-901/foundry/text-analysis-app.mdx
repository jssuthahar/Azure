## The technical explanation

**Azure Language in Foundry Tools** gives you ready-made text analysis behind one endpoint. If you have a Foundry resource you already have it. Copy the endpoint and a key from the resource (or use Microsoft Entra ID), and install the SDK.

```bash
pip install azure-ai-textanalytics
export LANGUAGE_ENDPOINT="https://<resource-name>.cognitiveservices.azure.com/"
export LANGUAGE_KEY="<key>"
```

| Feature | Method | What you get back |
| --- | --- | --- |
| Sentiment analysis | `analyze_sentiment` | positive / neutral / negative / mixed, scores per sentence |
| Key phrase extraction | `extract_key_phrases` | A list of main talking points |
| Named entity recognition | `recognize_entities` | Text, category (Person, Location, DateTime...), confidence |
| PII detection | `recognize_pii_entities` | Personal data found, plus `redacted_text` |
| Language detection | `detect_language` | Language name and ISO code |
| Summarization | `begin_abstract_summary` / `begin_extract_summary` | New summary sentences, or the key existing sentences |

### text_app.py

```python
import os
from azure.core.credentials import AzureKeyCredential
from azure.ai.textanalytics import TextAnalyticsClient

client = TextAnalyticsClient(
    endpoint=os.environ["LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["LANGUAGE_KEY"]),
)

reviews = [
    "The biryani was excellent but the rider called me five times. "
    "Call me on 9876543210 if there's a refund. Ordered in Chennai on Friday."
]

# Every method takes a LIST of documents and returns one result per document
sentiment = client.analyze_sentiment(reviews)[0]
print("Sentiment:", sentiment.sentiment, sentiment.confidence_scores)

phrases = client.extract_key_phrases(reviews)[0]
print("Key phrases:", phrases.key_phrases)

for entity in client.recognize_entities(reviews)[0].entities:
    print(f"Entity: {entity.text} ({entity.category}, {entity.confidence_score:.2f})")

pii = client.recognize_pii_entities(reviews)[0]
print("Redacted:", pii.redacted_text)  # the phone number comes back as asterisks

# Summaries run as a long-running operation
poller = client.begin_abstract_summary(reviews)
for doc in poller.result():
    print("Summary:", doc.summaries[0].text)
```

For that review you'd expect **mixed** sentiment (great food, annoying rider), key phrases like "biryani" and "rider", entities such as Chennai (Location) and Friday (DateTime), and a redacted line with the number masked.

### The alternative: ask a deployed model

You can get the same insights by prompting a chat model in Foundry, using the Foundry SDK from the chat app lesson:

```python
response = openai.responses.create(
    model="gpt-4.1-mini",  # deployment name
    instructions="Return JSON with sentiment, key_phrases and entities. Replace phone numbers with ***.",
    input=reviews[0],
)
print(response.output_text)
```

<Callout type="exam">
Match the verb to the feature. "Determine whether feedback is positive or negative" is **sentiment analysis**. "Identify the main points" is **key phrase extraction**. "Find people, places, organisations and dates" is **entity recognition**. "Hide personal information" is **PII detection**. "Shorten a long document" is **summarization**. The package is **azure-ai-textanalytics**, and every call takes a list of documents.
</Callout>

<DeepDive title="Plan for the 2029 retirements">

Microsoft has announced that key phrase extraction, sentiment analysis, summarization, entity linking, conversational language understanding and custom question answering in Azure Language retire on 31 March 2029, with Foundry models as the suggested path. Language detection, PII detection, NER and Text Analytics for health continue. A new project that leans on sentiment or summaries should either plan a move to prompts on a deployed model or start there.

</DeepDive>
