## Start with a question

<Story question="Your agent works perfectly in the playground. How do your customers use it?">

Nobody's going to log in to the Foundry portal to chat with your HR agent. Staff want it inside the intranet page, a Teams bot or a little command-line tool.

That's what a **client app** is for. It's a few lines of Python that send the user's message to the agent you built and print the reply, turn after turn.

</Story>

<Eli10>

## The technical explanation

A client app needs four things: the **project endpoint**, a **credential**, the **agent's name**, and a **conversation** to hold the chat history.

### 1. Set up

```bash
pip install "azure-ai-projects>=2.3.0" azure-identity
az login
# Project endpoint from the project's overview page in the Foundry portal
export FOUNDRY_PROJECT_ENDPOINT="https://<resource-name>.services.ai.azure.com/api/projects/<project-name>"
```

The project client only signs in with **Microsoft Entra ID**. Locally, `DefaultAzureCredential` picks up your `az login`. In Azure, give the app a managed identity with the **Foundry User** role on the project.

### 2. Create (or update) the agent from code

If you built the agent in the portal you can skip this and just use its name. Doing it in code is handy when you want the definition in source control.

```python
import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import PromptAgentDefinition

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)

# Each call creates a new, immutable version of "hr-helper"
agent = project.agents.create_version(
    agent_name="hr-helper",
    definition=PromptAgentDefinition(
        model="gpt-4.1-mini",  # your deployment name, not the model family
        instructions="You are Contoso's HR helper. Answer only HR questions. "
                     "If you don't know, say so and suggest emailing HR.",
    ),
)
print(f"Agent {agent.name}, version {agent.version}")
```

### 3. Chat in a loop

```python
# An OpenAI client that sends every request to the hr-helper agent
openai = project.get_openai_client(agent_name="hr-helper")

# One conversation = one chat with memory
conversation = openai.conversations.create()

while True:
    question = input("You: ").strip()
    if question.lower() in ("", "quit", "exit"):
        break
    response = openai.responses.create(
        conversation=conversation.id,
        input=question,
    )
    print("Agent:", response.output_text)

# Clean up the conversation when the chat is over
openai.conversations.delete(conversation_id=conversation.id)
```

Ask "How many casual leave days do I get?" and then "Can I carry them forward?". The second question only makes sense because the conversation already holds the first one. If you created a fresh conversation inside the loop, the agent would have no idea what "them" means.

### 4. Tidy up

Test code tends to leave things behind. Delete conversations you don't need, and if you created an agent version only for a test, delete it too (`project.agents.delete_version(...)` with the agent name and version). In a real app you'd keep the agent and create it from a deployment script, not every time the app starts.

<Callout type="exam">
Three ideas get tested here. To connect, you use **AIProjectClient** with the **project endpoint** and a Microsoft Entra ID credential such as **DefaultAzureCredential**, not an API key. To keep context, you reuse **one conversation** across turns. And the `model` you put in the definition is your **deployment name**.
</Callout>

<DeepDive title="What about Agent Framework?">

For bigger code-first projects Microsoft recommends the Microsoft Agent Framework (`agent-framework` package), which adds orchestration across several agents, middleware and local tools. For AI-901 the Foundry SDK calls above are enough: a project client, an agent version, a conversation and responses.
