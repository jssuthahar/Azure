## The technical explanation

Every Content Understanding app follows the same four steps, whatever the content type.

### What you need

- A **Foundry resource** with Content Understanding available and **default model deployments** set (analyzers call them).
- The resource **endpoint** (it looks like `https://<resource-name>.services.ai.azure.com/`) and either a **key** or Microsoft Entra ID access.
- An analyzer ID: a prebuilt one such as `prebuilt-invoice`, or a custom analyzer you created in the portal.

### The app

```python
# extract_app.py
# pip install azure-ai-contentunderstanding
import os
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.ai.contentunderstanding.models import AnalysisInput
from azure.core.credentials import AzureKeyCredential

client = ContentUnderstandingClient(
    endpoint=os.environ["CONTENTUNDERSTANDING_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["CONTENTUNDERSTANDING_KEY"]),
)

invoice_url = "https://example.com/invoices/inv-1042.pdf"  # your file's URL

# 1. Start the analysis (it runs asynchronously)
poller = client.begin_analyze(
    analyzer_id="prebuilt-invoice",
    inputs=[AnalysisInput(url=invoice_url)],
)

# 2. Wait for it to finish
result = poller.result()
fields = result.contents[0].fields

# 3. Read each field and route by confidence
THRESHOLD = 0.85
needs_review = []
for name, field in fields.items():
    confidence = field.confidence or 0
    print(f"{name}: {field.value} (confidence {confidence:.2f})")
    if confidence < THRESHOLD:
        needs_review.append(name)

# 4. Save or send to a person
if needs_review:
    print("Send to review:", ", ".join(needs_review))
else:
    print("All fields confident. Post to the finance system.")
```

Points worth knowing:

- **`begin_`** means a long-running operation. You get a **poller** back straight away and call `.result()` to wait.
- `result.contents` is a list. For one file you read `contents[0]`, which also has the **Markdown** of the document if you want the full text.
- Each field has a **`value`** and a **`confidence`**. Some fields (generated ones, for example) may not carry a confidence, which is why the code treats a missing score as 0.
- To switch to keyless auth, replace `AzureKeyCredential(...)` with `DefaultAzureCredential()` from `azure.identity` after `az login`.

### Same code, different content

Only the analyzer ID and the input change between content types:

| Content | Analyzer ID |
| --- | --- |
| Invoice | `prebuilt-invoice` |
| Receipt | `prebuilt-receipt` |
| Photo description | `prebuilt-imageSearch` |
| Call recording | `prebuilt-audioSearch` |
| Video | `prebuilt-videoSearch` |
| Your own fields | Your custom analyzer's ID |

<Callout type="exam">
Know the order: **create the client → begin_analyze → poller.result() → read fields**. If a question asks how the app decides what a person should check, the answer is the field's **confidence score** compared with a threshold. If it asks how to reuse the app for another content type, change the **analyzer ID**, not the code structure.
</Callout>

<DeepDive title="Making the review step useful">

A review queue only helps if the reviewer can act fast. Store the grounding with each low-confidence field so your review screen can highlight the spot on the page or the timestamp in the recording. Set thresholds per field rather than one global number: a wrong invoice total costs more than a wrong supplier phone number. Track how often reviewers correct each field; if they almost never change a value, you can lower its threshold and send fewer documents to people.

</DeepDive>
