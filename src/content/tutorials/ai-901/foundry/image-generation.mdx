## The technical explanation

An **image-generation model** turns a text prompt into a new image. In Foundry the main choice is **gpt-image-1** from OpenAI (DALL-E 3 is the older model you may still see). It's a different job from vision: a multimodal model *reads* an image you give it, while an image model *creates* one.

### Step 1: try it in the images playground

1. In your Foundry project, open the **model catalog**, find **gpt-image-1** and deploy it. Some image models need an access request before the deploy button works.
2. Open the **Images playground**, pick your deployment and type a prompt.
3. Set the **size** and **quality**, then generate. Change one thing at a time and compare.
4. Use **View code** to see the same request as Python.

| Setting | What it does | Values you'll see |
| --- | --- | --- |
| Size | Shape and resolution of the picture | `1024x1024` (square), `1536x1024` (landscape), `1024x1536` (portrait), `auto` |
| Quality | Detail level, which affects time and cost | `low`, `medium`, `high` (or `auto`) |
| Number of images | How many variations per request | `n` in code |

### Step 2: generate from code

You use the same Foundry SDK as for chat. The `model` value is your **deployment name**.

```python
# pip install "azure-ai-projects>=2.3.0" azure-identity
import base64, os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),   # uses your az login
)
openai = project.get_openai_client()

result = openai.images.generate(
    model="gpt-image-1",            # your deployment name
    prompt="A festive poster: a brass plate of laddoos surrounded by glowing diyas, "
           "warm golden light, the words 'Diwali Specials' in bold at the top",
    size="1024x1536",               # portrait poster
    quality="medium",
)

# gpt-image-1 returns base64 data, so decode it and save a PNG
with open("poster.png", "wb") as f:
    f.write(base64.b64decode(result.data[0].b64_json))
```

### Writing prompts that work

- **Subject first**, then setting, style, lighting and camera angle: "close-up product photo, white background, soft studio light".
- **Spell out any text** you want on the image and keep it short. Long sentences in images still go wrong sometimes.
- **Say the layout**: "logo in the top-left corner, empty space on the right for a price".
- **Iterate**. Keep the prompt that worked and change one detail per try.

### Editing an existing image

gpt-image-1 can also **edit**. You send an image plus an instruction such as "replace the background with a beach at sunset", and you can add a **mask** so only part of the picture changes (often called inpainting). In code that's `images.edit` instead of `images.generate`; in the playground you upload an image and describe the change.

### Guardrails and content credentials

Foundry **guardrails** (content filters) check image prompts and the generated images for hate, sexual, violence and self-harm content. If something's blocked, the request fails with a content-filter error instead of returning an image, and your app should show a friendly message. Every generated image also carries **content credentials**: signed C2PA metadata saying it was made with AI, so a newspaper or a customer can check where it came from.

<Callout type="exam">
Watch the verb. "Describe what's in this photo" points to a **multimodal or vision** model. "Create a new image from a description" points to an **image-generation** model like gpt-image-1. "Show the image was AI-generated" is **content credentials**, not a watermark you add yourself.
</Callout>

<DeepDive title="Cost and speed trade-offs">

Image generation is billed per image, and the price depends on size and quality, so `high` quality at a large size costs the most. A sensible pattern is to draft at `low` or `medium` quality, pick the best prompt, then generate the final at `high`. Generation takes a few seconds to tens of seconds, so web apps usually show a spinner or run the request in the background rather than blocking the page.

</DeepDive>
