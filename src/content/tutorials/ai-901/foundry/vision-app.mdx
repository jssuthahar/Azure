## The technical explanation

A lightweight vision app does four things: **load** an image, **encode** it, **send** it with a question to a multimodal deployment, and **read** the answer. You test the prompt first in the chat playground (attach an image, ask a question), then use **View code** to get a starting script.

### What you need

- A Foundry project with a **multimodal model** deployed, such as GPT-4.1, GPT-4.1-mini or GPT-4o.
- The **project endpoint** in an environment variable, `FOUNDRY_PROJECT_ENDPOINT`.
- Signed in with `az login` and the **Foundry User** role on the project. The AIProjectClient uses Microsoft Entra ID only, so there's no key in the code.

### The app

```python
# vision_app.py
# pip install "azure-ai-projects>=2.3.0" azure-identity
import base64, os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
openai = project.get_openai_client()

# 1. Load and encode the photo as a data URL
with open("leaf.jpg", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode("utf-8")
data_url = f"data:image/jpeg;base64,{image_b64}"

# 2. Send the question and the image together
response = openai.responses.create(
    model="gpt-4.1-mini",   # your multimodal deployment name
    instructions="You help farmers. Answer in two short sentences.",
    input=[{
        "role": "user",
        "content": [
            {"type": "input_text", "text": "What might be wrong with this tomato leaf?"},
            {"type": "input_image", "image_url": data_url},
        ],
    }],
)

# 3. Read the answer
print(response.output_text)
```

A few things to notice:

- `model` is the **deployment name**, not the model family.
- The image can be a **data URL** (as above) or a public **https URL**.
- `instructions` works like a system message. Use it to control tone and length, or to ask for JSON your app can parse.
- You can loop and ask follow-up questions with `previous_response_id` or a conversation, just like a chat app.

### The alternative: Azure Vision image analysis

Not every vision task needs a prompt. **Azure Vision in Foundry Tools** image analysis returns fixed, structured results: a **caption**, dense captions, **tags**, detected **objects** and people, smart-crop suggestions and printed or handwritten text with **OCR (Read)**. It uses its own SDK (`azure-ai-vision-imageanalysis`) and returns the same JSON shape every time.

| Need | Pick |
| --- | --- |
| Ask a different question about each photo, explain a chart, compare two images | Multimodal model via the Foundry SDK |
| Same caption and tags for millions of catalogue photos | Azure Vision image analysis |
| Read the text on a sign or a label | Azure Vision OCR (Read), or a multimodal model for a quick one-off |
| Pull named fields from images into a schema you define | Content Understanding |

<Callout type="exam">
If the question says the app must **answer questions about an image** or follow instructions about it, the answer is a **multimodal model** with an image in the prompt. If it lists **captions, tags or OCR** as the output with no prompt, it's **Azure Vision** image analysis. And remember the code clue: `input_image` sits next to `input_text` in the same user message.
</Callout>

<DeepDive title="Image size, tokens and detail">

Images are turned into tokens before the model sees them, and bigger images cost more tokens. Resize phone photos (often 4,000 pixels wide) to something like 1,024 pixels on the long side before sending, unless tiny details matter. Some models accept a `detail` setting (`low`, `high`, `auto`) on the image part; `low` is cheaper and fine for "what's in this photo?" questions. Keep sensitive photos in mind too: guardrails apply to image inputs, and you should tell users what happens to the pictures they upload.

</DeepDive>
