## The technical explanation

Models such as **GPT-4.1**, **GPT-4o** and the **GPT-5** family accept images in the prompt. The model card in the Foundry model catalog lists the supported inputs, so check it says image input before you deploy.

### In the chat playground

Open your multimodal deployment in the **chat playground**, attach an image to the message, and ask a question. The system message still applies, so you can say "You are an insurance assessor. Describe visible damage only, and don't guess the repair cost." It's the fastest way to see whether the model handles your kind of image.

### In code

With the Foundry SDK, the user message holds a list of **content parts**: `input_text` for the question and `input_image` for the picture.

```python
import base64, os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"], credential=DefaultAzureCredential())
openai = project.get_openai_client()

# A local photo becomes a base64 data URL
with open("bumper.jpg", "rb") as f:
    data_url = "data:image/jpeg;base64," + base64.b64encode(f.read()).decode("utf-8")

response = openai.responses.create(
    model="gpt-4.1",  # a multimodal deployment name
    instructions="You are an insurance assessor. Describe visible damage only.",
    input=[{
        "role": "user",
        "content": [
            {"type": "input_text", "text": "Where is the damage on this car, and how large does it look?"},
            {"type": "input_image", "image_url": data_url},
            # or an online image: {"type": "input_image", "image_url": "https://example.com/bumper.jpg"}
        ],
    }],
)
print(response.output_text)
```

You can put several images in one message, for example "before" and "after" photos, and ask the model to compare them.

### Getting good answers from images

| Do | Why |
| --- | --- |
| Ask a specific question ("What's the expiry date on the label?") | Vague prompts get vague descriptions |
| Send a clear, well-lit, upright image, cropped to what matters | Blur, rotation and clutter cause misreads |
| Tell it to say when it's unsure | Cuts down confident guesses |
| Check counts, small text and measurements | These are common weak spots |
| Keep a person in the loop for medical, legal or safety decisions | The model can be wrong and isn't accountable |

Images cost tokens like text does, and bigger or higher-detail images use more. Your deployment's **guardrails** (content filters) check image inputs too, and you shouldn't send images of people without a good reason and their awareness.

<Callout type="exam">
"Ask a question about an image" or "describe a photo in a chat" points to a **multimodal model** with an **input_image** part (URL or base64). If the scenario wants **fixed, repeatable** outputs like tags, bounding boxes or OCR text at scale, **Azure Vision in Foundry Tools** or Content Understanding fits better. And creating a **new** image is a different job: that's an image-generation model such as gpt-image-1.
</Callout>

<DeepDive title="The image detail setting">

The `input_image` part can take an optional `detail` value: `low`, `high` or `auto`. Low sends a small version of the image and uses far fewer tokens, which is fine for "is this a cat or a dog?". High lets the model look at tiles of the full image, which helps with small print and fine detail but costs more tokens. Auto lets the service choose.

</DeepDive>
