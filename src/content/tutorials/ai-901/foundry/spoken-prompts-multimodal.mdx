## The technical explanation

A **multimodal model** takes more than one kind of input. **Audio-capable** models in the Foundry model catalog (for example the gpt-audio and gpt-4o-audio-preview families) take speech as input and can return **text, audio or both**. Check the model card for supported audio formats, languages and regions, and deploy it in your project like any other model.

In the Foundry **chat playground** you can try this first: pick the audio model deployment, record or attach a short clip, and read the reply.

### Sending audio from Python

Audio-capable models use the Chat Completions message format. The user message holds a list of **content parts**: a text instruction and an **input_audio** part with the recording as base64.

```python
import base64, os
from openai import OpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

# Sign in with Microsoft Entra ID (az login locally)
token = get_bearer_token_provider(DefaultAzureCredential(), "https://cognitiveservices.azure.com/.default")
client = OpenAI(
    base_url=os.environ["AZURE_OPENAI_ENDPOINT"] + "openai/v1/",  # https://<resource>.openai.azure.com/
    api_key=token,
)

# Read a short WAV recording and encode it as base64
with open("question.wav", "rb") as f:
    audio_b64 = base64.b64encode(f.read()).decode("utf-8")

completion = client.chat.completions.create(
    model="gpt-audio",            # your audio-capable deployment name
    modalities=["text"],          # use ["text", "audio"] to get speech back too
    messages=[
        {"role": "system", "content": "You are a farm advisor. Answer in two short sentences."},
        {"role": "user", "content": [
            {"type": "text", "text": "Answer the question in this recording."},
            {"type": "input_audio", "input_audio": {"data": audio_b64, "format": "wav"}},
        ]},
    ],
)
print(completion.choices[0].message.content)
```

If you ask for `["text", "audio"]` you also pass an `audio` option (voice and output format), and the reply's `message.audio` holds base64 audio you can save and play, plus a transcript of what it said.

<Callout type="exam">
If the scenario says the app must send **speech directly to a model** and get an answer, pick an **audio-capable multimodal model** with an **input_audio** part. If it needs a specific neural voice, SSML or custom vocabulary, the **Azure Speech** pipeline fits better. If the caller must be able to **interrupt** in real time, think **realtime models** or the **Voice Live API**. A text-only model can't take audio.
</Callout>

<DeepDive title="Guardrails and privacy still apply">

The audio is a prompt like any other, so your deployment's guardrails (content filters) apply to what the model hears and says. Recordings can carry personal data such as names and account numbers, so treat stored audio like any other personal data: keep only what you need, and tell users their voice is being processed by AI. That's the transparency principle in practice.

</DeepDive>
