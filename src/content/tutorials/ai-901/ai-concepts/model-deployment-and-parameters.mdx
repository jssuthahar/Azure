  - term: Deployment
    definition: A named, callable instance of a model in your Foundry resource. Your code sends the deployment name as the model.
  - term: Global Standard
    definition: A pay-per-token deployment type where requests can be processed in any Azure region. Usually the first to get new models.
  - term: Data Zone Standard
    definition: A pay-per-token deployment type where processing stays inside a Microsoft-defined data zone (US, EU or APAC).
  - term: Provisioned throughput
    definition: Reserved model capacity bought in provisioned throughput units (PTUs), giving predictable, low-variance latency.
  - term: Batch deployment
    definition: An asynchronous deployment type that processes a file of requests with a 24-hour target, at about 50% lower cost.
  - term: Temperature
    definition: A parameter (0 to 2) that controls randomness. Low values give focused, repeatable answers; high values give more varied ones.
  - term: Top_p
    definition: A parameter that limits the model to the most likely tokens whose probabilities add up to p. Another way to control randomness.
  - term: Stop sequence
    definition: A string that makes the model stop generating when it would produce it.

## The technical explanation

Before your app can call a model in Microsoft Foundry, you **deploy** it inside your Foundry resource and give the deployment a name. Your code then sends that **deployment name** as the model. One model can have several deployments with different types and settings.

### Deployment types

| Deployment type | Where processing happens | How you pay | Pick it when |
| --- | --- | --- | --- |
| **Global Standard** | Any Azure region Microsoft routes to | Pay per token | You're starting out, want the newest models and high default quota |
| **Data Zone Standard** | Inside one data zone (US, EU or APAC) | Pay per token | A rule says data must be processed within that zone |
| **Standard** | The resource's own geography | Pay per token | You need processing in one geography and lower volume |
| **Global / Data Zone / Regional Provisioned** | Same split as above | Reserved capacity in PTUs | Steady, high, predictable traffic that needs low latency variance |
| **Global Batch / Data Zone Batch** | Global or within a data zone | About 50% cheaper per token | Big, non-urgent jobs sent as a file, 24-hour target |
| **Developer** | Global | Pay per token, no SLA | Evaluating fine-tuned models before production |

Two more options sit beside these. **Managed compute** runs open models on virtual machines you pay for by the hour. **Instant access** models (preview) can be called by name with no deployment step at all.

Whatever type you pick, **data at rest stays in your resource's geography**. The type only changes where a request is *processed*.

### Parameters

| Parameter | What it controls | Typical use |
| --- | --- | --- |
| **Temperature** (0 to 2) | Randomness of word choice. Lower = focused and repeatable | 0 to 0.3 for facts and extraction, around 1 for creative ideas |
| **Top_p** | Only consider the most likely tokens whose probabilities add up to p | Another way to control randomness. Change this *or* temperature, not both |
| **Max output tokens** | The longest the reply can be | Keep answers short and costs predictable |
| **Stop sequences** | Text that makes the model stop when it would produce it | End a list after one item, stop at "User:" |
| **Frequency penalty** | Discourages repeating the same tokens | Fewer repeated phrases |
| **Presence penalty** | Encourages bringing in new topics | More varied ideas in brainstorming |
| **Past messages included** (playground) | How much chat history is sent with each turn | More context vs more tokens |

**Reasoning models** work differently: instead of temperature you usually set a **reasoning effort** (how much the model thinks before it answers).

Here's how temperature and a token cap look in code with the Foundry SDK. `model` is your deployment name.

```python
# Low temperature for a factual answer, and a cap on length
response = openai.responses.create(
    model="gpt-4.1-mini",          # the deployment name, not the model family
    input="List three benefits of solar panels for a small shop.",
    temperature=0.2,               # focused, repeatable
    max_output_tokens=150,         # keep it short and cheap
)
print(response.output_text)
```

<Callout type="exam">
Watch for the residency clue. "Must be processed only within the EU" rules out **Global** types and points to **Data Zone** (or regional) deployments. "Predictable latency for steady traffic" means **Provisioned**. "Large, non-urgent, cheapest" means **Batch**. For parameters, "more deterministic answers" means **lower temperature**, and "limit the response length" means **max tokens**.
</Callout>

<DeepDive title="Quota, spillover and PTU sizing">

Pay-per-token deployments have a tokens-per-minute quota per model and region. Hit it and you get throttled (HTTP 429). Provisioned deployments are sized in PTUs, and you estimate the PTUs from your expected prompt and completion tokens per minute. Some teams run a Provisioned deployment for the steady base load and send overflow to a Standard deployment, so a traffic spike slows down gracefully instead of failing.

</DeepDive>
