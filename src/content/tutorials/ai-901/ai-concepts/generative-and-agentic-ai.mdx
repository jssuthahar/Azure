## Start with a question

<Story question="What's the difference between a friend who gives travel tips and a travel agent?">

Ask a well-travelled friend about a Goa trip and you'll get great advice: which beach, which month, what to eat. But you still have to book everything yourself.

A travel agent hears the same question and **does things**. Checks flight prices, finds a hotel with rooms, books both, and sends you the tickets.

Generative AI is the friend: it writes great answers. An **AI agent** is the travel agent: it uses tools to get the job done.

</Story>

## Explain it like I'm 10

<Eli10>

Generative AI is like a storyteller. You ask, it makes up words, pictures or songs.

An agent is a storyteller with a backpack of tools: a phone, a calculator, a map.

When you give it a job, it thinks "what should I do first?", uses a tool, looks at what happened, and tries the next step.

It keeps going until the job is done.

</Eli10>

## The technical explanation

**Generative AI** models (such as GPT-4.1 or Phi) take a prompt and produce new content one token at a time, each token predicted from everything before it. On their own they only know what they learned in training plus what you put in the prompt. They can't check today's stock level or send an email.

An **AI agent** wraps a model with two more things:

| Part | What it does | Example |
| --- | --- | --- |
| **Model** | Reads the request, reasons, decides what to do next | A gpt-4.1-mini deployment |
| **Instructions** | Sets the role, rules, tone and limits | "You're Contoso's support agent. Only discuss Contoso orders. Never promise a refund over the policy limit." |
| **Tools** | Let it fetch data or act | File search over policy PDFs, code interpreter, web search, function calling, OpenAPI tools, MCP servers, Azure AI Search |

The **conversation** keeps the history, so the agent remembers earlier turns. In Microsoft Foundry you build agents in **Foundry Agent Service**: Build, then Agents, then Create agent, pick a model, write instructions, add tools and test in the agent playground. Every save creates a new, immutable **version**, so you can roll back.

### Single agent, multi-agent and copilots

- **Single agent**: one agent with a focused job and a handful of tools. Start here.
- **Multi-agent**: several specialist agents (say, billing, shipping and returns), with an **orchestrator** agent or a workflow that routes each request and combines the results. Useful when one agent's instructions or tool list gets too big.
- **Copilot**: an AI assistant built into an app to help a person, like Microsoft 365 Copilot drafting a document or GitHub Copilot suggesting code. The person stays in charge and approves the result.

<TryIt labs="ai-first-agent" text="Create an agent with instructions and a tool, then ask it something that needs the tool and watch it call it." />

<Callout type="exam">
The word to watch is **tools**. If the scenario only needs new text or images, it's generative AI. If the AI must look something up, run code or change something in another system to finish a task, it's an **agent**. Remember the three parts: **model, instructions, tools**.
</Callout>

<DeepDive title="Keeping agents safe">

Give each agent only the tools and permissions it needs, and keep a human approval step for anything costly or hard to undo, like refunds or deleting records. Tool results are untrusted input: a web page or document can contain hidden instructions (indirect prompt injection), which is why Foundry guardrails include Prompt Shields. Use tracing and evaluations to see which tools an agent called and why.

</DeepDive>

## When to use it and when not to
