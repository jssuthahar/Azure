keyTerms:
  - term: AI workload
    definition: A category of task that AI performs, such as generating text, analysing sentiment or recognising speech.
  - term: Generative AI
    definition: AI that creates new content, such as text, code, images or audio, in response to a prompt.
  - term: Agentic AI
    definition: AI that pursues a goal by planning steps, calling tools and acting on the results, not just replying with text.
  - term: Text analysis
    definition: Extracting meaning from existing text, such as sentiment, key phrases, entities, language and summaries.
  - term: Computer vision
    definition: AI that interprets images and video, for example captions, object detection and reading printed text (OCR).
  - term: Information extraction
    definition: Turning unstructured content (documents, images, audio, video) into structured fields you can store and search.
  - term: Foundry Tools
    definition: The prebuilt AI services in Microsoft Foundry, formerly called Azure AI services, such as Azure Language, Azure Speech, Azure Vision and Azure Content Understanding.
interview:
  - level: beginner
    q: How do you tell text analysis apart from generative AI?
    a: >-
      Text analysis reads text that already exists and tells you something about it, like "this review is negative" or "these are the product names mentioned". Generative AI writes something new, like a reply to that review. Look at whether the output is a label or fresh content.
    followUps:
      - q: Can a generative model do text analysis too?
        a: >-
          Yes. You can prompt an LLM to return sentiment or key phrases. The exam still expects you to recognise the workload as text analysis, whichever tool you use.
  - level: intermediate
    q: What's the difference between computer vision and information extraction?
    a: >-
      Computer vision is about understanding what's in an image: a caption, objects, tags, the text it contains. Information extraction goes a step further and maps content into the specific fields you want, like InvoiceTotal or VendorName, often with confidence scores. It also works on audio and video, not just images.
    followUps: []
  - level: experienced
    q: When does a chatbot become an agentic AI workload?
    a: >-
      When it stops only answering and starts acting. If it can look up an order in a database, call a refund API or search files, and decide which of those to do and in what order, it's an agent. The giveaway is tools plus a goal it works towards over several steps.
    followUps: []
  - level: scenario
    q: A call centre wants to transcribe calls, detect angry customers and store the order number mentioned. Which workloads is that?
    a: >-
      Three working together. Speech to text for the transcript, text analysis for sentiment on that transcript, and information extraction or entity recognition to pull out the order number. Content Understanding can do the transcript and fields in one analyzer on the audio.
    followUps: []

## Start with a question

<Story question="If you hired one assistant for your shop, what would you actually ask them to do?">

Reply to customer emails. Read the reviews and tell you who's unhappy. Answer the phone. Check photos of stock for damage. Type the numbers from supplier bills into your accounts. Maybe even reorder stock when it runs low.

Those are very different jobs. AI splits them the same way. Each kind of job is an **AI workload**, and once you can name the workload, picking the right tool gets easy.

</Story>

## The technical explanation

AI-901 expects you to read a short scenario and name the workload. The trick is to ask two questions: **what goes in**, and **what should come out**?

| Workload | Input | Output | Example | Typical Azure option |
| --- | --- | --- | --- | --- |
| **Generative AI** | A prompt | New text, code, image or audio | Draft a reply to a complaint | Foundry Models (GPT, Phi, Llama) |
| **Agentic AI** | A goal | Actions taken plus an answer | Check an order, issue a refund, email the customer | Foundry Agent Service |
| **Text analysis** | Existing text | Labels, phrases, entities, summary | Find negative reviews and the products they mention | Azure Language in Foundry Tools, or an LLM prompt |
| **Speech** | Audio or text | Text or synthesised speech | Transcribe a call, read a message aloud | Azure Speech in Foundry Tools, audio-capable models |
| **Computer vision** | Image or video | Captions, tags, objects, text (OCR), or a new image | Spot missing items on a shelf photo | Azure Vision in Foundry Tools, multimodal models, gpt-image-1 |
| **Information extraction** | Documents, images, audio, video | Structured fields with confidence scores | Pull vendor, total and due date from invoices | Azure Content Understanding in Foundry Tools |

### Clue words to look for

- **Create, write, draft, generate, compose** point to generative AI.
- **Plan, act, book, update, use tools, complete a task** point to agentic AI.
- **Sentiment, opinion, key phrases, entities, PII, detect language, summarise** point to text analysis.
- **Transcribe, caption a call, read aloud, voice, translate speech, who spoke when** point to speech.
- **Photo, image, object, tag, read text in an image, describe a picture** point to computer vision.
- **Invoice, receipt, form, fields, schema, extract values, confidence score** point to information extraction.

Real solutions often mix workloads. A support line might use speech to text, then text analysis on the transcript, then a generative model to draft a follow-up email.

<TryIt labs="ai-foundry-setup" text="Create a Foundry resource and project, then look around: the same resource gives you models and Foundry Tools for every workload." />

<Callout type="exam">
Read the *output* the question wants. "Positive, negative or neutral" is text analysis, even if the input came from a call. "Write a reply" is generative. "Fill in fields from a scanned form" is information extraction, not plain OCR. And a chatbot is only **agentic** if it uses tools to take actions.
</Callout>

<DeepDive title="Prebuilt tool or a prompt to an LLM?">

Many workloads can now be done either way. A Foundry Tool such as Azure Language gives fixed, well-documented output and per-feature pricing. A prompt to a language model is more flexible and can combine several tasks in one call, but the output format needs care and you pay per token. Microsoft has announced that some Language features (key phrases, sentiment, summarisation, entity linking, CLU and custom question answering) retire on 31 March 2029 in favour of Foundry models, while language detection, PII, NER and Text Analytics for health continue.

</DeepDive>
