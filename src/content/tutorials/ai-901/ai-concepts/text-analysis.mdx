keyTerms:
  - term: Key phrase extraction
    definition: Finds the main talking points in a text, such as "delivery time" or "battery life".
  - term: Named entity recognition (NER)
    definition: Detects and categorises entities in text, such as people, locations, organisations, dates and quantities.
  - term: Entity linking
    definition: Matches an entity to a known reference (such as a Wikipedia entry) to tell apart things with the same name.
  - term: PII detection
    definition: Finds personal information such as phone numbers, email addresses and ID numbers so you can redact it.
  - term: Sentiment analysis
    definition: Labels text as positive, negative, neutral or mixed, with confidence scores per document and per sentence.
  - term: Opinion mining
    definition: Part of sentiment analysis that links each opinion to its target, such as "battery (negative)" and "screen (positive)".
  - term: Extractive summarisation
    definition: Picks the most important sentences from the original text.
  - term: Abstractive summarisation
    definition: Writes a new, shorter summary in its own words.

    a: >-
      Sentiment analysis tells you the overall feeling: "this review is mixed". Opinion mining tells you what each feeling is about: the food was great, the service was slow. So opinion mining is the more detailed, aspect-level view.

  - level: intermediate
    q: How is entity linking different from named entity recognition?
    a: >-
      NER finds an entity and gives it a category, like "Amazon" is an organisation. Entity linking goes further and decides which Amazon: the company or the river, by matching it to a known reference. NER says what kind, linking says which one.

## Start with a question

<Story question="You've got 10,000 customer reviews. How do you find out what people actually think?">

Reading them all would take weeks. You'd want to know quickly: are people happy? What are they talking about most? Which products, which cities? Are they complaining about delivery or about the product itself?

That's **text analysis**: software reading the text for you and pulling out feelings, topics, names and a short summary.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine a very fast reader with coloured highlighters.

Yellow for the important ideas. Blue for names of people and places. Red for anything private, like a phone number.

Then they put a happy or sad face next to each sentence, and write a two-line summary at the bottom.

That's what text analysis does, in seconds.

</Eli10>

## The technical explanation

Text analysis works on text you already have: reviews, emails, chat logs, tickets, transcripts. It doesn't write anything new (except abstractive summaries). Here's what each technique gives you, using one review as the example:

> "Ordered a Contoso phone from the Mumbai store on 3 March. Screen is gorgeous but the battery barely lasts a day. Call me on 98200 12345."

| Technique | What it returns | From the example |
| --- | --- | --- |
| **Language detection** | The language and a confidence score | English |
| **Key phrase extraction** | Main talking points | "Contoso phone", "Mumbai store", "battery", "screen" |
| **Named entity recognition (NER)** | Entities with categories | Contoso (Organization), Mumbai (Location), 3 March (DateTime) |
| **Entity linking** | Which real-world thing an entity is, with a reference link | Mumbai linked to the city's Wikipedia entry |
| **PII detection** | Personal data, with a redacted copy of the text | 98200 12345 (Phone number) replaced with asterisks |
| **Sentiment analysis** | Positive, negative, neutral or mixed, per document and per sentence | Document: mixed |
| **Opinion mining** | Each opinion and what it's about | screen: positive ("gorgeous"), battery: negative ("barely lasts") |
| **Summarisation** | A shorter version: **extractive** (picks sentences) or **abstractive** (rewrites) | "Customer likes the screen but the battery life is poor." |

Azure Language also includes conversational language understanding, custom question answering and Text Analytics for health, but the exam objective focuses on the techniques above.

<Callout type="exam">
Match the verb to the technique. "Main talking points" is **key phrases**. "Names of people, places, companies, dates" is **NER**. "Which one is meant" is **entity linking**. "Redact personal details" is **PII detection**. "How customers feel" is **sentiment**, and "how they feel about each feature" is **opinion mining**. "Shorter version" is **summarisation**.
</Callout>

<DeepDive title="Confidence scores and long documents">

Every Language result comes with confidence scores between 0 and 1. Use a threshold before acting automatically: for example, only route a ticket to the angry-customer queue when negative sentiment is above 0.8, and send borderline ones to a person. Requests have size limits per document and per call, so long documents are split into chunks. Summaries of long texts use the asynchronous (long-running) operations.

</DeepDive>
