## Start with a question

<Story question="Priya Sweets has one good photo of the shop, but the sky is flat grey. Can the owner fix just the sky without hiring a designer?">

Yes, and that's a different job from asking for a brand new picture.

When you ask a model to **generate**, it starts from a blank canvas and paints what your words describe. When you ask it to **edit**, it starts from your photo and has to decide what to keep. A **mask** is how you tell it: change this part, leave the rest.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine a colouring book page that you traced onto thin paper.

Where you cut a hole in the paper, you're allowed to colour. Everywhere else is covered, so the shop sign can't get a stray crayon mark.

The hole is the **mask**. The crayons are the **prompt**.

</Eli10>

## The technical explanation

In Microsoft Foundry you deploy an image model such as **gpt-image-1**. Your code calls the images API with the **deployment name** in the `model` field.

### Generate

```python
import base64, os
from openai import OpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

token = get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default")
client = OpenAI(base_url=os.environ["AZURE_OPENAI_ENDPOINT"].rstrip("/") + "/openai/v1/", api_key=token)

result = client.images.generate(
    model="gpt-image-1",          # your deployment name
    prompt="Festival banner for Priya Sweets, laddoos on a brass tray, warm light",
    size="1536x1024", quality="low", n=2,
    output_format="png", background="auto",
)
for i, item in enumerate(result.data, 1):
    open(f"banner_{i}.png", "wb").write(base64.b64decode(item.b64_json))   # base64 only
```

The controls you're expected to know (checked on Microsoft Learn, 25 November 2026):

| Setting | Values | Notes |
| --- | --- | --- |
| `size` | 1024x1024, 1024x1536, 1536x1024 | Square, portrait, landscape |
| `quality` | low, medium, high | Higher costs more and takes longer |
| `n` | 1 to 10 | Images per request |
| `output_format` | png, jpeg | No WEBP for output |
| `background` | auto, transparent | Transparent needs PNG |

### Edit with a mask

```python
result = client.images.edit(
    model="gpt-image-1",
    image=open("shop-front.png", "rb"),
    mask=open("mask.png", "rb"),             # PNG, same size, transparent = may change
    prompt="Replace the grey sky with a warm sunset. Keep everything else unchanged.",
    input_fidelity="high",                   # keep faces, logos and text close to the original
)
```

An edit works in three ways. **Mask-based** (inpainting) changes only the transparent area. **Prompt-driven** edits send the image with no mask, and the model decides what to touch, which is fine for a style change but risky for exact details. You can also send **reference images** so a new picture borrows a product or a style.

<Callout type="exam">
When a question says "only the background" or "everything else must stay the same", the answer is a **mask-based edit**. When it says "transparent background", look for **PNG**. When it says "the response had no URL", remember gpt-image returns **base64**.
</Callout>

### What guardrails do here

A guardrail on the deployment checks the **prompt**, and unsafe requests are refused before any image is made. Generated images also carry **content credentials**, so people can see they came from AI. Both belong in your design, not in an afterthought.

<DeepDive title="Why does the same prompt give a different picture every time?">

Image models sample, so a prompt is a brief, not a recipe. Put the subject, style, light and layout in the prompt, then use `n` to get several options. When one detail must be exact, such as a logo, don't ask the model to draw it from memory. Supply it as a reference image or add it afterwards in your own code, and review the result.

</DeepDive>
