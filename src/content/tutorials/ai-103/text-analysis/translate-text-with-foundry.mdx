## Start with a question

<Story question="Should your refund email say 'Contoso Pay' or 'Contoso Payer' in French?">

Contoso Pay sends refund messages to customers in Chennai, Delhi and Lyon. A translation service turns the English into Tamil, Hindi and French in under a second. The text reads well. But the product name came out translated like ordinary words, and in French it's now "Contoso Payer".

That's the whole lesson in one example. Translation is easy to get fast. Getting the **terms** and the **tone** right is the work.

</Story>

## Explain it like I'm 10

<Eli10>

**Azure Translator** is a speedy interpreter who has translated millions of sentences. Ask for three languages at once and you get three answers right away. But if your pet's name is "Biscuit", they might translate it to the word for a cookie.

A **dynamic dictionary** is a sticky note: "Biscuit stays Biscuit".

An **LLM translation flow** is a thoughtful friend. You say "be polite, use digits for numbers" and they do it. They're slower, and now and then they say it a bit differently, so you check their work.

## The technical explanation

### Azure Translator

Azure Translator in Foundry Tools translates text and documents. Key behaviors:

- **Language detection**: leave `from` out and the response includes the detected language and a score.
- **Several targets per call**: pass a list of target languages and get one result per language.
- **Billing per character**, and very low latency.
- **Same input, same output**, which helps testing.

```python
from azure.core.credentials import AzureKeyCredential
from azure.ai.translation.text import TextTranslationClient

client = TextTranslationClient(credential=AzureKeyCredential(KEY), region="eastus")
result = client.translate(body=[message], to_language=["ta", "hi", "fr"])
for t in result[0].translations:
    print(t.to, t.text)
```

A **multi-service** Foundry resource needs the **region** sent with the key (the `Ocp-Apim-Subscription-Region` header, or `region=` in the SDK). A single-service Translator resource doesn't.

### Protect your terms

| Need | Use | Training |
| --- | --- | --- |
| Keep one or two names unchanged, or fix a few translations | **Dynamic dictionary** in the request | None |
| A whole domain's vocabulary and style, medical or legal | **Custom Translator** | Sentence pairs in your language pair |

The dynamic dictionary is markup inside the text:

```text
Your <mstrans:dictionary translation="Contoso Pay">Contoso Pay</mstrans:dictionary> refund will arrive in 2 working days.
```

### LLM translation flows

Put the rules in the instructions of a model deployment:

```text
Translate the user's text into Hindi. Tone: formal.
Keep "Contoso Pay" in English. Keep numbers as digits. Return only the translation.
```

Set temperature to 0 for steadier output. The model follows tone and formatting rules that Translator can't, and it can use context you pass in. The price is cost per token, slower replies and some variation, so build an **evaluation** set of real messages and check accuracy, tone and terms before release.

| | Azure Translator | LLM flow |
| --- | --- | --- |
| Cost | Per character, low | Per token, higher |
| Speed | Very fast | Slower |
| Consistency | Same every time | Can vary |
| Tone and format | Limited | Follows instructions |
| Your terms | Dictionary, Custom Translator | Glossary in the prompt |

<Callout type="exam">
Cost, speed and steadiness at volume point to **Azure Translator**. Words like **formal tone**, **keep numbers as digits** or **follow these style rules** point to an **LLM flow**. "Keep the product name unchanged" without training is a **dynamic dictionary**. A **multi-service** resource error about the region means the **region header** is missing.
</Callout>

<DeepDive title="Custom Translator or a dynamic dictionary?">

A dynamic dictionary is a per-request override. It's perfect for a handful of names, but you must send it with every call. Custom Translator trains a model on parallel sentences, so it learns context and style across thousands of terms. Pick the dictionary for the quick fix, and Custom Translator when your content has its own language, like medical device manuals.

</DeepDive>
