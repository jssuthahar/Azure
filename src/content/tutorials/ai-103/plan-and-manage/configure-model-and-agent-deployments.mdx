## The technical explanation

### Configure a model deployment

In the **Foundry portal**: **Models + endpoints** → **Deploy model** → choose the model → **Customize**:

| Setting | What it controls |
| --- | --- |
| **Deployment name** | The name your code calls. Keep it stable and descriptive. |
| **Model version** | The exact release. Pick one when behaviour must not change. |
| **Deployment type** | Global, Data Zone, Standard, Provisioned or Batch. |
| **Tokens per minute (capacity)** | The slice of quota this deployment gets, with matching requests per minute. |
| **Version upgrade policy** | No auto upgrade, upgrade when a new default arrives, or upgrade only near retirement. |
| **Guardrail** | The set of controls applied to prompts and answers. |

```bash
az cognitiveservices account deployment create -n contoso-ai -g rg-agents \
  --deployment-name gpt-4.1-mini --model-name gpt-4.1-mini --model-version 2025-04-14 \
  --model-format OpenAI --sku-name DataZoneStandard --sku-capacity 50
```

Plan changes like code: when a model version retires, deploy the new one beside the old under a new name, test, then move traffic.

### Agents are versioned

An agent definition holds the **model deployment**, **instructions** and **tools** (file search, code interpreter, MCP, functions, knowledge bases). Each change creates a **new version** with its own ID. You choose which version serves traffic.

```python
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import PromptAgentDefinition
from azure.identity import DefaultAzureCredential

project = AIProjectClient(endpoint=PROJECT_ENDPOINT, credential=DefaultAzureCredential())
agent = project.agents.create_version(
    agent_name="support-agent",
    definition=PromptAgentDefinition(model="gpt-4.1-mini", instructions="Answer only from the policy knowledge base."),
)
print(agent.name, agent.version)
```

A safe release looks like this:

1. Create the new version in a **dev** project and run your evaluation set.
2. Promote the same definition to the next environment.
3. Watch metrics and continuous evaluation after release.
4. If scores drop, **switch back** to the previous version. Nothing was overwritten.

Applications reach all of it through the **project endpoint** (`https://<resource>.services.ai.azure.com/api/projects/<project>`) with Microsoft Entra ID, not a key.

<Callout type="exam">
"Behaviour must stay the same until we approve a change" means **pin the model version** and turn off auto upgrade. "Fast rollback of an agent" means **switch to the previous agent version**. If the question asks what an app calls, the answer is the **deployment name**. Capacity belongs to the deployment and is taken from **quota**.
</Callout>

<DeepDive title="Two deployments of the same model">

You can deploy the same model twice under different names, for example `chat-prod` with high capacity and a strict guardrail, and `chat-eval` with low capacity for test runs. Quota is shared across deployments of that model, so each one you add shrinks what's left. Delete test deployments when you're done with them.

</DeepDive>

## When to use it and when not to
