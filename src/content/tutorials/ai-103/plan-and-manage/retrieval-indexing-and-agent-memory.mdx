keyTerms:
  - term: Hybrid search
    definition: A query that runs keyword and vector search together and merges the results. Usually the best starting point for retrieval-augmented generation.
  - term: Semantic ranker
    definition: An Azure AI Search feature that re-ranks the top results by meaning and can return captions and answers.
  - term: Agentic retrieval
    definition: A retrieval mode where a model plans sub-queries from a conversation, runs them in parallel and returns grounded passages. It powers Foundry IQ knowledge bases.
  - term: Chunking
    definition: Splitting documents into pieces before indexing so each piece is small enough to retrieve and fits the model's context.
  - term: Integrated vectorization
    definition: An Azure AI Search feature that chunks content and calls an embedding model during indexing and at query time, so you don't write that code.
  - term: Agent memory
    definition: A store of information the agent learned about a user across sessions, such as preferences. Separate from knowledge, and scoped to one user.

## Start with a question

<Story question="Should the shop assistant remember your name, or read the refund rules from the wall?">

A good assistant does both, and keeps them apart. The refund rules are on the wall for everyone. Your name and your dislike of coriander are in the assistant's head, for you alone.

An AI agent needs the same split. The wall is a **knowledge base** that anyone can read and the company controls. The assistant's head is **memory**, filled in as it talks to each person. Mix them up and you get an agent that invents policy or forgets the customer.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine your class has a big library and each kid has a notebook.

The **library** has the school rules and textbooks. Everyone uses the same books. That's **knowledge**.

Your **notebook** says "Asha likes drawing" and "Asha is allergic to nuts". Only you use it. That's **memory**.

If you bring your own homework to the teacher, she reads that page right there. That's **file search**.

</Eli10>

## The technical explanation

### Retrieval methods on Azure AI Search

| Method | What it matches | Use it for |
| --- | --- | --- |
| **Keyword (full text)** | Exact words with BM25 ranking | Codes, names, part numbers |
| **Vector** | Meaning, using embeddings | Questions worded differently from the document |
| **Hybrid** | Keyword and vector, merged | The usual default for RAG |
| **Semantic ranker** | Re-orders the top results by meaning | Better order, captions, answers |
| **Agentic retrieval** | A model plans sub-queries and runs them in parallel | Multi-part questions over several sources |

A **Foundry IQ knowledge base** wraps agentic retrieval. You add **knowledge sources** (an existing search index, Blob Storage, SharePoint or the web), choose how much reasoning effort the query planner uses, and agents call the knowledge base as a tool. The agent gets grounded passages with citations.

### Plan the indexing

1. **Source**: Blob Storage, Azure SQL, Cosmos DB, SharePoint, or your own app.
2. **Ingest**: an **indexer** pulls on a schedule and tracks changes, or you **push** documents through the API.
3. **Chunk** the text so a piece is small enough to retrieve and to fit in the prompt. Overlap chunks a little so sentences aren't cut off.
4. **Vectorize** with an embedding model. **Integrated vectorization** does chunking and embedding for you during indexing and at query time.
5. **Enrich** with metadata (department, effective date, language) so you can filter, and so retrieval can skip retired content.
6. **Refresh** on a schedule, and deal with deletions, or the agent quotes yesterday's policy.

### Other ways an agent gets information

- **File search**: a vector store built from files a user uploads in a conversation (or you attach to the agent). Good for one person's contract, not for company-wide content.
- **Azure AI Search tool**: point the agent straight at an index you already built.
- **Web search** (grounding with Bing): fresh public information.
- **MCP servers, OpenAPI tools and functions**: live data and actions from other systems.

### Memory

| Memory type | Holds | Example |
| --- | --- | --- |
| **User profile** | Stable facts and preferences | "Vegetarian", "prefers email" |
| **Chat summary** | A summary of each past conversation | "Asked about a refund on order 48213" |

Scope memory to a user (for example `{user_id}`), set a **retention** time, and let the user see and delete it. Memory is in preview in Foundry as of 25 November 2026, so check Microsoft Learn before you rely on the details.

<Callout type="exam">
"Company policies with citations" is a **knowledge base on Azure AI Search**. "Exact SKU and also paraphrased questions" is **hybrid** search. "A user uploads a file in the chat" is **file search**. "Remember the user's preferences next week" is **memory** scoped to that user. Questions that mix both are testing whether you separate **shared knowledge** from **personal memory**.
</Callout>

<DeepDive title="Why pure vector search isn't enough">

Embeddings capture meaning, so "can I get my money back" finds the refund page. They're weak at exact strings. Search for "PCI-07" and a vector index may return other compliance pages that feel similar. Keyword search nails the exact code. Running both and merging is cheap insurance, and the semantic ranker then puts the best passage first.

</DeepDive>
