keyTerms:
  - term: Quota
    definition: The tokens-per-minute allowance a subscription has for a model and deployment type in a region. Deployments are carved out of it.
  - term: TPM and RPM
    definition: Tokens per minute and requests per minute. A deployment has both limits, and a request is throttled when either is exceeded.
  - term: HTTP 429
    definition: The status a Foundry endpoint returns when you exceed a rate limit. The retry-after header says how long to wait.
  - term: Exponential backoff
    definition: A retry pattern that waits longer after each failed attempt, often with random jitter, so clients don't all retry at once.
  - term: Spillover
    definition: A setting that sends overflow requests from a full provisioned deployment to a standard deployment instead of returning 429.
  - term: Prompt caching
    definition: Reusing the processed beginning of a prompt that repeats between requests, which lowers latency and the cost of the repeated input tokens.

<Story question="Why do users see errors at noon when the app was fine all morning?">

The support bot runs on a deployment with 10K tokens per minute, which is about 60 requests a minute. At 9 AM traffic is light. At noon every branch opens at once, the app sends 300 requests a minute, and 240 of them come back with **429 Too Many Requests**.

Nothing is broken. The deployment is doing what it was configured to do. The job is to decide whether to wait, to add capacity, or to send the overflow somewhere else.

## The technical explanation

### Quota and the slice per deployment

Quota is assigned **per subscription, per region, per model and deployment type**, in thousands of tokens per minute. When you create a deployment you choose its **TPM**, and that comes out of the quota. The matching **RPM** is about **6 per 1,000 TPM** for OpenAI models.

- **Portal:** Foundry portal → **Quota** (or Azure portal → Foundry resource → **Quotas**) shows used and remaining per model and region. Request more with the quota request form.
- **CLI:** `az cognitiveservices usage list --location eastus`.

Deployments share quota. A new deployment shrinks what's left, and deleting one releases it.

### When you exceed the limit

The endpoint returns **429** with a **retry-after** header. Handle it in the client:

```python
import random, time
from openai import RateLimitError

def call_with_backoff(fn, tries=6):
    for n in range(tries):
        try:
            return fn()
        except RateLimitError as e:
            wait = float(e.response.headers.get("retry-after", 2 ** n)) + random.random()
            time.sleep(wait)
    raise RuntimeError("Still throttled after retries")
```

The Azure SDKs and the OpenAI client already retry a few times. Tune them, and don't add loops that retry instantly.

### Scale options

| Option | Use it when |
| --- | --- |
| **Increase the deployment's TPM** | You have spare quota and the load is persistent |
| **Request more quota** | The subscription's quota is the limit |
| **Another deployment or region** | Quota is exhausted in one region. Load balance in the app or with a gateway such as Azure API Management |
| **Provisioned throughput (PTU)** | Steady high volume that needs predictable latency |
| **Spillover** | A provisioned deployment is full. Overflow goes to a standard deployment instead of failing |
| **Batch** | The work can wait up to 24 hours |

### Control cost

1. **Measure**: token counts in Azure Monitor per deployment, and Cost analysis for the resource group.
2. **Choose smaller models** for easy tasks (previous lesson).
3. **Trim the prompt**: shorter system messages, fewer retrieved chunks, summaries of long history.
4. **Cache**: repeated prompt prefixes can be cached by the service.
5. **Budget and alert**: set an Azure budget with alerts at, say, 80%, and a project-level token limit where available. Tags on resources show which team spent what.

<Callout type="exam">
"Requests intermittently fail with 429" means you hit **TPM or RPM**. The quick fix is **retry with backoff**. Lasting fixes are **more capacity**, **another deployment**, or **spillover** from a provisioned deployment. "Reserved capacity with predictable latency" is **PTU**. "Control monthly spend and warn at a threshold" is a **budget with alerts**.
</Callout>

<DeepDive title="Why sizing PTUs for the peak is a trap">

Provisioned throughput is billed for the capacity you reserve, used or not. If the peak is three times the base load, reserving for the peak means you pay for two thirds of it to sit idle most of the day. Size PTUs for the steady base and let spillover handle the peaks on pay-per-token capacity. Re-check the split every month, because both lines move.

</DeepDive>
