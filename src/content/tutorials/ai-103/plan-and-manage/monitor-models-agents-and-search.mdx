keyTerms:
  - term: Continuous evaluation
    definition: Scoring a sample of live agent responses with evaluators such as groundedness and safety, so quality changes show up as a metric.
  - term: Drift
    definition: A slow change in answer quality or behaviour over time, caused by new data, changed prompts, a new model version or shifting user questions.
  - term: Application Insights
    definition: The Azure Monitor feature that stores traces, requests, dependencies and logs. Foundry sends OpenTelemetry traces of model and tool calls to it.
  - term: Indexer run history
    definition: A record of each indexer execution in Azure AI Search with status, documents processed, and the items that failed and why.
  - term: Throttled queries
    definition: Search requests rejected because the service is at capacity. A sign that replicas are too few for the query load.
  - term: Grounding quality
    definition: How well an answer is supported by the retrieved content. Measured by the groundedness evaluator.

## Start with a question

<Story question="How do you know the agent got worse before the customers tell you?">

Ravi runs the support agent. In the first week, answers were crisp and cited the right policy. In the fourth week, tickets started saying "the bot told me something wrong". No alarm had fired. Latency was fine, errors were zero, and the model hadn't changed.

What had changed was the policy library. A nightly import had been failing on 120 PDFs, so the agent kept answering from last quarter's rules. You can't see that in a latency chart. You need to watch **quality** and the **data** under it.

</Story>

## The technical explanation

### Three layers to watch

| Layer | Tool | What it tells you |
| --- | --- | --- |
| **Platform** | **Azure Monitor metrics** | Requests, processed tokens, latency, errors and 429s per deployment |
| **Behaviour** | **Application Insights traces** | Every step of a run: model call, tool call, approval, retrieved passages |
| **Quality and safety** | **Continuous evaluation**, guardrail events | Groundedness, relevance and safety scores on live samples; blocked and flagged content |

Turn on **tracing** for the project by connecting an Application Insights resource, then use the **Monitoring** and **Tracing** pages in the Foundry portal. Set **alerts** on error rate, latency, token spikes, falling evaluation scores and guardrail blocks.

```bash
az monitor metrics list --resource <foundry-resource-id> --metric ProcessedPromptTokens GeneratedTokens TotalErrors --interval PT1H
```

### Model and agent drift

Quality changes for ordinary reasons: a prompt edit, a new model version, new content in the index, or different questions from users. To catch it:

1. Run **continuous evaluation** on a sample of live runs (for example 10%).
2. Track **groundedness**, **relevance** and a **safety** evaluator over time.
3. Alert when a score falls below your threshold.
4. Open traces of low-scoring runs and see what was retrieved.
5. Compare against the last known good change: version, prompt, index.

### Search health

For the Azure AI Search index behind your knowledge base:

| Signal | Where | Action |
| --- | --- | --- |
| **Indexer status and failed items** | Indexer run history | Fix unreadable files or permissions, rerun |
| **Document count vs source** | Index statistics | A gap means ingestion is missing data |
| **Search latency** | Search metrics | Add replicas or reduce query cost |
| **Throttled queries** | Search metrics | Add replicas |
| **Relevance** | Test queries with expected results, click-through | Tune analyzers, semantic ranker, chunking, or hybrid weights |

**Replicas** serve queries and give availability. **Partitions** hold more documents and speed up indexing. Turn on **diagnostic settings** to send search logs to Log Analytics so you can query them with KQL.

<Callout type="exam">
"Quality drifts after a content update" means check **continuous evaluation** and the **indexer**. "Why did the agent call that tool" means **traces**. "Search is throttled at peak" means add **replicas**, while "index is too big" means add **partitions**. Metrics tell you about **platform health**, and only evaluators tell you about **answer quality**.
</Callout>

<DeepDive title="Why evaluate a sample and not every answer">

Evaluators that use a model cost tokens and time, and they run on top of your own traffic. Scoring every live answer would add a large bill. A steady sample is enough to see a trend. When a score drops, increase the sample for a while and open the traces of the failing runs.

</DeepDive>

## When to use it and when not to

<UseWhen
  use={[
    'The agent answers from data that changes.',
    'Wrong answers have a cost: legal, financial or safety.',
    'You want evidence of quality over time, not a gut feeling.',
  ]}
  avoid={[
    'You watch only latency and error counts.',
    'You turn tracing on but never review low-scoring runs.',
