## Start with a question

<Story question="Why can a restaurant change its chef without reprinting the menu?">

The menu says "today's special", not "Ravi's special". The kitchen decides who cooks it. Customers keep ordering the same way, and the chef behind it can change.

A **deployment** works like that menu line. Your app asks for `support-chat`. Behind the name sits one **model**, one **version**, one **deployment type** and a slice of **capacity**. Move the name to a new model next month and the app doesn't change.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine a school with a big helper robot and a tiny helper robot.

The big one is great at hard homework. The tiny one is fast at easy things, like sorting your pencils.

You don't shout the robot's factory name. You shout a nickname, like "Homework Helper".

The nickname is the **deployment name**. The school can swap the robot behind the nickname, and you still just call "Homework Helper".

</Eli10>

## The technical explanation

### Pick the model for the job

| Need | Choose | Why |
| --- | --- | --- |
| Hard, multistep problems, long documents | A **large** or **reasoning** model (gpt-4.1, o4-mini) | Better answers on difficult work, higher cost and latency |
| High-volume, simple tasks such as labelling | A **small language model** (Phi-4-mini-instruct, gpt-4.1-nano) | Fast and cheap |
| Writing and fixing code | A **code-capable** model | Trained on programming tasks |
| Images or audio as input | A **multimodal** model (gpt-4.1, Phi-4-multimodal-instruct) | Accepts more than text |
| Search and similarity | An **embedding** model (text-embedding-3-small) | Returns vectors, not text |

Test two candidates on your own examples before you decide. Benchmarks don't know your tickets.

### Deploy it

In the Foundry portal go to **Build > Models + endpoints > + Deploy model**. You choose the model, a **deployment name**, the **deployment type** (Global Standard, Data Zone Standard, Standard, Provisioned or Batch), the **model version** and the **capacity** in tokens per minute. From the CLI:

```bash
az cognitiveservices account deployment create -n contoso-agents -g rg-agents \
  --deployment-name support-chat --model-name gpt-4.1-mini --model-format OpenAI \
  --sku-name GlobalStandard --sku-capacity 50
```

Deployment names must be unique in the resource. Pick names that describe the job, such as `support-chat` or `label-fast`.

### Call it from Python

Install the Foundry SDK, then connect with the **project endpoint** and a keyless credential. Both values come from the project **Overview** page, and the endpoint belongs in an environment variable, not in code.

```python
# pip install "azure-ai-projects>=2.3.0" azure-identity
import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
                          credential=DefaultAzureCredential())
openai = project.get_openai_client()          # OpenAI-compatible client

r = openai.responses.create(model="support-chat",      # the DEPLOYMENT name
                            input="In one sentence, why do apps call a deployment name?")
print(r.output_text, r.usage.input_tokens, r.usage.output_tokens)
```

The reply carries the token counts you pay for. To run this in Azure without a key, enable a **managed identity** on the host and give it the **Foundry User** role on the Foundry resource. Locally, `DefaultAzureCredential` uses your own sign-in.

<Callout type="exam">
Look for the **deployment name**. If an option passes `gpt-4.1-mini` as the model but the deployment is called `support-chat`, that call fails. "Cheapest option for simple, high-volume text labelling" is a **small language model**. "No keys in code" is a **managed identity** with **DefaultAzureCredential**.
</Callout>

<DeepDive title="Deployment types change where and how you pay">

**Global Standard** and **Data Zone Standard** bill per token and differ in where the prompt may be processed: anywhere, or inside a data zone. **Standard** stays in one region. **Provisioned** reserves capacity for steady, latency-sensitive traffic, and **Batch** suits big offline jobs. You choose the type when you deploy, so a residency rule is a deployment decision, not a code change. Model versions can be pinned or set to upgrade automatically, as of 25 November 2026.

</DeepDive>
