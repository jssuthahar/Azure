## Start with a question

<Story question="How does a teacher know a student really understands?">

A teacher doesn't judge from one confident answer in class. She sets the same test, marks each question against the textbook, and looks at which answers fall apart. A student who says something the book never said gets marked down, however fluent it sounds.

**Evaluators** do that marking for your app. They take a set of questions, the sources the app had and the answers it gave, and score each row. A low **groundedness** score is the "that's not in the book" mark.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine you're checking a friend's book report.

First you check each sentence: is it really in the book? That's **groundedness**.

Then you check: did they answer the question the teacher asked? That's **relevance**.

Then: is it neat and easy to read? That's **coherence** and **fluency**.

Last, you check there's nothing rude or scary in it. That's the **safety** check.

</Eli10>

## The technical explanation

### The evaluator families

| Family | Examples | What it tells you |
| --- | --- | --- |
| **Quality (AI-assisted)** | Groundedness, relevance, coherence, fluency | Scored 1 to 5 by a judge model, with a pass threshold you choose |
| **Quality (compare to a reference)** | Similarity, F1 score | How close the answer is to a ground truth |
| **Safety** | Violence, hate and unfairness, sexual, self-harm, indirect attack, protected material | Whether harmful content or manipulation is present |
| **Agent** | Intent resolution, tool call accuracy, task adherence | How an agent behaved (a later lesson) |

### A dataset and a run

Each row of a JSONL file holds what the evaluator needs, for example `query`, `context`, `response` and `ground_truth`.

```json
{"query": "When will my refund arrive?",
 "context": "Refunds reach the original payment method in 5 to 7 working days.",
 "response": "Refunds arrive instantly as store credit, plus a ₹500 voucher.",
 "ground_truth": "5 to 7 working days"}
```

```python
# pip install azure-ai-evaluation azure-identity
from azure.ai.evaluation import evaluate, AzureOpenAIModelConfiguration, GroundednessEvaluator, RelevanceEvaluator

judge = AzureOpenAIModelConfiguration(azure_endpoint=resource_endpoint, azure_deployment="support-chat")
result = evaluate(data="rag-eval.jsonl",
                  evaluators={"groundedness": GroundednessEvaluator(judge), "relevance": RelevanceEvaluator(judge)},
                  azure_ai_project=project_endpoint)      # the run also appears under Evaluations in the portal
print(result["metrics"])
```

The example row scores **1 out of 5** on groundedness. The context says 5 to 7 working days, and the response invents instant credit and a voucher. That's a fabrication, and the score catches it even if the average of the dataset looks fine.

### Make evaluation a habit

1. Build a small dataset from real questions, including some your documents **can't** answer.
2. Run quality and safety evaluators, and read the **lowest** rows.
3. Change one thing, such as the prompt or the retrieval.
4. Run the **same** dataset again and compare.

<Callout type="exam">
Match the symptom to the evaluator. "Claims not found in the retrieved documents" is **groundedness**. "Well written but off topic" is **relevance**. "A retrieved document contains hidden instructions" is the **indirect attack** evaluator. "Prove a prompt change didn't reduce quality" means the **same dataset and evaluators before and after**.
</Callout>

<DeepDive title="Judge models and cost">

AI-assisted evaluators call a model for every row and every evaluator, so a dataset of 500 rows with four evaluators makes about 2,000 judge calls. Use a capable deployment as judge, keep the dataset focused, and run the full set on release rather than on every small edit. Safety evaluators for harm categories run on Foundry's safety evaluation service and need a Foundry project, which is why the script passes the project endpoint.

</DeepDive>
