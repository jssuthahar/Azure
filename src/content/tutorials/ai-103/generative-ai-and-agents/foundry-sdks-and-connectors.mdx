## Start with a question

<Story question="Why does a hotel give you a key card instead of the master key?">

A key card opens your room and nothing else, and the front desk can cancel it. A master key opens everything and, if it's lost, every lock is at risk.

An **API key pasted in code** is the master key. **Microsoft Entra ID** with a **managed identity** is the key card: the app proves who it is, gets a short-lived token, and only the rooms its role allows. The **Foundry SDK** is built around that.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine your project is a clubhouse with one front door.

The SDK is the door. You tell it the clubhouse address, which is the **project endpoint**, and show your membership badge, which is your sign-in.

Inside there's a board listing the other places the club can visit: the library and the weather station. Those are **connections**.

You ask the board for "the library" by name. You never carry the library's secret password yourself.

</Eli10>

## The technical explanation

### One client, many doors

```python
# pip install "azure-ai-projects>=2.3.0" azure-identity
import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],   # .../api/projects/<project>
                          credential=DefaultAzureCredential())

openai = project.get_openai_client()                 # model calls with deployment names
for d in project.deployments.list():                 # what is deployed
    print(d.name, d.model_name)
for c in project.connections.list():                 # what the project can reach
    print(c.name, c.type, c.target)
```

| You want | Use |
| --- | --- |
| Call a model | `project.get_openai_client()` then `responses.create(model=<deployment>)` |
| List deployments | `project.deployments.list()` |
| Reach another resource | `project.connections.get("search-contoso")` |
| Create and run agents | `project.agents` and the agent client |
| Find the trace destination | The project's telemetry helpers (Application Insights connection string) |

The package also exists for JavaScript, .NET and Java, and the same operations are available over REST, as of 25 November 2026.

### Connections keep secrets out of code

Create a connection in the portal (**Settings > Connected resources**) or with the CLI. A connection has a **category** (for example Azure AI Search or Application Insights), a **target** and an **authentication type**. Prefer **Microsoft Entra ID**. Then grant the right role: the project's managed identity needs **Search Index Data Reader** on the search service, for example.

```bash
az cognitiveservices account project connection create -n contoso-agents -g rg-agents \
  --project-name order-desk --connection-name search-contoso --file search-connection.yml
```

```python
conn = project.connections.get("search-contoso")     # name in, target out
print(conn.target)                                   # https://srch-contoso-agents.search.windows.net
```

### Two endpoints, don't mix them

The **project endpoint** (`.../api/projects/<project>`) is for `AIProjectClient`. The **resource endpoint** (`https://<resource>.services.ai.azure.com/`) is what Foundry Tools and some evaluator settings expect. When a call can't find anything, check you used the right one.

<TryIt labs="agt-genai-deploy-call" text="Set the project endpoint, list the project's connections and deployments, then call a deployment by name." />

<Callout type="exam">
"Read the Azure AI Search endpoint from the project, with no hard-coded values" is a **connection**. "No key anywhere, laptop and Azure" is **DefaultAzureCredential** with a **managed identity**. A **403** after you create a connection usually means a **missing role** on the target resource.
</Callout>

<DeepDive title="Local development to production">

Locally, `DefaultAzureCredential` can use your Azure CLI or Visual Studio Code sign-in. In Azure it uses the managed identity assigned to the host. Give each environment its own project and its own endpoint in an environment variable, and keep the identity roles in your infrastructure code. The application code then stays identical from laptop to production.

</DeepDive>
