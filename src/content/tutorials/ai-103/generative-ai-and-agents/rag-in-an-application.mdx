## Start with a question

<Story question="Would you answer an exam question from memory or with the book open?">

If a friend asks "how many days do I get to return a damaged kettle?" about a shop you've never visited, you'd guess. If you open the shop's policy page first, you'd read the answer out.

A model without retrieval is the friend guessing. **RAG** opens the right page first. The app finds the best pieces of your documents, puts them in front of the model and asks it to answer from them.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine a quiz where you may look in the class notebook.

First you flip to the right page. That's **retrieval**.

Then you read the page and write your answer in your own words. That's **generation**.

If the notebook doesn't have the answer, you say "I don't know" instead of making something up.

</Eli10>

## The technical explanation

### Two phases

**Ingestion** happens before any question:

1. Read the documents and **split** them into **chunks**, for example about 500 tokens with a 50-token overlap.
2. **Embed** each chunk with an embedding model such as `text-embedding-3-small`.
3. **Upload** the text, the source name and the vector to an **Azure AI Search** index.

**Query** happens for every question:

1. Run a **hybrid** search: keywords plus a vector query for the question.
2. Take the top few chunks.
3. Put them in the prompt with the rule "answer from the sources and cite them".
4. Send it to the chat deployment and return the answer with its citations.

```python
conn = project.connections.get("search-contoso")          # target comes from the project
search = SearchClient(endpoint=conn.target, index_name="policies-index", credential=cred)
hits = search.search(search_text=question,
                     vector_queries=[VectorizableTextQuery(text=question, k_nearest_neighbors=3, fields="contentVector")],
                     top=3)
sources = "\n".join(f"[{h['source']}#{h['chunk']}] {h['content']}" for h in hits)

r = openai.responses.create(
    model="support-chat",
    instructions="Answer from the sources and cite them like [file#chunk]. "
                 "If the sources don't contain the answer, say you don't know.\n\nSources:\n" + sources,
    input=question, temperature=0.2)
```

### What makes it work

| Part | What to decide | What goes wrong |
| --- | --- | --- |
| **Chunking** | Size and overlap | Chunks that start mid-sentence lose their meaning |
| **Embedding model** | One model for index and queries | Different models give vectors you can't compare |
| **Search type** | Hybrid, often with a semantic ranker | Vector-only misses exact codes |
| **Top K** | How many chunks go in the prompt | Too few misses the answer, too many adds noise and cost |
| **Prompt** | Answer only from sources, cite, admit gaps | The model fills the gaps with a guess |

Foundry also offers a managed route: a **Foundry IQ knowledge base** on Azure AI Search plans sub-queries and returns grounded passages with citations. The same ideas apply, and you can use it instead of building the retrieval yourself.

Documents are content from outside your app. They can hide instructions that try to steer the model, which is an **indirect attack**, so scan retrieved content and evaluate for it.

<Callout type="exam">
"Answers must come from the latest company documents" is **RAG**. If the facts change weekly, an option that says "fine-tune weekly" is a distractor. "Exact part numbers and natural-language questions" points to **hybrid search**. "Retrieval returns poor matches after someone changed the embedding model" means **query and index must use the same model**.
</Callout>

<DeepDive title="Why an honest I don't know matters">

When retrieval returns nothing useful, a model that was never told to refuse will still produce a fluent answer. Put the refusal rule in the instructions, return source IDs so answers can be checked, and score **groundedness** on a test set that includes questions your documents can't answer. That test set is what catches the confident invention before a customer does.

</DeepDive>
