## Start with a question

<Story question="Why does a delivery app show you each stop and how long it took?">

When a parcel arrives late, a total time doesn't help. You want to see the steps: packed, left the depot, waited at the hub, out for delivery. The long wait at the hub tells you where to fix things.

A **trace** is that tracking page for an AI run. Each step is a **span** with its time and, for model calls, its **tokens**. You see where the time and the money went.

</Story>

<Eli10>

"Started the job. Asked the brain a question: 0.6 seconds. Phoned the parcel office: 0.9 seconds. Wrote the answer: 0.6 seconds."

Now you can see the phone call was the slowest bit.

## The technical explanation

### What a trace looks like

| Span | Duration | Tokens |
| --- | --- | --- |
| `invoke_agent order-agent` | 2140 ms | n/a (the whole run) |
| `chat support-chat` (plan) | 610 ms | 412 in |
| `execute_tool get_order_status` | 940 ms | n/a |
| `chat support-chat` (answer) | 590 ms | 96 out |

Read it top to bottom: the **agent run** contains **model calls** and **tool calls**. The slowest child is the first place to look.

### Set it up

1. **Connect Application Insights** to the project (Foundry portal, **Tracing**, or a connection).
2. **Opt in** to the GenAI instrumentation, which is a preview as of 25 November 2026.
3. **Configure Azure Monitor** with the project's connection string and **instrument** the SDK.

```python
# pip install azure-ai-projects opentelemetry-sdk azure-core-tracing-opentelemetry azure-monitor-opentelemetry
# export AZURE_EXPERIMENTAL_ENABLE_GENAI_TRACING=true                  (opt in)
# export OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true       (dev only: records prompts and answers)
from azure.ai.projects.telemetry import AIProjectInstrumentor
from azure.monitor.opentelemetry import configure_azure_monitor

configure_azure_monitor(connection_string=project.telemetry.get_application_insights_connection_string())
AIProjectInstrumentor().instrument()

openai = project.get_openai_client(agent_name="order-agent")
conversation = openai.conversations.create()
print(openai.responses.create(conversation=conversation.id, input="Where is order ORD-1042?").output_text)
```

### Token analytics and latency in KQL

Spans carry attributes such as `gen_ai.request.model`, `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`. Summarise them:

```kusto
dependencies
| where timestamp > ago(1d) and isnotempty(customDimensions["gen_ai.operation.name"])
| extend model = tostring(customDimensions["gen_ai.request.model"]),
         tokens_in = toint(customDimensions["gen_ai.usage.input_tokens"]),
         tokens_out = toint(customDimensions["gen_ai.usage.output_tokens"])
| summarize calls=count(), tokens_in=sum(tokens_in), tokens_out=sum(tokens_out),
            p50=percentile(duration, 50), p95=percentile(duration, 95) by name, model
```

Use it to answer: which model costs most, which operation is slow, and is the **p95** much worse than the **p50**? Safety signals work the same way: filter results and blocked requests show up as annotations you can count and alert on.

### Privacy

Message content recording is **off by default** and separate from tracing. Turn it on in development to debug prompts. In production keep it off unless your policy allows it, restrict who can read the Application Insights data, and set a retention period.
