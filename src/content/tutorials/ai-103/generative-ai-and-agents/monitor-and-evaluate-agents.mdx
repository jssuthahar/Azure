## Start with a question

<Story question="How does a driving examiner judge a driver?">

The examiner doesn't only check that you arrived. She watches the whole drive: did you understand where to go, did you use the mirrors and signals correctly, did you follow the rules of the test?

**Agent evaluators** are the examiner. **Intent resolution** asks if the agent understood the destination. **Tool call accuracy** watches the mirrors and signals, meaning the tools and arguments. **Task adherence** checks it followed the rules it was given.

</Story>

## Explain it like I'm 10

<Eli10>

Imagine you ask your helper robot to find your lost shoe.

Did it understand you wanted a **shoe**, not a sock? That's **intent**.

Did it look in the right places and use the right tools, instead of pretending it searched? That's **tool use**.

Did it follow your rule, "ask me first before throwing anything away"? That's **adherence**.

If it fails, you write down *why*, and fix that reason. That's **error analysis**.

</Eli10>

## The technical explanation

### What each evaluator reads

| Evaluator | Looks at | Typical failure it finds |
| --- | --- | --- |
| **Intent resolution** | The user request and the agent's response | Answered about invoices when the user wanted to cancel |
| **Tool call accuracy** | The tool calls and arguments | Called `get_order_status` with "ORD-0000", an order number nobody gave |
| **Task adherence** | The instructions and the run | Didn't ask for the order number as instructed |

The dataset holds agent messages and tool calls, for example one JSON line per run:

```json
{"query": "Where is my order?",
 "tool_calls": [{"name": "get_order_status", "arguments": {"order_id": "ORD-0000"}}],
 "response": "It arrives tomorrow."}
```

```python
from azure.ai.evaluation import evaluate, TaskAdherenceEvaluator, ToolCallAccuracyEvaluator, IntentResolutionEvaluator

result = evaluate(data="agent-runs.jsonl",
                  evaluators={"task_adherence": TaskAdherenceEvaluator(judge),
                              "tool_call_accuracy": ToolCallAccuracyEvaluator(judge),
                              "intent_resolution": IntentResolutionEvaluator(judge)},
                  azure_ai_project=project_endpoint)
```

### Error analysis

Scores tell you **which** runs failed. Error analysis tells you **why**. Read the lowest rows and group them:

| Cause seen in rows | Fix |
| --- | --- |
| Invented tool arguments | Required parameters in a strict schema, and "ask if missing" in the instructions |
| Claimed an action with no tool call | Add the tool, require approval, and check the trace for the call |
| Wrong tool chosen | Clearer tool descriptions, or split the agent |
| Ignored a rule | Move the rule higher in the instructions and add an example |

Then **rerun the same dataset** to prove it worked, and add the failing cases to your test set so they can't come back.

### In production

Pre-release tests don't catch drift. Foundry can run **continuous evaluation** on a sample of live conversations, show scores, latency, tokens and failures on a **monitoring** dashboard, and raise alerts through Azure Monitor. For one bad run, open its **trace** in Application Insights and read the spans in order, as of 25 November 2026.

<TryIt labs="agt-genai-observe" text="Score agent-runs.jsonl with the agent evaluators and read the error analysis for runs 2 and 3." />

<Callout type="exam">
Match the failure to the evaluator. **Invented or wrong tool arguments** is **tool call accuracy**. **Misread goal** is **intent resolution**. **Ignored instructions** is **task adherence**. And "detect a drop in quality on real traffic" is **continuous evaluation with alerts**, not a one-time test.
</Callout>

<DeepDive title="Why average scores mislead for agents">

Agent runs fail in clusters. If 10 percent of runs invent an order number, the average can still look healthy, yet one in ten customers gets a wrong answer. Report the pass rate per evaluator, list the failing rows, and tag each with a cause. Track the share of each cause release by release, so you can see which fix helped.

</DeepDive>
