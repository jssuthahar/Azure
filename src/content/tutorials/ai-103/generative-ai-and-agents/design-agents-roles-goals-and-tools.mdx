## Start with a question

<Story question="What do you tell a new shop assistant on day one?">

You say who they are ("you're the order desk"), what they're there for ("tell customers where their parcel is"), what they may use ("the order system") and what to do when stuck ("if there's no order number, ask for it, never guess").

That's exactly an **agent definition**. The **instructions** give the role, the goal and the rules. The **tools** are the order system. And the **conversation** is the notepad of this one customer's chat.

</Story>

## The technical explanation

### The parts of an agent

| Part | What it does | Example |
| --- | --- | --- |
| **Model** | The deployment that does the thinking | `support-chat` |
| **Instructions** | Role, goal, rules, tone, escalation | "Always call get_order_status for order questions. If the order number is missing, ask." |
| **Tools** | What it can use | A function, file search, Azure AI Search |
| **Conversation** | Messages of one chat | Created once, referenced by ID on every request |
| **Version** | A numbered snapshot of the definition | `order-agent` v3 |

### Write a good tool schema

The model decides to call a tool from its **name and description**, and fills the arguments from the **schema**. Be exact:

```python
get_order_status = FunctionTool(
    name="get_order_status",
    description="Look up the delivery status of one Contoso order. Call it whenever the customer gives an order number.",
    parameters={"type": "object",
                "properties": {"order_id": {"type": "string", "description": "Order number, for example ORD-1042"}},
                "required": ["order_id"], "additionalProperties": False},
    strict=True)

agent = project.agents.create_version(agent_name="order-agent", definition=PromptAgentDefinition(
    model="support-chat",
    instructions=("Role: Contoso Retail's order assistant. Goal: tell customers where their order is. "
                  "Always call get_order_status for order questions and ask for the order number if it's missing. "
                  "Never promise a date the tool didn't return."),
    tools=[get_order_status]))
```

Mark every parameter the tool really needs as **required**, set `additionalProperties` to false and turn **strict** on. Then a missing order number can't become a made-up one: the instructions tell the agent to ask, and the schema leaves no room to guess.

### Track the conversation

Create a **conversation** for each chat and pass its ID with every request, so the service keeps the history for you. The other option is to resend the messages yourself on each call, which you control but must store and trim. Long-term facts about a user are not part of the conversation. That's **memory**, covered in the next lesson.

```python
openai = project.get_openai_client(agent_name="order-agent")
conversation = openai.conversations.create()
r = openai.responses.create(conversation=conversation.id, input="Where is my order?")
```

### Versions and agent kinds

Each change to instructions, tools or model makes a new **version**, so you can compare versions on the same evaluation set and roll back. This lesson builds a **prompt agent**: a model with instructions and tools. Foundry also has **workflow** agents for multi-step flows and **hosted** agents that run your own code, both in preview as of 25 November 2026.

<Callout type="exam">
When an agent **invents** a value, the fix is a **required parameter in a strict schema** plus an instruction to ask. "Behave as a polite order assistant and refuse unrelated requests" belongs in **instructions**. "Keep the earlier messages of this chat" is a **conversation**, and "roll back after a bad change" is a **version**.
</Callout>

<DeepDive title="Instructions that work">

Short, specific instructions beat long ones. Start with the role and the goal, then list rules as plain sentences, then say what to do on failure: no result, missing input or an unrelated request. Add one example if the format matters. Test with awkward inputs on purpose, such as no order number, two order numbers, or a request the agent shouldn't handle, and keep those cases in your evaluation set.

</DeepDive>
