## Start with a question

<Story question="Your support chats are full of phone numbers and card digits, and a legacy product code needs a lookup. How do you clean and enrich the text before it's searchable?">

Think of a mailroom. Before a letter reaches a desk, someone slits it open, a second person blacks out the account numbers, a third stamps the department from a lookup table, and then it goes into the pigeonholes.

A **skillset** is that mailroom line. Each worker is a **skill**. Some are standard (read the photo, black out personal data). Some are yours (stamp the department from our own table). The pigeonhole is the index, but a stamp that never gets written down on the letter never reaches it.

</Story>

## The technical explanation

A skillset sits between document cracking and the index. For each document the indexer builds an **enrichment tree**, a tree of nodes that starts with `/document/content` (text) and `/document/normalized_images/*` (images). Every skill reads some nodes and **adds new nodes**.

### Anatomy of a skill

| Part | What it means |
| --- | --- |
| `@odata.type` | Which skill it is |
| `context` | How often it runs: once per `/document`, or once for each item such as `/document/normalized_images/*` |
| `inputs` | Which nodes it reads (`source`) |
| `outputs` | The nodes it writes (`targetName`) |

Execution order follows the data: a skill that reads another skill's output waits for it.

### Built-in skills by job

| Job | Skills |
| --- | --- |
| Read images | **OCR**, Image Analysis |
| Shape text | **Text Split** (chunks), Text Merge (put OCR text back with the body) |
| Understand text | Key Phrase Extraction, Entity Recognition, Sentiment, Language Detection, Text Translation, Custom Entity Lookup |
| Protect data | **PII Detection** (finds personal data, returns a masked copy) |
| Vectors | **Azure OpenAI Embedding** (and Azure Vision multimodal embeddings, in preview) |
| Layout and chunking | **Content Understanding** skill (tables, sections, figures, semantic chunks) |
| Generative | GenAI Prompt (a Foundry chat model in the pipeline) |

Some skills run on Microsoft-hosted models and need an attached Foundry resource for billing. Others, such as the embedding and Content Understanding skills, call a resource and deployment you own.

### Custom skills: the Web API skill

When no built-in skill does what you need, point a **Web API skill** at your own HTTPS endpoint. The service sends a batch of records, and your code returns one result per `recordId`:

```json
{ "@odata.type": "#Microsoft.Skills.Custom.WebApiSkill",
  "uri": "https://func-skills.azurewebsites.net/api/lookup",
  "httpMethod": "POST", "batchSize": 10, "timeout": "PT30S",
  "context": "/document",
  "inputs":  [ { "name": "text", "source": "/document/content" } ],
  "outputs": [ { "name": "productCode", "targetName": "productCode" } ] }
```

```json
{ "values": [ { "recordId": "r1", "data": { "productCode": "WM-2210" }, "errors": null, "warnings": null } ] }
```

Return **every** `recordId` you received, report problems in `errors` or `warnings` per record, and secure the endpoint (a function key, or Microsoft Entra ID authentication on the skill). Azure Functions is the common home for it.

### Getting enrichments into the index

A skill output is only a node in a temporary tree. To keep it, you map it:

- **Output field mappings** on the indexer copy one node to one index field, such as `/document/maskedText` to `masked_text`.
- **Index projections** on the skillset create **one search document per item** (each chunk) and set the parent key. Use these with Text Split.

If personal data must not be searchable, split and embed the **masked** text, and don't map the original `content` to a searchable field.

```json
"outputFieldMappings": [
  { "sourceFieldName": "/document/maskedText", "targetFieldName": "masked_text" }
]
```

### Cost and reruns

Skills that call models cost money for every document, every run. Turn on an **enrichment cache** so a rerun reuses outputs whose inputs didn't change. When you change a skillset, **reset** the indexer, because it won't revisit files it already processed.

<Callout type="exam">
"A skill ran but the data isn't in the index" means a missing **output field mapping** (or **index projection**). "Custom logic" means a **Web API** skill, usually an **Azure Function**, and the response must repeat every **recordId**. "Keep tables and headings together in chunks" points to the **Content Understanding** skill, and "mask personal data" to **PII Detection**.
</Callout>

<DeepDive title="Knowledge store and debug sessions">

A skillset can also write enrichments outside the index with a **knowledge store**: tables, JSON objects or image files in Azure Storage. It's useful for analytics, or to inspect what a skill produced without paying to query the index.

When a skill's output looks wrong, use a **debug session** in the portal. It runs one document through the skillset and shows the enrichment tree, node by node, so you can see where a value went missing and test a changed skill before you rerun the whole indexer.

Sensitive data adds one more habit: apply PII detection before the embedding skill, so the vector is made from the masked text too.

</DeepDive>
