## Start with a question

<Story question="Your HR agent confidently invents a parental leave rule. How do you make it answer from the real policies, and say so when it can't?">

Think of a new employee at a help desk. If you give them no manual, they guess. If you give them a manual and tell them "answer from the manual and point to the page", they stop guessing. If the answer isn't in the manual, they say "let me check".

A **knowledge base** is the manual, a **knowledge source** is one book in it, and the **MCP tool** is the agent's way to open it. The **managed identity** is the staff badge that lets the agent into the library, and the instructions are the rule: cite the page, or say you don't know.

</Story>

## The technical explanation

You've built an index. Now the agent has to use it, safely and with citations.

### The pieces

| Piece | Job |
| --- | --- |
| **Knowledge source** | Points at content: a search index on your service, Blob Storage, SharePoint, OneLake, or the web. |
| **Knowledge base** | Lists knowledge sources, sets the **retrieval reasoning effort** and the **output mode**, and exposes retrieve and MCP endpoints. |
| **Agentic retrieval** | Plans subqueries, runs them in parallel (keyword, vector or hybrid), reranks each with the semantic ranker and merges the result. |
| **Agent** | A Foundry agent with the knowledge base as a tool and instructions about how to use it. |

Indexed sources need a **semantic configuration** on the index, because every subquery is reranked.

### Retrieval reasoning effort

| Effort | What happens | Needs a model? |
| --- | --- | --- |
| **minimal** | One query goes to the candidate sources as it is. | No (unless you want answer synthesis) |
| **low** | A model plans subqueries and picks sources. | Yes |
| **medium** | More planning and iteration than low. | Yes |

Set it explicitly instead of assuming a default. A question such as "Can I expense a taxi from the airport, and how long do I have to claim it?" is really two questions. At minimal effort it's one blended query; at low effort it becomes two focused ones that run in parallel.

The **output mode** is either **extractive data** (raw passages with references, which your agent or app reasons over) or **answer synthesis** (the knowledge base writes a cited answer, which needs a model).

### Creating them (REST, GA contract 2026-10-01)

```http
PUT /knowledgesources/ks-policies?api-version=2026-10-01
{ "name": "ks-policies", "kind": "searchIndex",
  "searchIndexParameters": { "searchIndexName": "policies-idx" } }

PUT /knowledgebases/kb-policies?api-version=2026-10-01
{ "name": "kb-policies",
  "knowledgeSources": [ { "name": "ks-policies" } ],
  "retrievalReasoningEffort": { "kind": "low" },
  "outputMode": "extractiveData",
  "models": [ { "kind": "azureOpenAI", "azureOpenAIParameters": {
      "resourceUri": "https://ai-agt-kb01.openai.azure.com",
      "deploymentId": "gpt-4.1-mini", "modelName": "gpt-4.1-mini" } } ] }
```

Some agentic retrieval features are still in preview, and which ones you get depends on the Search REST API version you call. As of 25 November 2026, `2026-10-01` is the GA contract for minimal, low and medium effort, citations and answer synthesis, and a preview version adds newer items. Check the current migration page when you build.

### Connecting the agent

1. **Create a project connection** to the knowledge base's MCP endpoint (`.../knowledgebases/<name>/mcp`), using the **project managed identity** and the search audience.
2. **Add the tool** to the agent with `allowed_tools` limited to the retrieve tool, and decide on `require_approval` (reading a policy index is low risk).
3. **Grant the role.** On the search service, assign the project's managed identity **Search Index Data Reader**. Read-only is all an agent needs.
4. **Write the instructions.** Say to answer from the retrieved passages, cite the sources, and reply that it doesn't know when nothing relevant comes back.

```python
tool = MCPTool(server_label="policies", server_url=mcp_endpoint,
               require_approval="never", allowed_tools=["knowledge_base_retrieve"],
               project_connection_id="kb-policies-mcp")
agent = project.agents.create_version(agent_name="policy-agent",
    definition=PromptAgentDefinition(model="gpt-4.1-mini", tools=[tool],
        instructions="Use the knowledge base tool. If it has no answer, say you don't know. Cite sources."))
```

Without the role you get a **403** on the first tool call, which is the classic mistake. Network settings matter too: a private connection between the agent and the search service doesn't automatically protect the search service's own connections to its data sources and models.

### Workflows and apps

Anything that can make an HTTPS call can use the same knowledge base: a Logic Apps or Power Automate step, an Azure Function, or a Microsoft Agent Framework app. They call the **retrieve** endpoint (or SDK) with the conversation, then pass the returned passages to a model or use them directly. One knowledge base can serve many agents.

### Other ways to ground an agent

| Option | Use it when |
| --- | --- |
| **Knowledge base (Foundry IQ)** | Curated company content shared by many agents, with planning and citations |
| **Azure AI Search tool** on an index | One index and a simple, direct query |
| **File search** | Files a user uploads in a conversation |
| **Function tool** | Live data from a system of record |

<DeepDive title="Permissions and cost">

Sources such as SharePoint and some others can carry access control lists, and the knowledge base can run queries under the caller's Microsoft Entra identity so users only get content they're allowed to see. For your own indexes, store group IDs on each chunk and apply a filter that matches the signed-in user.

Agentic retrieval is billed in more than one place: the semantic ranker reranks up to 50 chunks per subquery, and low and medium effort add model tokens for planning and, if you use it, answer synthesis. Lower the effort, reduce the number of sources, or answer simple questions with minimal effort to keep cost down. Review the activity log the retrieve call can return, which shows each subquery and how many results it produced.

</DeepDive>
