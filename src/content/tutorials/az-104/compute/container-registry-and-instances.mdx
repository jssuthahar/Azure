## Start with a question

<Story question="Why pay for a server all day for a job that runs for five minutes?">

Think of a bakery that bakes a special cake once a night. It doesn't buy a second oven and leave it on all day. It keeps the recipe in a locked cupboard, rents an oven for five minutes each night, and hands the oven back when the cake is done.

In Azure the locked cupboard is **Azure Container Registry**: your private images, safe and versioned. The rented oven is **Azure Container Instances**: it runs one image as a **container group**, with the CPU and memory you ask for, and stops when the job is done if you tell it to.

</Story>

## Explain it like I'm 10

<Eli10>

A container image is a lunchbox with everything an app needs packed inside.

The **registry** is your locker at school. Only people with your key can open it.

**Container Instances** is a table where you open one lunchbox and eat. You pick the table size before you sit down, and you can't make it bigger halfway through.

The **restart policy** is your rule for what happens when you finish: sit down again (Always), only if you dropped your food (OnFailure), or go home (Never).

</Eli10>

## The technical explanation

### Azure Container Registry: create and manage it

A registry name is 5 to 50 letters and numbers, no hyphens, and it becomes the **login server**: `acrcontoso.azurecr.io`. Images live in **repositories** and are named by **tag** (`invoice-job:v1`) or by **digest** (`sha256:…`).

| Tier | Included storage | Good for | Premium-only extras |
| --- | --- | --- | --- |
| **Basic** | 10 GiB | Learning and small teams | |
| **Standard** | 100 GiB | Most production teams | |
| **Premium** | 500 GiB | Large, global or locked-down setups | Geo-replication, private endpoints, the highest throughput |

You can **move between tiers in place**. Upgrading to Premium doesn't move or rebuild images, and there's no downtime.

**Portal:** search **Container registries**, select **+ Create**, fill in **Registry name**, **Location** and **Pricing plan**, then **Review + create**. Later, **Settings → Properties** changes the plan and **Services → Geo-replications** adds regions.

```bash
az acr create -g rg-admin-apps -n acrcontosoadm01 --sku Standard
az acr import -n acrcontosoadm01 --source mcr.microsoft.com/azuredocs/aci-helloworld:latest --image aci-helloworld:v1
az acr update -n acrcontosoadm01 --sku Premium
az acr replication create -r acrcontosoadm01 -l westeurope
```

```powershell
New-AzContainerRegistry -ResourceGroupName rg-admin-apps -Name acrcontosoadm01 -Sku Standard -Location eastus
Update-AzContainerRegistry -ResourceGroupName rg-admin-apps -Name acrcontosoadm01 -Sku Premium
```

**Who can pull?** Give the app's managed identity (or a service principal) the **AcrPull** role on the registry. **AcrPush** adds push. The **admin user** is one shared username and password for the whole registry; it's off by default, and you should keep it that way outside quick tests.

<Callout type="tip">
`az acr import` copies a public image (say from Docker Hub or mcr.microsoft.com) straight into your registry without Docker on your machine. Teams do this so their builds don't depend on a public registry's rate limits.
</Callout>

### Azure Container Instances: provision a container

ACI deploys a **container group**: one or more containers scheduled on the same host, sharing a lifecycle, an IP address and any mounted volumes (such as an Azure Files share). Linux groups can hold several containers; Windows groups are more limited.

**Portal:** search **Container instances**, select **+ Create**. On **Basics**: container name, region, **Image source** (Quickstart images, Azure Container Registry, Other registry), image and tag, **OS type** and **Size** (vCPU and memory). **Networking** sets Public or Private, a **DNS name label** and ports. **Advanced** holds the **restart policy**, environment variables and command override.

```bash
az container create -g rg-admin-apps -n aci-invoice-job \
  --image mcr.microsoft.com/azuredocs/aci-helloworld \
  --cpu 1 --memory 1.5 --restart-policy OnFailure --os-type Linux
```

For an image in your own registry, add `--registry-login-server`, `--registry-username` and `--registry-password`, or `--acr-identity` with a managed identity that has AcrPull.

### Sizing and scaling ACI

| Setting | What to know |
| --- | --- |
| **CPU and memory** | Requested per container when you create the group. Most regions give a standard Linux group up to 4 vCPU and 16 GB. |
| **Changing size** | Not in place. CPU, memory, OS type and restart policy need a **delete and recreate**. |
| **Scaling** | None built in. More load means more groups that you create, or a move to Container Apps or AKS. |
| **Billing** | Per second of vCPU and memory while the group runs. |

| Restart policy | Behaviour | Use it for |
| --- | --- | --- |
| **Always** (default) | Restarts the container whenever it stops | Long-running services |
| **OnFailure** | Restarts only on a non-zero exit code | Batch jobs that should retry on error |
| **Never** | Runs once and stays stopped | One-off tasks you want to inspect after |

<TryIt labs="adm-containers" text="Create a registry, get refused a geo-replica on Standard, upgrade to Premium, then run a job in Container Instances with OnFailure." />

<Callout type="exam">
Watch the wording. "Copy images to a second region" or "private endpoint for the registry" means **Premium**. "Run a task once and only rerun it if it fails" means **OnFailure**; "never restart" means **Never**. "Increase the memory of an existing container group" means **delete and redeploy**, because there's no resize. And any answer that says Container Instances **autoscales** is wrong.
</Callout>

<DeepDive title="Why not just use the admin user?">

The admin user is one credential shared by everyone and everything, with push and pull rights. You can't tell who used it, and rotating it breaks every app at once. With Microsoft Entra ID, each app's managed identity gets exactly AcrPull on one registry, you see it in the activity log, and nothing has a password to leak. Some older tools still need the admin user; if you must use it, rotate the password and turn it off again when you're done.

</DeepDive>
