keyTerms:
  - term: Managed disk
    definition: A block storage volume for a VM that Azure stores, replicates and encrypts for you, such as an OS or data disk.
  - term: Temporary disk
    definition: Local storage on the VM's host (D on Windows, often /mnt on Linux). Data on it is lost after deallocation, redeployment or host maintenance.
  - term: Host caching
    definition: A per-disk cache on the host. None, ReadOnly or ReadWrite. Not available for Ultra Disk or Premium SSD v2.
  - term: Server-side encryption (SSE)
    definition: Encryption at rest of managed disks in Azure Storage, on by default, with platform-managed or customer-managed keys.
  - term: Encryption at host
    definition: Encryption of the temp disk and OS/data disk caches on the VM host, so data is encrypted from the host to Storage.
  - term: Disk encryption set
    definition: The resource that links managed disks to a customer-managed key in Azure Key Vault.
  - term: Azure Disk Encryption (ADE)
    definition: Older guest-OS encryption with BitLocker or DM-Crypt and Key Vault. It can't be combined with encryption at host on the same VM.

Encryption at host encrypts those on the host itself and sends data to Storage already encrypted, which is what auditors usually mean by end-to-end. ## Start with a question

<Story question="If your house is locked, is the post on your doormat safe?">

Your filing cabinet is locked. Great. But the letter you're working on sits on the desk by the window, and the post waits on the doormat. Locking the cabinet didn't protect those.

A VM's **managed disks** are the locked cabinet: encrypted in Azure Storage by default. The **temp disk** and the **disk cache** are the desk and the doormat, on the physical host. **Encryption at host** locks those too.

</Story>

## Explain it like I'm 10

<Eli10>

Your school bag has a few parts.

The big pocket with your books is the **OS disk**. A second bag for sports kit is a **data disk**. You can pick up another one any time.

The scrap paper on your desk is the **temp disk**. When you change classrooms, it gets thrown away.

**Encryption at host** is writing in secret code even on the scrap paper, so nobody passing by can read it.

## The technical explanation

### The three kinds of disk

| Disk | Where it lives | Survives deallocation? | Use it for |
| --- | --- | --- | --- |
| OS disk | Managed disk in Azure Storage | Yes | The operating system |
| Data disk | Managed disk in Azure Storage | Yes | Databases, app files, logs |
| Temporary disk | Local storage on the host | **No** | Page file, swap, scratch data |

Managed disk types, fastest first: **Ultra Disk** and **Premium SSD v2** (performance set separately from size, no host caching), **Premium SSD** (production), **Standard SSD** (light production, web servers) and **Standard HDD** (backups, dev/test). Premium and Standard SSD also come in **ZRS** versions that survive a zone failure.

### Add, change and grow disks

Portal: **VM › Settings › Disks › + Create and attach a new disk** (or **Attach existing disks**), set the LUN, type, size and **Host caching**, then **Save**.

```bash
az vm disk attach -g rg-contoso-prod --vm-name vm-app-01 -n vm-app-01-data1 \
  --new --size-gb 128 --sku Premium_LRS --caching ReadOnly
az vm disk detach -g rg-contoso-prod --vm-name vm-app-01 -n vm-app-01-data1
az disk update -g rg-contoso-prod -n vm-app-01-data1 --sku StandardSSD_LRS --size-gb 256
```

```powershell
$vm = Get-AzVM -ResourceGroupName rg-contoso-prod -Name vm-app-01
$cfg = New-AzDiskConfig -Location eastus -CreateOption Empty -DiskSizeGB 128 -SkuName Premium_LRS
$disk = New-AzDisk -ResourceGroupName rg-contoso-prod -DiskName vm-app-01-data1 -Disk $cfg
Add-AzVMDataDisk -VM $vm -Name vm-app-01-data1 -ManagedDiskId $disk.Id -Lun 0 -CreateOption Attach -Caching ReadOnly
Update-AzVM -VM $vm -ResourceGroupName rg-contoso-prod
```

| Change | VM running? |
| --- | --- |
| Attach or detach a data disk | Yes (unmount it in the OS before detaching) |
| Grow a data disk | Yes, in most cases, then extend the partition |
| Grow the OS disk | Deallocate first |
| Change disk type (Premium ↔ Standard) | Deallocate the VM or detach the disk |
| Shrink a disk | Not possible |
| Max data disks | Set by the VM size |

**Host caching**: ReadOnly suits read-heavy data such as database data files, None suits write-heavy logs, and ReadWrite is only safe when the app writes through properly. The OS disk defaults to ReadWrite.

### Encryption options

| Option | Covers | Keys | Notes |
| --- | --- | --- | --- |
| Server-side encryption (SSE) | Managed disks at rest in Storage | Platform-managed by default, or customer-managed via a **disk encryption set** | Always on |
| **Encryption at host** | Temp disk, OS/data disk **caches**, data in flow to Storage | Same keys as SSE | Runs on the host, no VM CPU cost |
| Azure Disk Encryption (ADE) | Volumes inside the guest OS | Key Vault | BitLocker/DM-Crypt; retires on 15 September 2028, so use encryption at host for new VMs |
| Confidential disk encryption | OS disk bound to the VM's TPM | Platform or customer key | Confidential VM sizes only |

### Turn on encryption at host

```bash
# once per subscription
az feature register --name EncryptionAtHost --namespace Microsoft.Compute
az feature show --name EncryptionAtHost --namespace Microsoft.Compute --query properties.state
az provider register --namespace Microsoft.Compute

# new VM
az vm create ... --encryption-at-host true

# existing VM: must be deallocated
az vm deallocate -g rg-contoso-prod -n vm-app-01
az vm update -g rg-contoso-prod -n vm-app-01 --set securityProfile.encryptionAtHost=true
az vm start -g rg-contoso-prod -n vm-app-01
```

In the portal: **Disks** tab of the create wizard › **Encryption at host**, or on an existing deallocated VM **Disks › Additional settings › Encryption at host: Yes**. The VM size has to support it, and the VM can't also use ADE.

<Callout type="exam">
"Encrypt the **temp disk** and **caches**" or "end-to-end encryption without using VM CPU" is **encryption at host**. "Use our own key in Key Vault for disks at rest" is a **customer-managed key** through a **disk encryption set**. If enabling encryption at host fails, the answers are: register **Microsoft.Compute/EncryptionAtHost**, **deallocate** the VM, and don't combine it with **Azure Disk Encryption**. "Data disappeared after a restart on a new host" means it was on the **temporary disk**.
</Callout>

<DeepDive title="Picking disk performance">

On Premium SSD, performance grows with size tiers (P10 = 128 GiB with about 500 IOPS, P30 = 1 TiB with about 5,000), so people sometimes buy a bigger disk just for IOPS. Premium SSD v2 and Ultra Disk let you set capacity, IOPS and throughput separately, and change performance without a restart. Remember the VM size caps total disk IOPS and throughput too: four fast disks on a small VM are limited by the VM, not the disks. Snapshots (`az snapshot create`) give point-in-time copies of a disk for backups or cloning.

</DeepDive>
