## Start with a question

<Story question="What if your laptop could get more memory just by restarting it?">

Your laptop's memory is soldered in. To get more, you buy a new laptop and copy everything across.

An Azure VM doesn't work like that. Its **size** is a setting. Pick a bigger one, the VM **restarts**, and it comes back with more CPU and memory, same disks, same name. The catch: sometimes the size you want isn't on the hardware your VM sits on, and then you have to **deallocate** it first so Azure can start it somewhere else.

</Story>

## Explain it like I'm 10

<Eli10>

Think of a hotel.

Your VM is a guest. The **size** is the room: single, double or suite.

Moving to a bigger room on the same floor is quick. You just pop out and back in. That's a **resize with a restart**.

If the suite is on another floor, you have to check out first and check in again. That's **deallocate, then resize**.

Your suitcase (the disks) comes with you either way.

</Eli10>

## The technical explanation

### Creating a VM

**Virtual machines › + Create › Azure virtual machine** opens a wizard with tabs **Basics, Disks, Networking, Management, Monitoring, Advanced, Tags, Review + create**. The **Basics** tab is where most exam questions live:

| Field | What to choose |
| --- | --- |
| Subscription, Resource group | Where it's billed and managed |
| Virtual machine name, Region | Name (15 characters max for Windows), region close to users |
| Availability options | No infrastructure redundancy, Availability zone, Virtual machine scale set or Availability set |
| Security type | Trusted launch (default), Standard or Confidential |
| Image | Ubuntu, Windows Server, RHEL and so on |
| Size | Family, vCPUs, memory and price |
| Administrator account | SSH public key or password |
| Inbound port rules | None, or selected ports such as SSH (22), RDP (3389), HTTP (80) |

Creating the VM also creates an OS disk, a network interface, usually a public IP and an NSG, and a virtual network if you don't pick one.

```bash
az vm create -g rg-contoso-prod -n vm-app-01 --image Ubuntu2404 \
  --size Standard_D2s_v5 --zone 1 --admin-username azureuser --generate-ssh-keys
```

```powershell
New-AzVM -ResourceGroupName rg-contoso-prod -Name vm-app-01 -Location eastus `
  -Image Ubuntu2204 -Size Standard_D2s_v5 -Zone 1 -Credential (Get-Credential)
```

### Reading a size name

`Standard_D4ds_v5` breaks down as family **D**, **4** vCPUs, **d** (local temp disk), **s** (Premium SSD capable), version **v5**. Common families:

| Family | Built for | Example |
| --- | --- | --- |
| B | Burstable, mostly idle with short spikes | Standard_B2s |
| D | General purpose | Standard_D4s_v5 |
| E | Memory optimised (databases, caches) | Standard_E8s_v5 |
| F | Compute optimised (batch, gaming servers) | Standard_F8s_v2 |
| L | Storage optimised (high local disk throughput) | Standard_L8s_v3 |
| N | GPU | Standard_NC6s_v3 |

The size also caps the number of **data disks** and the disk IOPS a VM can push, so a bigger disk on a small VM can still be slow.

### Resizing

Portal: **VM › Availability + scale › Size**, pick a size, **Resize**. CLI and PowerShell:

```bash
az vm list-vm-resize-options -g rg-contoso-prod -n vm-app-01 -o table
az vm resize -g rg-contoso-prod -n vm-app-01 --size Standard_D4s_v5
```

```powershell
$vm = Get-AzVM -ResourceGroupName rg-contoso-prod -Name vm-app-01
$vm.HardwareProfile.VmSize = 'Standard_D4s_v5'
Update-AzVM -VM $vm -ResourceGroupName rg-contoso-prod
```

The rules to remember:

1. A resize on a running VM **restarts** it.
2. If the size isn't offered on the VM's current **hardware cluster**, it's greyed out (or the command fails). **Deallocate** the VM and every size in the region becomes available.
3. In an **availability set**, a size that isn't on the cluster means deallocating **all** VMs in the set before resizing any of them.
4. The new size must support what the VM uses: enough data disk slots, Premium storage if its disks are Premium, and the same VM generation.

<Callout type="exam">
"The size you need isn't listed" or "is greyed out" means the VM's cluster doesn't have it: **stop (deallocate)** the VM, then resize. A resize always means a **restart**, so it isn't zero downtime. Match workloads to families: **E** for memory, **F** for compute, **N** for GPU, **B** for bursty and cheap. And "stop paying for compute" is **deallocate**, not shutting down from inside the guest.
</Callout>

<DeepDive title="Sizes, quotas and policy">

Every subscription has **vCPU quotas** per region and per family. A resize or a create that would go over fails with a quota error; request more under **Subscriptions › Usage + quotas**. Azure Policy's **Allowed virtual machine size SKUs** definition can deny sizes your company doesn't want, and it applies to resizes too. Azure Advisor flags VMs with low CPU use and suggests a smaller size, which is often the easiest saving on an AZ-104 cost question.

</DeepDive>
