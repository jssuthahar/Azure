## The technical explanation

### Public zones

Create a zone named after the domain (`contoso-shop.com`). Azure assigns **four name servers** (`ns1-0x.azure-dns.com`, `.net`, `.org`, `.info`). To make the internet use them, set them as the **NS records** at your **registrar**, or as an NS record set in the **parent zone** for a child zone (delegating `shop.contoso.com` from `contoso.com`). Azure DNS **hosts** zones; it doesn't **register** domains (App Service Domains can).

Zones are Azure resources, so you get **RBAC** (DNS Zone Contributor), **resource locks** and activity logs. Price feel: about $0.50 per zone a month plus $0.40 per million queries (illustrative).

### Records

| Type | Example | Notes |
| --- | --- | --- |
| A / AAAA | www → 20.85.4.10 | IPv4 / IPv6 address |
| CNAME | shop → contoso.azurewebsites.net | Not at the apex, and alone on its name |
| MX | @ → mail.contoso.com (priority 10) | Mail |
| TXT | @ → "v=spf1 …" | Verification, SPF |
| SRV, CAA, PTR, NS | | Services, certificate authorities, reverse lookup, delegation |
| SOA, NS at @ | | Created for you |

Each record set has a **TTL** (3600 seconds by default) that controls how long resolvers cache it.

### Alias records

An **alias record set** points at an **Azure resource** instead of a fixed value: a **public IP**, **Traffic Manager** profile, **Azure Front Door** or **CDN** endpoint, or another record set in the same zone. If the resource's IP changes, the record follows, and if the resource is deleted the record returns nothing instead of a stale address. Alias A records work at the **apex**, which is how you point `contoso.com` itself at a load balancer.

### Private zones

A **private DNS zone** (for example `contoso.internal` or `privatelink.blob.core.windows.net`) resolves only from **virtual networks linked** to it. VMs using Azure-provided DNS ask **168.63.129.16**, which answers from every linked zone.

- **Virtual network link**: required for every VNet that should resolve the zone. **Peering doesn't share private zones.**
- **Auto-registration** on a link: VMs in that VNet get A records created, updated and removed automatically. A VNet can have **one** registration zone, but resolution links to many zones.
- On-premises clients need **Azure DNS Private Resolver** (or a DNS forwarder VM) to query private zones.

### Portal and CLI

Portal: **DNS zones → + Create**, copy the name servers from **Overview**, then **+ Record set** (set **Alias record set: Yes** for an alias). **Private DNS zones → + Create → Virtual Network Links → + Add** (tick **Enable auto registration** if wanted).

```bash
az network dns zone create -g rg-net-lb -n contoso-shop.com
az network dns zone show -g rg-net-lb -n contoso-shop.com --query nameServers
az network dns record-set a add-record -g rg-net-lb -z contoso-shop.com -n api --ipv4-address 20.85.4.11
az network dns record-set cname set-record -g rg-net-lb -z contoso-shop.com -n shop --cname contoso.azurewebsites.net
az network dns record-set a create -g rg-net-lb -z contoso-shop.com -n www --target-resource <public-ip-id>

az network private-dns zone create -g rg-net-lb -n contoso.internal
az network private-dns link vnet create -g rg-net-lb -n link-vnet-web -z contoso.internal \
  -v vnet-web --registration-enabled true
az network private-dns record-set a add-record -g rg-net-lb -z contoso.internal -n db --ipv4-address 10.40.2.10
```

PowerShell: `New-AzDnsZone`, `New-AzDnsRecordSet`, `New-AzPrivateDnsZone`, `New-AzPrivateDnsVirtualNetworkLink`.

<Callout type="exam">
"The zone is created but the domain doesn't resolve" means the **registrar's NS records** weren't changed. "Point the apex at an Azure resource" or "the record must update when the IP changes" means an **alias record**. "VMs must register their names automatically" means a private zone link with **auto-registration**, and remember only **one registration zone per VNet**. A VNet without a **virtual network link** can't resolve a private zone, even if it's peered.
</Callout>

<DeepDive title="Custom DNS servers on a VNet">

A VNet can use **custom DNS servers** (VNet → **DNS servers**) instead of Azure-provided DNS, for example domain controllers. Those servers must forward Azure names, including privatelink zones, to 168.63.129.16, or private endpoints stop resolving. VMs pick up a DNS server change after a restart or DHCP renewal.

</DeepDive>
