## The technical explanation

### How it works

1. The admin opens the VM in the portal and selects **Connect → Connect via Bastion** (or runs the native client command).
2. The browser talks to Bastion over **TLS 443**, after Microsoft Entra sign-in and Azure RBAC checks.
3. Bastion opens **RDP (3389)** or **SSH (22)** to the VM's **private IP** inside the VNet.

Bastion is a hardened, managed host: no OS for you to patch, no jump box to secure.

### What you need

| Requirement | Detail |
| --- | --- |
| Subnet | Named exactly **AzureBastionSubnet**, **/26 or larger** (a /26 gives room for host scaling) |
| Public IP | **Standard**, static (not needed for Developer or private-only Premium) |
| Reach | VMs in the same VNet and in **peered** VNets |
| VM NSG | Allow 3389/22 **from the AzureBastionSubnet range** (or VirtualNetwork) |
| Permissions | Reader on the VM, its NIC and the Bastion resource |

If you put an NSG on AzureBastionSubnet itself, it needs specific rules (inbound 443 from Internet and from GatewayManager, outbound to the VNet on 3389/22, to AzureCloud on 443, and so on). Route tables aren't supported on that subnet.

### SKUs

| Feature | Developer | Basic | Standard | Premium |
| --- | --- | --- | --- | --- |
| Portal RDP/SSH | ✅ | ✅ | ✅ | ✅ |
| Dedicated host, peered VNets | No | ✅ | ✅ | ✅ |
| Host scaling (2 to 50 instances) | No | No | ✅ | ✅ |
| Native client (`az network bastion ssh/rdp`) | No | No | ✅ | ✅ |
| IP-based connection, shareable link | No | No | ✅ | ✅ |
| Session recording, private-only deployment | No | No | No | ✅ |

You can **upgrade** a SKU in place but not downgrade. Price feel: Basic is around $0.19 an hour plus outbound data (illustrative), Standard costs more per hour plus per extra instance.

### Portal and CLI

Portal: create **AzureBastionSubnet** in the VNet, then **Bastions → + Create** (tier, instance count, VNet, public IP) and on **Advanced** tick **Native client support** if needed. You can also choose **Enable Azure Bastion** on the **Security** tab when creating a VNet.

```bash
az network vnet subnet create -g rg-net-paas --vnet-name vnet-paas -n AzureBastionSubnet --address-prefixes 10.30.3.0/26
az network public-ip create -g rg-net-paas -n pip-bastion --sku Standard --allocation-method Static
az network bastion create -g rg-net-paas -n bas-paas --vnet-name vnet-paas \
  --public-ip-address pip-bastion --sku Standard --enable-tunneling true --location eastus
az network bastion ssh -g rg-net-paas -n bas-paas --target-resource-id <vm-resource-id> \
  --auth-type AAD
az network bastion update -g rg-net-paas -n bas-paas --scale-units 4
```

PowerShell: `New-AzBastion -ResourceGroupName rg-net-paas -Name bas-paas -PublicIpAddress $pip -VirtualNetwork $vnet -Sku Standard`.

<Callout type="exam">
Exact details win marks here: the subnet is **AzureBastionSubnet**, at least **/26**, and the public IP is **Standard**. "Use the native RDP or SSH client on my workstation" requires **Standard or Premium** with native client support. "Admins must connect to VMs that have no public IP, through the browser, over 443" is **Bastion**. One Bastion in a hub can serve **peered** spokes.
</Callout>

<DeepDive title="Bastion or just-in-time VM access?">

Microsoft Defender for Cloud's just-in-time access opens a management port on the NSG for a short time to one source IP. It reduces exposure but still needs a public IP on the VM. Bastion removes the public exposure entirely. Many teams use Bastion for everyday admin and keep VPN or ExpressRoute for bulk access from the office.

</DeepDive>
