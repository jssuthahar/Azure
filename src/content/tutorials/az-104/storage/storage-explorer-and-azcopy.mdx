## The technical explanation

### Storage browser and Storage Explorer

The portal's **Storage browser** (on every storage account) lets you browse containers, file shares, queues and tables, upload, download, change tiers and generate SAS tokens. Watch the **authentication method**: with *Microsoft Entra user account* you need a data role; with *Access key* you need permission to list keys.

**Azure Storage Explorer** is the desktop version, free for Windows, macOS and Linux. You can open it from the portal with **Open in Explorer**. It connects to:

- a **subscription**, by signing in with Microsoft Entra ID,
- one **storage account or service**, with a connection string, an account name and key, or a **SAS URL** (handy for partners: they see only what the SAS allows),
- the **local emulator** (Azurite).

It manages blobs (including tiers, snapshots, soft-deleted blobs and versions), file shares, queues, tables, access policies and Data Lake ACLs. Big uploads and downloads run through **AzCopy** inside it.

### AzCopy

AzCopy v10 is a single executable, already installed in **Azure Cloud Shell**. It's built for scale: parallel transfers, automatic retries, job plans you can resume, and server-to-server copies.

| Command | Use |
| --- | --- |
| `azcopy login` | Sign in with Microsoft Entra ID (`--identity` for a managed identity) |
| `azcopy make` | Create a container or file share |
| `azcopy copy` (`cp`) | Copy files or blobs; add `--recursive` for folders |
| `azcopy sync` | Copy only new or changed files; `--delete-destination true` removes extras |
| `azcopy list` / `remove` | List or delete blobs |
| `azcopy jobs list` / `jobs resume` | See and restart jobs |

Useful flags: `--include-pattern "*.pdf"`, `--block-blob-tier Cool`, `--dry-run`, `--put-md5`.

**Authorization** is either:

1. **Microsoft Entra ID**: `azcopy login`. Blob Storage then checks **data roles**: **Storage Blob Data Reader** to read, **Storage Blob Data Contributor** or **Owner** to write. Subscription Owner isn't enough. Role assignments can take a few minutes to apply.
2. **SAS token** appended to the URL, which needs no role.

AzCopy doesn't take an account key directly for Blob Storage; use a SAS or Entra ID.

```bash
# Entra ID: sign in, then copy a folder (needs Storage Blob Data Contributor)
azcopy login
azcopy copy "./hr-docs/*" "https://stcontosoprod.blob.core.windows.net/hr-archive" --recursive

# SAS: no role needed, short expiry, HTTPS only
SAS=$(az storage container generate-sas --account-name stcontosoprod -n hr-archive \
  --permissions acwl --expiry 2026-11-25T18:00Z --https-only -o tsv)
azcopy copy "./hr-docs/*" "https://stcontosoprod.blob.core.windows.net/hr-archive?$SAS" --recursive

# Nightly mirror: only changes, and remove what was deleted locally
azcopy sync "./hr-docs" "https://stcontosoprod.blob.core.windows.net/hr-archive?$SAS" --delete-destination true

# Account to account (server to server)
azcopy copy "https://stcontosoprod.blob.core.windows.net/photos?<SAS>" \
  "https://streplicaweu.blob.core.windows.net/photos?<SAS>" --recursive
```

<Callout type="exam">
"Bulk copy, scriptable, resumable" is **AzCopy**. "Graphical tool for blobs, files, queues and tables on a Mac" is **Storage Explorer**. "Only transfer changed files" is **azcopy sync**. "An admin who is Owner gets 403 with azcopy login" means a missing **Storage Blob Data** role. And for tens of terabytes over a slow link, the answer is **Azure Data Box**, not AzCopy.
</Callout>

<DeepDive title="Performance and logs">

AzCopy picks a concurrency level based on CPU count; set `AZCOPY_CONCURRENCY_VALUE` to tune it, and `azcopy benchmark` to test throughput. Every job writes a log and a plan file under `~/.azcopy`, which is how `azcopy jobs resume` knows what's already done. Copying between accounts keeps the data on the Azure network, so it's fast and your bandwidth doesn't matter.

</DeepDive>

## When to use it and when not to

<UseWhen
  use={[
    'Bulk uploads, downloads or account-to-account copies (AzCopy).',
    'Repeating jobs such as nightly sync from on-premises (azcopy sync).',
    'Admins who prefer a GUI for browsing and fixing data (Storage Explorer).',
  ]}
  avoid={[
    'Tens of terabytes over a slow connection (Azure Data Box).',
    'Continuous copying of new blobs between accounts with no scheduler (object replication).',
    'Keeping on-premises file servers in sync with a share as a cache (Azure File Sync).',
  ]}
  alternatives={[
    '<strong>Azure Data Box</strong> for offline bulk transfer.',
    '<strong>Object replication</strong> for automatic blob copies between accounts.',

  ]}
