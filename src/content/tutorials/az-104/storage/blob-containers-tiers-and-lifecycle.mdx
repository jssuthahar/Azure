## Start with a question

<Story question="Why keep last year's tax papers on your desk when they could go in a box in the loft?">

This month's bills sit on your desk because you touch them daily. Last year's go in a filing cabinet. Papers from five years ago go in a box in the loft: cheap to keep, but you need a ladder and an afternoon to get them out.

Blob **access tiers** are the desk (**Hot**), the cabinet (**Cool** and **Cold**) and the loft (**Archive**). A **lifecycle policy** is the house rule that moves papers along on their own.

</Story>

## The technical explanation

### Containers

Portal: **Data storage > Containers > + Container**. Name it (3 to 63 lowercase letters, numbers and hyphens) and pick the **anonymous access level**:

| Level | Anonymous users can |
| --- | --- |
| **Private** | Nothing (the default) |
| **Blob** | Read blobs if they know the URL |
| **Container** | Read blobs and list the container |

Anonymous access is possible only when the account setting **Allow Blob anonymous access** is on. New accounts have it **off**, and with it off every container stays private whatever you choose. Advanced options include a default **encryption scope** and version-level immutability.

### Access tiers

| Tier | Online | Minimum days | Good for |
| --- | --- | --- | --- |
| **Hot** | Yes | None | Data in active use |
| **Cool** | Yes | 30 | Backups, older content read occasionally |
| **Cold** | Yes | 90 | Rarely read, must be instant when read |
| **Archive** | **No** | 180 | Compliance archives, raw data you may never read |

The account has a default tier (Hot, Cool or Cold) that blobs inherit; you can set a tier per blob. Moving out of a tier early adds an **early deletion charge**. Rough feel for 1 TB a month: Hot around $20, Archive around $2 (illustrative). Archive is available on **LRS, GRS and RA-GRS** accounts only.

To read an archived blob you **rehydrate** it: change its tier to Hot, Cool or Cold, or copy it to an online blob. **Standard** priority can take up to **15 hours**; **High** priority is usually under an hour for blobs smaller than 10 GB and costs more.

### Lifecycle management

Portal: **Data management > Lifecycle management > + Add a rule**. A rule has:

- **Scope and filters**: all blobs or a **filter set** of blob **prefixes** (such as `invoices/`) and **blob index tags**; blob type **block blobs** (append blobs support delete only); subtypes **base blobs**, **snapshots**, **versions**.
- **Conditions**: `daysAfterModificationGreaterThan`, `daysAfterCreationGreaterThan` or `daysAfterLastAccessTimeGreaterThan` (which needs **last access time tracking** turned on).
- **Actions**: `tierToCool`, `tierToCold`, `tierToArchive`, `delete`, and `enableAutoTierToHotFromCool`.

A policy holds up to 100 rules. Azure runs it about **once a day**, and a new or changed policy can take up to **24 hours** to start acting. If several actions match one blob, the cheapest one wins (delete, then Archive, then Cold, then Cool).

```json
{ "rules": [ { "enabled": true, "name": "age-out-invoices", "type": "Lifecycle",
  "definition": {
    "filters": { "blobTypes": ["blockBlob"], "prefixMatch": ["invoices/"] },
    "actions": {
      "baseBlob": {
        "tierToCool":    { "daysAfterModificationGreaterThan": 30 },
        "tierToCold":    { "daysAfterModificationGreaterThan": 90 },
        "tierToArchive": { "daysAfterModificationGreaterThan": 180 },
        "delete":        { "daysAfterModificationGreaterThan": 2555 } },
      "version": { "delete": { "daysAfterCreationGreaterThan": 90 } } } } } ] }
```

```bash
az storage container create --account-name stcontosoprod -n invoices          # private
az storage blob set-tier --account-name stcontosoprod -c invoices -n invoice-2025-01.pdf --tier Cold
az storage account management-policy create -g rg-storage-prod --account-name stcontosoprod \
  --policy @lifecycle.json
```

```powershell
$ctx = (Get-AzStorageAccount -ResourceGroupName rg-storage-prod -Name stcontosoprod).Context
New-AzStorageContainer -Name invoices -Permission Off -Context $ctx
$blob = Get-AzStorageBlob -Container invoices -Blob invoice-2025-01.pdf -Context $ctx
$blob.BlobClient.SetAccessTier("Cold")
```

<Callout type="exam">
Read the access pattern. "Accessed daily" is **Hot**. "Rarely accessed but must be available immediately" is **Cool** or **Cold** (Cold if it's kept 90+ days). "Can tolerate hours of latency, lowest cost" is **Archive**. "Read an archived blob" means **rehydrate** first. "Move blobs automatically" is **lifecycle management**, and "based on last read" means turning on **last access time tracking**. A container that can't be made public points to the account's **anonymous access** setting.
</Callout>

<DeepDive title="Smaller details that cost money">

Changing tiers costs write operations, and reading Cool, Cold and Archive data costs more per GB. Lifecycle rules that move millions of tiny blobs can cost more than they save, so filter by prefix and consider packing small files. Versions and snapshots are billed too; give them their own delete actions in the same policy.

</DeepDive>
