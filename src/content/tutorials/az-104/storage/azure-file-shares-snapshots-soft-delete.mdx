## Start with a question

<Story question="What if your office shared drive had a time machine?">

Every office has had the moment: someone drags the wrong folder to the bin on the shared drive, and the quarterly reports are gone. On a good file server, IT opens last night's copy and puts the folder back.

**Azure Files** gives you shared drives in the cloud, and **share snapshots** are that time machine. **Share soft delete** covers the bigger accident, when someone deletes the whole share.

</Story>

## The technical explanation

### Create a share

Portal: storage account, **Data storage > File shares > + File share**. You set a name (3 to 63 lowercase letters, numbers and single hyphens), the access tier and the maximum capacity, and on the **Backup** tab you can turn on Azure Backup straight away.

| Choice | Options |
| --- | --- |
| Account type | **Standard general-purpose v2** (HDD) or **Premium FileStorage** (SSD) |
| Tier (standard) | **Transaction optimized** (busy, many operations), **Hot** (general team shares), **Cool** (archive-like, cheaper storage, dearer access) |
| Protocol | **SMB** 3.x (Windows, Linux, macOS, TCP port 445) or **NFS** 4.1 (Linux, premium only, virtual network access) |
| Size | Quota up to **100 TiB** per share |

Standard shares cost per GB stored plus transactions; for example, Transaction optimized is around $0.06 per GB-month (illustrative). Premium shares are billed on provisioned size and give predictable IOPS and throughput.

### Share snapshots

A snapshot captures the **entire share** at a point in time. It's **read-only** and **incremental**: only changed data since the last snapshot is stored and billed. Up to **200** snapshots per share.

- Take one by hand before a risky change: share **> Operations > Snapshots > + Add snapshot**.
- Let **Azure Backup** take them on a schedule and manage retention.
- Restore a single file or folder from the portal, or on Windows through **Previous Versions** on the mounted drive.
- A share with snapshots can't be deleted unless you delete the snapshots too (`--include snapshots`).

### Share soft delete

Soft delete for file shares is on **Data management > Data protection**, with retention from **1 to 365 days**. New accounts have it on with **7 days**. When a share is deleted, it waits in a soft-deleted state with its snapshots; **Show deleted shares > Undelete** brings it back. It's share-level only: it doesn't recover a single deleted file inside a live share.

### CLI and PowerShell

```bash
az storage share-rm create -g rg-storage-prod --storage-account stcontosoprod \
  -n finance --quota 1024 --access-tier TransactionOptimized --enabled-protocols SMB
az storage share-rm snapshot -g rg-storage-prod --storage-account stcontosoprod -n finance

az storage account file-service-properties update -g rg-storage-prod -n stcontosoprod \
  --enable-delete-retention true --delete-retention-days 14

# Recover a deleted share
az storage share-rm list -g rg-storage-prod --storage-account stcontosoprod --include-deleted -o table
az storage share-rm restore -g rg-storage-prod --storage-account stcontosoprod \
  -n finance --deleted-version <version>
```

```powershell
New-AzRmStorageShare -ResourceGroupName rg-storage-prod -StorageAccountName stcontosoprod `
  -Name finance -QuotaGiB 1024 -AccessTier TransactionOptimized
Update-AzStorageFileServiceProperty -ResourceGroupName rg-storage-prod -StorageAccountName stcontosoprod `
  -EnableShareDeleteRetentionPolicy $true -ShareRetentionDays 14
```

<Callout type="exam">
Match the accident to the tool. "A file in the share was deleted or overwritten" is a **share snapshot** or **Azure Backup** restore. "The whole share was deleted" is **share soft delete**. "The storage account must not be deleted" is a **resource lock**. "Linux needs NFS" is a **premium FileStorage** account. Snapshot limits (**200**) and soft delete retention (**1 to 365 days**) show up in answer choices.
</Callout>

<DeepDive title="Azure File Sync">

If branch offices need fast local access, **Azure File Sync** installs an agent on a Windows Server that caches the Azure file share. Cloud tiering keeps hot files local and leaves cold ones as pointers in Azure. The cloud share is still where snapshots and soft delete protect the data.

</DeepDive>
