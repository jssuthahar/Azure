## Start with a question

<Story question="How does a building inspector keep every new house safe without visiting every site every day?">

A council publishes building rules: no houses on the flood plain, every house needs a smoke alarm. Some rules stop the build before it starts (planning permission refused). Some just get noted on an inspection report. And some the council fixes for you, like fitting the missing smoke alarm and sending the bill.

**Azure Policy** is that rulebook. **Deny** refuses the build, **Audit** writes it on the report, and **Modify** fits the smoke alarm for you.

</Story>

## Explain it like I'm 10

<Eli10>

Your class has rules on the wall.

"No phones in class": a teacher takes it at the door. That's **Deny**.

"Homework should have your name": the teacher marks it but still accepts it. That's **Audit**.

"Every book needs a cover": the teacher puts a cover on for you. That's **Modify**. And for the books already on the shelf, someone does a cover-fixing day. That's **remediation**.

</Eli10>

## The technical explanation

### The pieces

- **Definition**: the rule (`if` a condition, `then` an effect). Hundreds are **built-in**; you can write **custom** ones in JSON.
- **Initiative** (policy set): several definitions grouped, such as a security baseline.
- **Assignment**: a definition or initiative applied at a **scope** (management group, subscription, resource group) with **parameters**, **exclusions**, a **non-compliance message** and an **enforcement mode**.
- **Exemption**: excludes one resource or scope, with a reason (waiver or mitigated) and an optional expiry.

Policies assigned higher up apply to everything below. The person deploying doesn't matter: an Owner is stopped by Deny just like anyone else.

### Effects

| Effect | When | Result | Needs identity? |
| --- | --- | --- | --- |
| **Deny** | Create or update | Request refused with `RequestDisallowedByPolicy` | No |
| **Audit** | Create, update and evaluation | Allowed, marked **Non-compliant** | No |
| **Append** | Create or update | Adds fields, such as IP rules | No |
| **Modify** | Create or update, and remediation | Adds, replaces or removes tags and some properties | **Yes** |
| **AuditIfNotExists** | After deployment | Flags if a related resource (like an extension) is missing | No |
| **DeployIfNotExists** | After deployment, and remediation | Deploys the missing related resource, such as diagnostic settings | **Yes** |
| **Disabled** | Never | Turns the rule off | No |

### Assign a policy

Portal: **Policy → Definitions** → pick one → **Assign policy**. Tabs: **Basics** (scope, exclusions, assignment name, **Policy enforcement**), **Parameters**, **Remediation** (create a remediation task, managed identity type and location), **Non-compliance messages**, **Review + create**.

```bash
# Deny anything outside two regions, at a management group
az policy assignment create -n eu-only \
  --policy e56962a6-4747-49cd-b67b-bf8b01975c4c \
  --scope /providers/Microsoft.Management/managementGroups/mg-contoso \
  --params '{ "listOfAllowedLocations": { "value": ["westeurope","northeurope"] } }'

# Modify: copy the costcenter tag from the resource group, with a managed identity
az policy assignment create -n inherit-costcenter \
  --policy ea3f2387-9b95-492a-a190-fcdc54f7b070 -g rg-finance \
  --params '{ "tagName": { "value": "costcenter" } }' \
  --mi-system-assigned --location westeurope

# Fix resources that already exist
az policy remediation create -n fix-costcenter --policy-assignment inherit-costcenter -g rg-finance

az policy state summarize -g rg-finance        # compliance numbers
az policy state trigger-scan -g rg-finance     # re-evaluate now
```

When you assign through the CLI, give the managed identity a role (for tags, **Tag Contributor**) at the scope. The portal does this for you.

### Compliance

New assignments are evaluated within about **30 minutes**; existing resources are re-checked about every **24 hours** or when you trigger a scan. **Policy → Compliance** shows each assignment's percentage and the non-compliant resources with the reason.

<Callout type="exam">
"Prevent" or "ensure resources can only be created" = **Deny**. "Identify" or "report" = **Audit**. "Automatically add a tag" = **Modify** (or Append for some properties). "Automatically deploy diagnostic settings or an agent" = **DeployIfNotExists**. "Apply to existing resources" = **remediation task**, which needs a **managed identity**. "Group several policies" = **initiative**. Policy controls **what**; RBAC controls **who**.
</Callout>

<DeepDive title="Policy and resource groups">

Most built-in resource policies use mode **Indexed**, which evaluates resources that support tags and location, not resource groups themselves. That's why there are separate definitions like **Require a tag on resource groups**. A resource group's tags are also not inherited by its resources; **Inherit a tag from the resource group** (Modify) is the built-in fix. Allowed locations doesn't apply to resource groups either; use **Allowed locations for resource groups** if the group's metadata location matters.

</DeepDive>
